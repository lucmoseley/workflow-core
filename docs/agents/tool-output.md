# Reading a slice, not a file — the output convention

Tool output is **74.2% of a long session's context here** ([docs/research/tool-output-profile.md](https://github.com/lucmoseley/workflow-core-tracker/blob/0a69e0d4be03/docs/research/tool-output-profile.md)). mantahostels#1553 (cap tool output rather than compact conversation) declined every capping setting the CLI offers and ruled that the only lever left is reducing the output at source.

## Why no setting does this instead

- `BASH_MAX_OUTPUT_LENGTH` defaults to 30,000 characters, and **results do reach it**. Past it a result has two fates and nothing found predicts which: saved to a file behind a 2 KB preview (~460 in the 14 days to 9 October 2026), or cut at ~30,000 characters with no notice (~55, on CLI 2.1.282–2.1.294) (#1029). Lowering it to 10,000 would reclaim 8.9% of all tool-result bytes and truncate `git diff`, against the standing rule to show the diff of each change before committing it.
- Capping the Read tool would reclaim 13.1%, but a capped Read returns a `PARTIAL view` notice rather than an error, so a session reading `docs/doc-map.md` could act on a fragment without knowing it did.

Reopening either needs new evidence, not a re-reading of the same figures.

- **Read the part of a file you need, not the whole file, and send a large command's output to a file and read the slice that matters.** Four shapes cost most here, each with what to do instead: an **unbounded `cat`** whose named files total ~20,000 characters or more — `grep -n '<pattern>' <path>` to find the lines, then `sed -n '<start>,<end>p' <path>`; a **`sed -n` range spanning 200 lines or more, or running open-ended to `$`** — name a last line, or narrow with a grep first; a **bare glob whose match count you do not know** — `ls <glob> | wc -l` first, or narrow the pattern; and a **`Read` call with no `limit` returning 10,000 or more characters** — pass `offset` and `limit`, which is one call, after a `grep -n` to find the line to start at. Where you genuinely need the whole thing, redirect it (`… > .claude/tmp/out.txt`, never `$CLAUDE_JOB_DIR/tmp` — `scripts/guard-job-dir-scratch.sh` refuses that, mantahostels#2406, #1139) and read the slice back. **Advisory** (mantahostels#1562, mantahostels#2595; #185): `scripts/guard-wide-read.sh`, wired as four `PreToolUse` registrations — a `Read` one, and three `Bash` ones narrowed to `cat`, `sed` and `awk` — that **warns and never denies**, naming the shape it matched, the size it measured and the cheaper form. Warn-only is the decision, not a first step toward denying — a session often has a real reason to read widely, and mantahostels#103's line is to warn where a guard is inferring. The `Read` warning latches per (agent, file), once a session (#1034). Known residuals: only `cat`, `sed` and `awk` are judged on the Bash side, so `grep` goes unwarned whatever it reads — and `grep` and `head` bound lines, not bytes, so a match in a single-line file returns the whole line (#1026); a pipe or a redirect anywhere in the command silences it, quoted ones included; a path that does not resolve against the hook's cwd is never measured; and `sed` is judged on line span, never on the bytes those lines hold. **The Read limb's own two: a call carrying any `limit` is never judged**, **and it measures the first 2,000 lines from `offset`**, which is where `Read` stops, so bytes past that line are neither counted nor charged for. A third: the figure is the file's own bytes, where `Read` returns them with a `cat -n` line prefix, so the effective threshold sits above 10,000 and rises with the line count (mantahostels#2595).
- **A repeated `Bash` or `Read` call is refused outright once its last two runs have given the same answer** — byte-identical output, or for a `Read` the file unchanged since (#1090). Vary the command, or read the answer already in hand — the first refusal on a signature clears its count, so a real re-check costs one turn and moves on, but a **second** refusal on the same signature leaves the chain armed. **Enforced** (mantahostels#2570, mantahostels#2615): `scripts/guard-echo-call.sh`, the sibling `PreToolUse` `Bash|Read` hook. It never judges the prescribed timed watch — a `sleep <n>; …` beat, or a bare no-op — nor `ListAgents`, all three left to `guard-agent-poll.sh`'s cadence rule; and it never catches a response that changes on every call (a growing log, a timestamp), by design.
- **`grep` in the Bash tool is Claude Code's bundled ugrep, and a bounded repeat in its pattern can make it refuse the pattern or stall** — `.{0,20}x.{0,20}` over a long line prints `exceeds complexity limits` and exits 2, and under `2>/dev/null` that reads as "no match" (#1021). Exit 2 is no verdict; re-spell it with `-P` in place of `-E`, every other flag kept — the same output for a pattern of literals, `.`, bracket classes and bounded repeats, though an alternation or a basic-mode `( ) | + ?` can match differently under `-P` — or use `rg` or python. **Advisory** (#1021): `scripts/guard-ugrep-pattern.sh` warns once per (agent, session) on a bare `grep` whose pattern holds `{N,M}`, `{,M}` or `{N,}` (`\{N,M\}` without `-E`) and no `-P` or `-F`. `egrep`, `xargs grep` and a path spelling reach GNU grep, and are not judged.
- **An image read many reads ago may no longer reach you.** Claude Code sends at most about 17.5 million base64 characters of images per request. Past that it swaps the oldest for `[media removed: request limit]`. The Read result still says image, and nothing in the result marks the swap (#1784). Never judge an image that shows that text, and never describe one from memory: stop and report which images you could not see. A brief that has an agent read more images than that should split them across agents. **Advisory** (#1784): `scripts/guard-image-budget.sh`, a `PostToolUse` Read hook, counts each agent's image and PDF Reads. It warns once at 13,000,000 characters, then names each file the cap pushes out. Images arriving any other way are not counted, so the warning comes late there. After a compaction the count is too high, so it comes early.

## Where the thresholds come from

**The byte threshold is 20,000 characters, and it is a price, not a percentile** — the break-even against the remedy this convention names, grep-then-sed, two extra tool calls each a turn at full context (mantahostels#2571, which carries the derivation). **Treat it as a rough centre, not a bound in either direction**; re-tune from mantahostels#2571, not from this paragraph.

**The `Read` limb's threshold is 10,000 — half the figure above, by construction rather than by a second measurement** (mantahostels#2595, which carries the derivation and the firing rates). Every term in the model is shared between the two limbs but the remedy's call count: grep-then-sed is two calls, a `Read` carrying `offset` and `limit` one. Both limbs price a turn at its marginal cost; pricing it at its mean instead would move both together, to 13,100 (Bash) and 6,600 (`Read`), and one limb on each price is not defensible. It is overridable per run through `WFC_WIDE_READ_TOOL_BYTES`, and it is the figure to move first if the Read limb warns too often.

The 200-line span and the 5-file match count are unmeasured judgement, and are the first to move if this warns too often. Each is stated beside its constant in `scripts/guard-wide-read.sh`, and each is overridable per run through `WFC_WIDE_READ_BYTES`, `WFC_WIDE_READ_LINES` and `WFC_WIDE_READ_MATCHES`. The 30,000-character cut-off sentence is not a judgement but the CLI's default cap, overridable through `WFC_WIDE_READ_CUT_BYTES`.

## Reading the read-call count

**Exclude `cat` of a backgrounded job's own output file before counting reads in a transcript** (mantahostels#2571). **The swing to `Read` on 30 August 2026 was a change in which model ran, not in read behaviour** (mantahostels#2595, which holds the per-model figures and the hypotheses ruled out).

## What it does not catch

`grep`, `rg`, `head` and `tail` bound their output in lines — by pattern or by line count — so a glob handed to one is the cheaper form this convention recommends, and warning on it would be warning on the fix. Lines are not bytes: a single very long line passes through whole (#1026).
