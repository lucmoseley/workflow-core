AN UNASKED RE-RUN IS REFUSED ONCE A SESSION (#815, ruled at #790 Q3): a bare
`npm run test`, `npm test` or `npm run test:changed`, while green runs from any
sessions already cover what it would test (ADR-0009). It reads HEAD plus this
session's own uncommitted files, and cover is judged on that same tree, so it
can only repeat the verdict those runs gave.

Before a push, `{command:push_check}` says what is owed; run the suite for that.
Re-typing the refused command runs it — a reason you can name is reason enough.

Never refused: a run naming files or a filter, `--full=<cause>`, a run in
another checkout, a session with no id, or anything after the first refusal.
