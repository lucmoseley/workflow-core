**`takes:human` is picked from the next action, never the subject.** Name the concrete act performed outside Claude Code, and it is one of the founder's own (#1077 Q1 (A), amended by Q2 (A)): pay, buy or subscribe; sign or accept terms; delete; install an app; accept an invite; grant access; OAuth Authorize; a CAPTCHA guarding an act he is taking; card entry; a one-time code; phone verification; signing a site in for the first time; an act Claude Code's automatic permission check refused (never the same act by another path), per `rule:founder-handover`; a phone call, an in-person act, or an act in a desktop or phone app; sending anything a person outside reads. If you cannot name one the label is wrong, however legal- or compliance-flavoured the subject reads: an agent reading repo files and writing a ruling takes `/wayfinder`, and one applying a prescribed edit takes `/implement`. **A founder decision or confirmation takes `takes:wayfinder`** — the founder makes it inside Claude Code, in a `/wayfinder` grilling session, so nothing happens outside it (mantahostels#3439). **There is no "no command opens this" shape**: a scripted tracker whose queue has emptied closes, or moves to the command that owns what is left, and never sits under `takes:human` (mantahostels#3352). **An act whose product is a file in this repository is never an outside act**, whatever tool a document names as the owner's — an SVG is text, and an agent writes it; the founder's taste on an agent-drawn asset is a `/wayfinder` review (mantahostels#3439, mantahostels#3503). **A `manual-finding` is never that shape either** — `manual-sync` in full mode is the command that opens it, so a stale operating-manual stamp takes `takes:implement`, and `check-issue-labels.js` flags the contrary as CONTRADICTED (mantahostels#2810, mantahostels#3146). **A permanently-open issue is not that shape either** — every issue must be closeable (mantahostels#678).

**Being barred is not being impossible, and that is the mistake this label actually attracts** (mantahostels#2775, the ticket that ruled it). A skill's own scope barring *this* pass from an edit, a repo rule barring an agent from an act, a command wanting a password — none of them puts the work outside Claude Code, and the last least of all: the founder types `! <cmd>` and it runs *in* the session. Each of those goes back to `/implement` or to `/wayfinder`. **A `403` is the fourth shape, and it names one permission, never the act** (mantahostels#3358). Before calling an act outside, enumerate what the token *does* hold and look for a route through it.

**So a `takes:human` body NAMES ITS OUTSIDE ACT, on its own line: `**Outside Claude Code:** <the act, in plain words>`.** **Enforced** (mantahostels#2775): the `guard-issue-create-label` core denies a `gh issue create` — flag form or REST — that applies `takes:human` and carries no such line, **and a `gh issue edit <n> --add-label takes:human` on an issue whose body has none** (mantahostels#3555), fetching the body through `gh` and failing open, recorded, where it cannot — but refusing one that rewrites the body in the same call with a `--body` it cannot read or any `--body-file` (#669), since relabelling alone always has its body fetched. **The same guard denies either where the Outside line names a repo file as the act's product** — a backticked path under `docs/`, `app/`, `scripts/`, `components/`, `lib/` or `public/`, a `.svg`/`.png`/`.md`/`.js`/`.ts` filename, or Inkscape, Figma, Photoshop or a spreadsheet — the lexical test `check-issue-labels.js` repeats as REPO-FILE-ACT (mantahostels#3555). The line check cannot tell whether the act named is real. It reads a heredoc piped into `--body-file -` — the `cat <<'BODY' | gh issue create …` form every create uses — where it is the command's only `gh issue create` (mantahostels#3439); a body it cannot read (a `$VAR`, a `$(…)`, a file not on disk, an unquoted heredoc whose body would expand, `--body-file -` fed any other way) is refused (#668). **Two routes escape it entirely**: the GraphQL form, where labels are opaque node ids; and a create or relabel by a script or the web UI, which no `PreToolUse` hook sees. **Both are caught after the fact:** `scripts/check-issue-labels.js` reports NO-OUTSIDE-ACT on any open `takes:human` body whose line is absent or names nothing, and REPO-FILE-ACT on one whose line names a repo file. **A third limb refuses an Outside line that names a PROHIBITION rather than an act** (#140) — `no agent may`, `an agent is not permitted to`, `agents are barred`, `no session may`. **Every alternative names an agent or a session as the barred subject**: a prohibition about the *world* is usually part of a real errand — *"once submitted it may not be edited"*, *"phone the bank and ask why the account is barred"* — and a wider draft denied all of those. **Enforced**: the same `guard-issue-create-label` core denies it on create and relabel, and `check-issue-labels.js` reports BARRED-NOT-IMPOSSIBLE after the fact. Before relabelling, **test the bar rather than restating it** — `test -w <path>` for a file you believe unwritable, and read the rule itself for one you believe forbids it; a real bar is `takes:wayfinder`, an unreal one `takes:implement`. **Unenforced** (mantahostels#3358; mantahostels#804 for why a stale `takes:human` goes unreviewed): the same `check-issue-labels.js` WARNs HUMAN-UNREVIEWED on any open `takes:human` whose `updated_at` is 14 or more days old, telling the reader of `node scripts/status-report.js` to re-test the act in-session and comment with what was tried. Any touch resets that clock — a relabel, a sweep's body edit — so the WARN asks for a look and never proves one happened. A WARN and never a FAIL, because a real errand — a payment, a form, a reply from an OTA desk — legitimately outlives 14 days.

**Anything a person outside reads, the founder sends** (#1077 Q2 (A)) — an email, a LinkedIn message or connection note, a contact or support-desk form, a partner or affiliate application, a government registration, a public profile edit; a push to `main` publishing the website is not one. An agent drafts and iterates it with him; once he approves the final draft it may open a pre-filled Gmail compose window from the address the draft names, and it never presses Send, never pre-fills a website form, and no Chrome child sends (#1089 Q3 (A); the procedure is the `browser-ladder` skill's). **A website job no act on the list covers reaches the founder only after three methods failed** (#1077 Q3 (A)): at least three genuinely different free methods, each actually run, under a `Tried:` line, one per line with what it showed. **Enforced** (#1095): a fourth Outside-line limb passes a `takes:human` body only where its Outside line holds a word from the founder-act vocabulary, on the Outside line alone, or where a `Tried:` line, bold or plain, is followed directly by three or more list items, a sub-item counting as its method's detail rather than a method. `scripts/file-issue.js` refuses it and `check-issue-labels.js` reports NOT-A-FOUNDER-ACT after the fact; the `guard-issue-create-label` core denies it on create and relabel (#1097). **Accepted limit** (#1077 Q5 (A)): it sees three methods listed, never whether they were different or really run, and it passes a list word used in a non-act sense (*"look up which payment methods the site lists"*).

**A founder-facing item is filed the moment it exists, and a `takes:human` body follows one template ending `**Close when:** <what finishes it>`** — `rule:founder-deliverable`. **Enforced** (#983): the same guard and `file-issue.js` refuse a `takes:human` body without that line, and `check-issue-labels.js` reports NO-CLOSE-WHEN after the fact.

**A multi-step outside act gets an in-chat walk, not a re-explanation.** Where the Outside line names a walk a human must click through — a first sign-in to a third-party dashboard, credentials to capture, a one-off cutover — the walk takes the founder through the issue's body step by step, as a founder hand-over (`rule:founder-handover`) with any credential handed over as its secret line, and is never a second copy. **Unenforced** (#479): nothing detects a multi-step act walked without the hand-over, and an errand that is a *wait* on someone else earns no walk at all.

`takes:` is **disposition** — what to do with the issue next. `kind:` is **provenance** — what the issue is and where it came from: a `kind:spec` takes `/to-tickets` before its tickets exist and nothing afterwards, and a `kind:ticket` can take `/wayfinder` when it turns out to hide a decision.

**`takes:children` marks a container** — an open issue whose every remaining action sits on its open sub-issues.

**A `wayfinder:map` is never a container** while any open child carries a `wayfinder:<type>`: `/wayfinder <n>` works the map itself, so a map takes `takes:wayfinder`. **The exception is the exhausted many-destination map** — no open child carrying a `wayfinder:<type>`, each a spec or a `kind:brief` — which takes `takes:children` (#578).

A spec whose tickets are all *closed* is not a container either — nothing open carries its residual, so someone must decide whether it is discharged. That is `takes:triage`.
