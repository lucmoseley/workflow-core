A FOUNDER-FACING ITEM lives in an open issue, never only in chat. Three kinds count:

  - a deliverable the founder must still act on — a draft to send, a file to upload;
  - an act only the founder can do, written only in chat or inside a comment — a click-through, or a judgement no agent can make;
  - a decision the founder has not answered.

This holds in background and interactive sessions alike. Chat, a `needs input:` or `waiting:` ending, the status line, the job list and a closed issue's comment never count.

FILE IT THE MOMENT the session produces the deliverable or names the act, not at session end. A paste the founder runs while this session waits — a `!` line, or a line in his own terminal whose output he sends back — or a secret he enters, is finished in the session and needs no issue: the `waits on you:` line cites the ticket in hand.

A CHECK BY EYE OR EAR IS YOURS FIRST (#4114). Before filing or handing one over, get the output yourself: text from the real renderer at the real size (`node scripts/refill-panel.js --print` for the refill panel), a screenshot through the browser route, or a reading through any API the effect touches — this machine's Windows side answers `powershell.exe` from WSL2, so a desktop app's sound or flash is often readable. A different experiment reaching the same answer counts. Where any of these reads it, check it and close on that evidence, even where the close clause names the founder, and say so on the ticket. Only what no route reaches goes to him: how something feels or looks to a person, or an effect no API reads, such as a push on his phone. The ticket says which of the two it is.

A CLAIM THAT A SESSION CANNOT OBSERVE SOMETHING — in a body, a hand-over or a `**waived:**` line — names the methods it tried, each with what it showed. An untried "cannot" is no reason.

THE LABEL:

  - a deliverable or an act outside Claude Code   → takes:human, with the body below
  - a judgement by eye of agent-made work         → takes:wayfinder, with a `## Question` body
  - an unanswered decision                        → takes:wayfinder, with a `## Question` body

A `takes:human` BODY, in this order (modelled on mmm-infra#32):

  1. **Outside Claude Code:** <the act>
  2. Why the work exists and the facts it rests on, each dated.
  3. The deliverable verbatim in a fenced block — or each step with its surface, its literal text and what the founder should see.
  4. {rule:close-when-line}

THE ISSUE BODY IS THE HAND-OVER'S SOURCE for later sessions, never what the founder is sent to read: the final message asking for the act carries every step in full (`rule:founder-handover`).

A DECISION'S QUESTION ROUND is posted on the issue that carries it before the session ends on `needs input:`.
