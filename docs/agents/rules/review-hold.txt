A COMMIT ON A DECLARED SENSITIVE PATH IS HELD UNTIL ITS PRE-COMMIT REVIEW IS RECORDED. Load the code-review skill on exactly what the commit will carry, staging nothing but `git add -N <new file>`: pin `t=$(node scripts/commit-paths.js --tree [--patch <file>] -- <unpatched paths>)`, then fixed point `HEAD`, diff `git diff HEAD $t -- <commit paths>`. Once the findings are disposed and their fixes are in the working tree, record the review — no closing step does — with:
  node scripts/write-review-marker.js --base <the fixed point this review diffed> --findings <the distinct findings across every run> --tier escalated|mission-critical --areas <every area the refusal or `Tier owed:` names, and any globless area you judged touched, comma-separated> --paths <every path the review's diff named, comma-separated>
adding `--patch <file>` where the commit takes one. It writes `.claude/tmp/markers/.codereview-pass-$CLAUDE_CODE_SESSION_ID` — base=, findings=, tier=, areas=, paths= and the tree= `node scripts/commit-paths.js --tree` prints for those paths — and refuses, writing nothing, where the review left no artefact. base= names what the review diffed, rather than claiming the session's start point, because the Stop nag and the push warning then check what lies between that start point and base= and keep asking for a review of any code there, where a start-point claim would silence them over code no review saw. paths= is checked rather than trusted for the same reason: the hold refuses it unless it names every path the commit changes, and the nag and the warning keep asking for a review of any code this session wrote outside it, committed or not. To cover code this session committed earlier too, review from the start point in `.claude/tmp/markers/.concision-base-$CLAUDE_CODE_SESSION_ID` — fixed point that sha, diff `git diff <that sha> $t -- <commit paths>`, `$t` pinned as above, `<commit paths>` being every path this session wrote and `<unpatched paths>` those less any `--patch` file — and pass that sha as --base and `<commit paths>` as --paths. A worktree commit is not held, but run the same command there, as the nag and the warning read its paths= too. Then commit at once. Any later edit changes the tree and re-arms the hold: review the edit, then re-run the command. A neighbour's commit moves HEAD and so changes a pathspec commit's tree too; after that alone, re-run it with no new review.
