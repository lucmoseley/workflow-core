WORK LANDS THROUGH YOUR SESSION'S QUEUE REF — NEVER A PUSH TO `main`, NO
OTHER BRANCH ON THE REMOTE, AND NEVER A PULL REQUEST.

Each session pushes its own queue ref, `queue/<worktree name>`, and the queue
lander alone moves `main`. A pull request is refused through `gh pr create` and
`gh api` alike.

Land from your session's worktree:

  node scripts/session-checkout.js land   # merges origin/main, pushes your queue ref; refused? do as it says, land again

After the push, `node scripts/landing-status.js` reads each commit as landed,
or queued on your queue ref.

WHAT PASSES: a push creating or fast-forwarding your own queue ref, a tag
(`git push origin v1.2.3`, `--tags`), a deletion of any branch but `main`, a
queue ref and the lander's own, and a branch under `spike/` — a
data branch kept off `main` on purpose and never merged. A bare tag name passes
only where the tag already exists locally when the push is judged: push it as
`refs/tags/<name>`, or create the tag in a separate call first.

A SECOND LIMB: `.husky/pre-push` refuses a push to `main` of any sha the
lander's green ledger does not hold, from any route. `git push --no-verify`
defeats it.

WHAT THIS DOES NOT CATCH: a push or pull request made outside Claude Code or in
the GitHub web UI, one reached through a script, and a push steered by a
`remote.<name>.push` refspec in git config, save a push to `main`, which the
pre-push limb still refuses. Its silence there is not leave.
