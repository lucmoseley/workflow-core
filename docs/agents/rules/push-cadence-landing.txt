PUSH TO `landing` WHEN `{command:push_check}` FINDS EVERY COMMIT IT SENDS
COVERED — by your green or a neighbour's — and run the suite only for what it
names. The push is your own act; never ask the founder for it. Push before the
turn's last message, or say in that message why the push is held.

  {command:push_check}
  {command:typecheck}
  {command:check}
  <the edited file's own checker>
  git push origin main:landing   # HEAD:landing from a worktree

A push costs nothing; holding one back buys nothing. `.husky/post-commit`'s
unpushed count is a reminder, not a prompt to push.

The push sends EVERY commit on `main`, a parallel session's too.

A REJECTED PUSH means `landing` moved: `git pull --ff-only`, then retry.

A push to `landing` has not landed: the lander moves `main` to it only once the
full suite passes there, 25–60 min later, and reverts a commit that breaks it.
Never write `result:` on the strength of the push.
