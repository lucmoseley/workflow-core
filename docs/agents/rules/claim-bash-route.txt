NOTHING REFUSES A BASH-ROUTE WRITE TO A CLAIMED FILE, ON EITHER TIER. Read the
claims yourself before one:

  node scripts/session-arbiter.js list

The claim guard is a `PreToolUse` hook on `Write`, `Edit` and `NotebookEdit`
alone. A `cp`, `mv`, `tee`, a `>` redirect, `git restore`, `git checkout --
<path>`, `sed -i`, a heredoc and a script writing for you all reach
the file unrefused — and the list is open.

A Bash-parsing DENY was declined on price (mantahostels#287); guard-dispatch.js's guard-claimed-bash-write
core warns instead, on a TIER-1 target and nine of those spellings (mantahostels#1818), plus the
tier-1 paths an inline `python`/`node` QUOTES (mantahostels#2854). The content record
(mantahostels#295) speaks AFTER the write: a scan following every Bash call
baselines whatever moved, so a clobber is reported at your next write to that
file and the overwritten version stays recoverable.

ONE BLIND SPOT BEYOND THAT: a destructive command YOU ran yourself is trusted
and never reported at all (mantahostels#329). Its recovery is still kept —
`node scripts/session-arbiter.js versions <path>`.
