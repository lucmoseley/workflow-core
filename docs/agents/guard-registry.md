# Guard registry

The enforcement record of every rule a guard prints at the moment it bites, kept out of the always-loaded pool (#1942). This file holds its one marker, its guard path and its citations, where `scripts/check-guard-registry.js` reads them.

**A new guard's rule sentence goes here by default**, not into `CLAUDE.md` (`docs/agents/guard-authoring.md` surface 8). A rule enters an always-loaded file only with an entry in `docs/pool-admission-ledger.json`, and `scripts/check-context-budget.js` refuses a commit that adds one without it.

Each rule is a top-level bullet inside the region below, tagged as surface 8 defines. A known-gap clause that names no act for the session goes on the rule's entry here, never into the pool.

### Conventions

- **The shared working tree stays on `main`, and a throwaway worktree needs `-b <name>` or `--detach`.** **Enforced** (mantahostels#110, mantahostels#1648): `scripts/guard-dispatch.js` (its `guard-branch` core) denies the breach and hands you the whole rule — recipe, escape and second limb — on the command itself (`rule:branch-shared-tree`). **A worktree has no `node_modules`**, so call binaries by path (`node_modules/.bin/…` in the canonical checkout) or scoped (`npx @biomejs/biome`, unpinned). Never a bare `npx <tool>`: `npx biome` is an unrelated package, silent and exit 0, and `--no-install` is no defence.
- **Hand edits and agent work in a driven session commit directly to `main` — no remote branch but `spike/*`, and never a PR.** **Enforced** (#764): `scripts/guard-dispatch.js` (its `guard-branch-publish` core, `rule:branch-publish`).
- **With the `landing` module on, work lands through `landing` — never a push to `main`, which only the lander moves — and `landing` is never force-pushed or deleted.** **Enforced** (#2409, spec #2261): `scripts/guard-dispatch.js` (its `guard-branch-publish` core) denies the push to `main` (`rule:branch-publish-landing`) and the forced or deleting push to `landing` (`rule:landing-rewind`); `.husky/pre-push` refuses a push to `main` of a sha the lander's green ledger holds neither itself nor by its tree, which `--no-verify` defeats. The push, CI-status, green-suite, pull and shared-tree rules are swapped for their `-landing` twins by the guards that print them.
- **Never merge a Dependabot PR — take its fix locally: `docs/agents/dependabot.md`.** **Enforced** (mantahostels#3351, #2020): `scripts/guard-dispatch.js` (its `guard-branch-publish` core) refuses a `gh pr merge` of one, handing over the whole recipe (`rule:dependabot-merge`). A merge through `gh api`, the web UI or a script is never seen, and one whose PR the guard cannot look up is allowed and recorded.
- **Commit by pathspec, never `git add` first — `node scripts/commit-paths.js -m "…" -- <paths>`.** **Enforced** (mantahostels#117, mantahostels#118, mantahostels#975, mantahostels#1539): `scripts/guard-dispatch.js` (its `guard-commit-form` core) denies the sweeping forms, warns on the rest, and hands you the whole rule on your first `git add` or `git commit` of the session (`rule:commit-pathspec`). Its warns are advisory: read the index yourself.
- **`--no-verify` does not skip the gates on `git commit` or `git merge`, and `git revert` is gated too — the whole `.husky/pre-commit` stack runs anyway, and a finding refuses the operation**, stranding it behind the abort command the refusal names. A cherry-pick replay, a rebase replay, a `rebase --continue` resolution, `git am` and `git rebase --apply` run the **secrets scan alone** — the rest of the stack is unrun there, so a routine rebase stays possible. **Any commit made while one of those is in progress takes that narrow path**, a `--no-verify` one included; a `cherry-pick --continue` is the exception, running the whole stack because git fires `pre-commit` on it. **Enforced** (mantahostels#1705, mantahostels#1706, mantahostels#1707): `.husky/prepare-commit-msg`, `.husky/pre-applypatch` and `scripts/guard-dispatch.js` (its `guard-commit-form` core). **Three defeats remain, all open to an agent** (guard LIMITS): `HUSKY=0` or `core.hooksPath` off .husky/_, each disarming every hook, and a wrapped `git am --no-verify`, skipping `pre-applypatch`. **Never gated**: `git filter-branch`, `git replace`, plumbing (`git commit-tree`, `git hash-object`) and a direct `.git` write, none of them hook-reachable — and history already on `main`.
- **Never `git commit --amend` in the shared tree.** **Enforced** (mantahostels#2540): `scripts/guard-dispatch.js` (its `guard-commit-form` core) denies it.
- **Show the diff of each change before committing it.** **Unenforced** (#2022): `scripts/guard-dispatch.js` (its `guard-commit-form` core) hands it over on your first `git add`, `git commit` or `commit-paths.js` call of the session (`rule:commit-show-diff`), but nothing sees whether a diff was shown.
- **A commit subject is at most 72 characters.** **Enforced** (#2332): `.husky/commit-msg` runs `scripts/check-commit-subject.sh` on every route but a replay and prints the whole rule (`rule:commit-message`). `Revert "…"`, `Reapply "…"`, git's own `Merge branch …`-style, `fixup!`, `squash!` and `amend!` subjects pass; `--no-verify` and `HUSKY=0` skip it.
- **A commit subject is imperative and says what changed — no `so …` clause, no Conventional Commits prefix; the body gives the why.** **Advisory** (#2022): `scripts/guard-dispatch.js` (its `guard-commit-form` core) hands over the whole rule on the same trigger (`rule:commit-message`); nothing judges a subject's form or the body.
- **Push when `npm run push:check` finds every commit being pushed attested — by your certificates, a neighbour's, or both together — and run the suite only for what it names; your own act, never asked of the founder; then `npm run check:ci` once — read it, never rerun it: it judges a commit range, not your sha.** **Advisory** (mantahostels#244; mantahostels#1098; #766; #2018; #2285): `scripts/guard-dispatch.js` (its `guard-commit-form` core) hands you the whole rule at your first commit, or the next where its gate rules fill that one's ceiling, and `scripts/guard-dispatch.js` (its `guard-push-rules` core) before your first push where no commit has (`rule:push-cadence`); `scripts/guard-unpushed-commits.js` names unpushed commits at Stop. With the `landing` module on, push to `landing` once the tests you touched pass; no push owes `push:check`, and the lander runs the full suite (`rule:push-cadence-landing`, #2929).
- **A push warns unless full or admissible certificates — from a bare `npm run test` or `--changed`, over a read graph that renders — attest its range between them; no whole-suite run is owed (mantahostels#2207).** **Advisory** (mantahostels#987; mantahostels#908 chose a warn over blocking a push on a neighbour's red; #185): `.husky/pre-push` names each unattested file, and `scripts/guard-dispatch.js` (its `guard-push-rules` core) hands you the rule on your first push (`rule:push-green-suite`). With the `landing` module on, no push owes a certificate: the lander runs the full suite (#2929).
- **`npm run test` narrows to the diff (mantahostels#3208), so the whole suite is `npm run test -- --full=<cause>` (#182: a required, closed-vocabulary reason); `npm run test:changed` may stand in for it wherever the read graph renders from the tree. The run settles that itself and says which you got (mantahostels#2146, #998).** `scripts/run-vitest.js` unions the diff's runtime READERS, from the manifest and the tree's render, into vitest's import-graph selection, so a changed document selects its readers (mantahostels#2095) — failing open to a bare `--changed`, warning, if the manifest is unreadable, and to the manifest alone, marked not admissible, if the tree will not render. **Unenforced** (mantahostels#2095, mantahostels#2146): only `scripts/run-vitest.js` grants that, and only to an argv holding nothing but `--changed` and its ref, as a bare run supplies; nothing refuses a push backed by one; and the extractor is lexical, so an INDIRECT read — a test importing a helper — is unselected, unseen by `--check`. **A fourth gap (mantahostels#2270): a manifest written over a neighbour's mid-edit tree can gain or drop an edge, and `--check` never sees it**; `generate-test-read-edges.js` warns on an uncommitted read, but an edit landing and reverting between two writes stays unseen. With the `landing` module on, a bare `npm run test` runs only the tests you touched and never widens, no run stands in for the whole suite at a push, and the lander runs the full suite (#2930).
- **Reconcile the shared `main` by fast-forward or not at all — `git pull --ff-only`. A refusal means it has diverged: merge `origin/main` in a throwaway worktree, run the suite there, and fast-forward the shared tree onto the result (#290). Never merge or rebase in the shared tree itself.** **Enforced** (mantahostels#245, #290): `scripts/guard-dispatch.js` (its `guard-pull-form` core) denies a rebasing or merging pull, a `git merge` without `--ff-only` and a `git rebase` in the shared tree, as a `PreToolUse` Bash hook, and hands you the whole rule on the command itself, refused or not (`rule:pull-fast-forward`).
  - **Never force-push `main`.** **Enforced** (#1733): `scripts/guard-dispatch.js` (its `guard-branch-publish` core) denies it, printing why and the follow-up commit to make instead (`rule:main-rewind`).
- **A file a live session has written is taken — leave it until that session releases it, its own commit lands all its hunks (#2058, #2148), or its process ends.** **Enforced** (mantahostels#113): `scripts/guard-dispatch.js` (its `guard-file-claim` core), a `PreToolUse` deny on `Write|Edit|NotebookEdit`, denies the write and hands you the whole rule on your first guarded write — or the NEXT, where the arbiter REFUSED it or merely spoke on it, a note spending the same envelope (mantahostels#2369, mantahostels#2386) (`rule:file-claim`).
- **When a live session blocks you, wait on it — `node scripts/session-arbiter.js wait <path|issue>`, backgrounded — and never ask the founder whether to.** Past its ceiling, ASK the holder in band — `request <path> "<why>"`. The holder reads it at its next **write** to that file, `release` of it or turn where the delivery mod runs, hourly at most; a repeat is no new ask. Read its answer, a release or `decline`, with `requests`. **Unenforced** (#543, mantahostels#1702): nothing tells a session asking the founder from one with a real question, or makes a holder read or answer a request.
- **Nothing refuses a Bash-route write to a claimed file, on either tier — but a tier-1 one is announced first: `scripts/guard-dispatch.js` (its `guard-claimed-bash-write` core) injects the live claims on the paths it names, once a session per holder and path and within a 2,000 B session budget (then an hourly pointer), and is silent where none is held.** Nine spellings, plus the tier-1 paths an inline `python`/`node` QUOTES (mantahostels#2854), so a wrapper or `dd` still passes unseen and `scripts/` gets nothing — read the claims yourself before one (`node scripts/session-arbiter.js list`). **Advisory** (mantahostels#287, mantahostels#295, mantahostels#1818; #185): `scripts/guard-dispatch.js` (its `guard-file-claim` core) carries this rule in the first envelope of its cluster, so it reaches your first guarded write, once (`rule:claim-bash-route`).
- **Reverse one change with the inverse targeted edit, never a whole-file restore; discard your own edits only by naming your own paths, and never `cp` a file over one in the shared tree.** **Advisory** (#2028): `scripts/guard-dispatch.js` (its `guard-claimed-bash-write` core) hands over the whole rule once a session, on a `cp`, `mv`, `git restore` or `git checkout` that writes a tracked file holding uncommitted changes (`rule:whole-file-restore`). It lands with the command's result, after the restore has run; a `Write` putting back a whole file and a `git -C` restore are never seen.
- **A script can be half-written while you run it — `node scripts/<x>.js` runs the bytes on disk, a neighbour mid-save included, so one that hangs or answers implausibly is re-run against a clean tree before it is debugged.** **Advisory** (mantahostels#1035; #185): `scripts/guard-dispatch.js` (its `guard-stale-script` core) warns, naming the holder. **Its silence proves nothing**, and blind spots it does not name itself: a script another script runs, one reached through a wrapper, `xargs`, `env` or `npm --prefix <dir> run`, and one run after a `cd`.
- **A hand-rolled wait loop takes a ceiling — a `timeout` wrapper or a counter** (mantahostels#2012). **Advisory** (mantahostels#2042; #185): `scripts/guard-dispatch.js` (its `guard-wait-loop` core) warns, handing over both recipes. **A loop started outside the Bash tool is never seen.**
- **An `rm` Claude Code's removal check cannot resolve is refused once — a variable-then-slash target the command never sets, a relative glob after a `cd`, or any `rm` beside a `bash -c` or `bash $script` — naming the two spellings that never prompt: a literal path in a call of its own, or no `rm` at all.** **Enforced** (#2436): `scripts/guard-dispatch.js` (its `guard-rm-unchecked` core) (`rule:rm-unchecked`); the re-send of the same command passes, as the limbs infer the harness's check rather than read it.
- **A shell script no repository tracks that writes git state turns on errexit and nounset (`set -eu`) before its first `cd`, `source` or git write, and keeps them on.** **Enforced** (#3162): `scripts/guard-dispatch.js` (its `guard-scratch-git` core) refuses running one under `bash`, `sh`, `zsh`, `dash` or `ksh`, on a `<` redirect, through `source` or `.`, as the command itself, behind a `timeout`/`env`/`nohup`/`nice`/`command`/`exec`/`time`/`sudo`/`xargs` prefix, or inside a shell's `-c` text. It reads the script's text lexically, so a git act spelled through a variable or another script passes, and a script piped into a shell or a heredoc into `bash` is never read.
- **Build any scratch repository under `mktemp -d`, outside this repository**, so a git command in a scratch directory that is not a repository cannot walk up into the shared `.git/`. **Unenforced** (#3162): the refusal says it; nothing checks where a script builds.
- **A Bash wait over 15 minutes is refused — hand the work back, never end on `waiting:`** (#1286). **Enforced** (#1288): `scripts/guard-dispatch.js`, its `guard-wait-loop` core (`rule:wait-length`).
- **A denied edit is registered as a debt, and the entry is completed by the session that was denied.** **Enforced** (mantahostels#120): `scripts/guard-dispatch.js`'s `guard-file-claim` core — the arbiter registers on deny and reads the store on the next claim — and the same guard hands you the rule before any of that (`rule:denied-edit-debt`).
- **Finished with a guarded file? Your commit gives the claim back; where it cannot, release it: `node scripts/session-arbiter.js release <path>`.** **Unenforced** (mantahostels#121, mantahostels#126): nothing makes a session release by hand. **The exception (mantahostels#2336, #2058): `.husky/post-commit` gives back your own whole-file claim on every committed path left holding none of your uncommitted changes — clean, or carrying only changes it can prove are another session's.** `scripts/guard-dispatch.js` (its `guard-file-claim` core) hands you the whole rule on your SECOND guarded write, the first envelope being full (`rule:claim-release`).
- A **script** that writes a tracked doc is invisible to that hook and must claim for itself. **Unenforced** (mantahostels#113): nothing detects the omission. The same guard hands you the rule on a write under `scripts/`, where the script is being written (`rule:script-self-claim`).
- **A raw issue-body write erases a parallel session's edit.** **Enforced** (mantahostels#131, mantahostels#132): `scripts/guard-dispatch.js` (its `guard-issue-body` core) (`rule:issue-body-clobber`).
- **An issue created with no `takes:` label routes to nobody.** **Enforced** (mantahostels#453, mantahostels#470, mantahostels#511, mantahostels#519): `scripts/guard-dispatch.js` (its `guard-issue-create-label` core) (`rule:issue-takes-label`).
- **A close that names no outstanding work loses it.** **Enforced** (mantahostels#185): `scripts/guard-dispatch.js` (its `guard-issue-close` core) (`rule:close-outstanding`).
- **A commit staging `docs/reference-roadmap.html` must leave it structurally valid.** **Enforced** (mantahostels#698): `scripts/check-roadmap-valid.js` in `.husky/pre-commit` (`rule:roadmap-validity`).
- **Always commit the lockfile with the `package.json` change that moves it.** **Enforced** (#2029): `scripts/check-lockfile-sync.js` in `.husky/pre-commit` refuses a staged lockfile whose root entry does not mirror the manifest's dependency fields, or a manifest declaring dependencies with no lockfile, and prints the whole rule (`rule:lockfile-sync`). Unseen: a workspace member's `package.json`, a v1 lockfile's ranges, and a pnpm, Yarn or Bun lockfile.
- **A commit staging `skills-lock.json` stages the record of a completed `node scripts/check-vendored-skills.js --upstream` run, its lock and licence-notice hashes matching the staged ones.** **Enforced** (#2394, ruled at #2377): `scripts/check-vendored-skills.js`'s `--covered` mode in `.husky/pre-commit` refuses a missing, unparseable or stale `.agents/vendored-upstream-pass.json`, naming the command. A run with any licence not matching writes no record. `WFC_UPSTREAM_RECORD_OFF=1` stands the refusal down for one commit, for a GitHub outage that SKIPs the run, and `scripts/check-weakens-line.js` refuses that commit until a `Weakens:` line names the variable.
- **A commit that weakens a check names each weakening on a `Weakens:` line, or splits it into a commit of its own.** **Enforced** (#2235): `scripts/check-weakens-line.js` in `.husky/commit-msg` refuses a commit whose staged diff turns a module off in `.claude/workflow-core.json`, runs a `check-*`, `guard-*` or test command fewer times in a workflow, adds a skip to a test file HEAD holds, or runs with a gate's `WFC_<NAME>_OFF` stand-down set, naming each one its message leaves unnamed (`rule:weakens-line`). A merge and a replay stand down; what it does not see (an `if: false`, a narrowed argument, a skip moved between tests, an amend) is in its own header.
- **A commit must not write back a file a neighbour changed since your base.** **Enforced** (#100, #113, #114): `scripts/stale-write-back-gate.sh` in `.husky/pre-commit` refuses it (`rule:stale-write-back`). Residuals: a generator reading stale inputs after your first write to its output minted a base equal to HEAD, and passes; `HUSKY=0` and a moved `core.hooksPath` skip it with the rest of the stack; plumbing (`commit-tree`) is never hook-reachable; and a path over the tier-scan's mint cap (`SCAN_MINT_MAX`) is judged against the session-start base until minted; its other skips are in its own header.
- **Research never lands in `docs/research/` — post it on its issue.** **Enforced** (#2356): `scripts/check-research-added.js` in `.husky/pre-commit` refuses a commit adding a file there, a rename or copy into it included, and prints the whole rule (`rule:research-in-tree`). Editing or deleting a note still there passes.
- **A commit is refused while the tree tracks a gate's subject with its switch off** — a test file with no `commands.test`, the roadmap page with `roadmap` off, the operating manual or a §B entry with `governance` off, the brand sheet and `app/` with `site` off. **Enforced** (#1506): `scripts/check-gate-switches.js` in `.husky/pre-commit` names the subject, the config edit and the `init-adopter.js --no-plugin-install` run that fix it.
- **Before adding any package, verify it exists on the registry with real download history and active maintenance.** **Enforced** (mantahostels#1803): `scripts/guard-dispatch.js` (its `guard-npm-install` core) denies an install naming a package `package.json` does not list unless it carries `--ignore-scripts` and passes the registry's existence, age and download checks, and denies a bare `npx` of an unlisted name.
- **The roadmap HTML and `docs/roadmap-digest.md` ship as a pair, their version lines matching.** **Enforced** (mantahostels#910): `.husky/pre-commit` refuses an HTML staged without its digest through `scripts/check-roadmap-pair.js`, and a drifted version line through `scripts/check-digest-version.js`, each printing the regenerate-and-commit fix.
- **A commit staging `app/` that adds a banned tell from the brand sheet's §11 is refused.** **Enforced** (mantahostels#858): `scripts/check-website-copy.js` in `.husky/pre-commit` names each tell and its rewrite.
- **Closing a roadmap card's issue by hand forecloses /card-close.** **Enforced** (mantahostels#220): the same `guard-issue-close` core of `scripts/guard-dispatch.js` (`rule:card-close-by-hand`).
- **While something runs in the background, end the turn — and a turn ends with text and no tool call at all.** A background subagent or Bash job usually wakes this session, and one finishing mid-call is folded into the next tool result (#845) — so a poll learns nothing and costs a full-context turn ([docs/research/waiting-stall-forensics.md](https://github.com/lucmoseley/workflow-core-tracker/blob/0a69e0d4be03/docs/research/waiting-stall-forensics.md)). Say in one line what was delegated and what happens with its result, then stop. **In a background job that line begins `waiting:`** — `scripts/guard-priced-options.js` refuses a turn carrying none of `result:`, `needs input:` or `waiting:` (mantahostels#1200), capped at **3 blocks a session** of its own (mantahostels#2544), and its refusal drops you back inside the turn, where looking again is the cheapest move, the loop the cap bounds (mantahostels#1994). Outside the marker line never narrate waiting, never "end the turn" with an inert command like `true`, a tool call that re-invokes the session, and never re-read the job's own `tasks/*.output` file while it runs. **A `killed` notification is not a finished job.** **Enforced** (mantahostels#627, mantahostels#659): `scripts/guard-dispatch.js` (its `guard-agent-poll` core), whose 3-look cap rests on that cost (#845). Known residual: it counts calls and never intent, so a real reason to look three times is refused too; and a poll spelled otherwise — `cat`/`wc`, `tail -f`, a script — is unclassified. A `waiting:` on nothing is refused at Stop by `guard-priced-options.js`, failing open on a spelling it cannot read (mantahostels#2487).
- **A hand-fired `gh workflow run` of `scheduled-checks.yml` or `ci.yml` spends the same 3-a-day budget the session-start autofire spends** — off the one counter every route writes, the `.sweep-autofire` marker in the git common dir, which worktrees share, and with no exemption for repairing a missed slot (mantahostels#2188; mantahostels#3514). **Enforced** (mantahostels#2202): `scripts/guard-dispatch.js` (its `guard-sweep-fire` core) denies the fire once the day is out (`rule:sweep-fire-budget`).
- **A turn never ends with uncommitted work in the shared tree** — the one-line `waiting:` hand-off, while a launch is still out, the exception and the only one. **Enforced** (mantahostels#1555): `scripts/guard-uncommitted-work.js` refuses a turn while this session's own tracked edits sit uncommitted, capped at **6 blocks a session**.

### Ground truth and commands

- **`docs/doc-map.md` §A is itself `derived`**, rendered from `docs/doc-map-classes.json` — register a document with `node scripts/register-doc.js` and `npm run gen:doc-map-section-a`, never by writing a row (mantahostels#1852). **Enforced**: `scripts/check-doc-map.js` refuses a hand-written row in `.husky/pre-commit` and in CI, printing the `register-doc.js` recipe.
- **A superseded value left live is reported, not refused — but a `Supersedes` bullet with no key in `docs/doc-map-superseded.json` is.** **Enforced** (mantahostels#861): `.husky/pre-commit` runs `scripts/check-superseded-values.js --broken-only` on a commit staging the map or its sidecar, printing the fix; the live-value scan, `npm run check:superseded`, only reports. `scripts/guard-dispatch.js` (its `guard-commit-form` core) hands over `rule:superseded-values-gate` on the first commit staging a `docs/` path where `governance` is on.
- **Cite this repo's tracker bare — `#N`. `mantahostels#N` is the inherited tracker, different issues under the same numbers.** **Enforced** (#162, #2015): `scripts/check-citation-tracker.js` refuses at commit a newly-added `mantahostels#N` the inherited tracker never used, and `scripts/guard-dispatch.js` names one as a `Write` or `Edit` adds it, handing over `rule:citation-tracker`. A number both trackers used passes both; nothing catches that half.
- **The pre-commit Biome gate reads this commit's own staged paths only** — `npm run check:staged`, where `npm run check` is the whole repo (mantahostels#179). **Advisory**: `scripts/guard-dispatch.js` (its `guard-commit-form` core) hands over `rule:biome-staged-gate` on the first commit staging a file Biome reads.
- **A `derived` or `generated-only` document is never hand-edited** — edit its source and re-run its generator. **Advisory** (#2016): `scripts/guard-dispatch.js` (its `guard-file-claim` core) reads the written path's class from `docs/doc-map-classes.json` and hands over `rule:doc-authority-class` on a `Write`, `Edit` or `NotebookEdit` of one, once a session.
- **`npm run lint` never sees a shell file — `npm run check:sh` is shellcheck over the ones `formatters.js` lists.** **Advisory** (#2019): `scripts/guard-dispatch.js` (its `PostToolUse` `post-write` core) hands over `rule:shell-lint-blind` after a `Write` or `Edit` of a shell file, once a session.
- **A `Write`/`Edit` in Biome's scope, shell or Python is formatted on the spot, so the file reads back reformatted.** **Advisory** (#2019): `scripts/guard-dispatch.js` (its `PostToolUse` `post-write` core) names the file on every reformat and hands over `rule:write-reformatted` on the first, once a session.
- **Route every `docs/reference-roadmap.html` edit through the `roadmap-edit` skill loop — never hand-edit that file.** **Advisory** (#2021): `scripts/guard-dispatch.js` (its `guard-file-claim` core) hands over `rule:roadmap-edit` on a `Write`, `Edit` or `NotebookEdit` of it, once a session, in a host with `roadmap` on (#2301). It cannot tell a hand edit from the loop's own, so it prints on either; a Bash-route write (`sed -i`, a redirect) escapes it.
- **`docs/operating-manual.md` is written only through the `manual-sync` skill — never hand-edited and never refreshed outside it.** **Advisory** (#2233): `scripts/guard-dispatch.js` (its `guard-file-claim` core) hands over `rule:manual-sync` on a `Write`, `Edit` or `NotebookEdit` of it, once a session, in a host with `governance` and `roadmap` both on, where the skill can run. It cannot tell a hand edit from the skill's own, so it prints on either; a Bash-route write (`sed -i`, a redirect) escapes it.
- **Load the `writing-for-agents` skill before writing a skill file, a `CLAUDE.md` or an `AGENTS.md`.** **Advisory** (#2030): `scripts/guard-dispatch.js` (its `guard-file-claim` core) hands over `rule:writing-for-agents` on a `Write`, `Edit` or `NotebookEdit` of a path under `.claude/skills/` or `.agents/skills/`, or of any `CLAUDE.md` or `AGENTS.md`, once a session. It never sees whether the skill was loaded, and a Bash-route write escapes it.

### Gotchas

- **No suite run is keyed to the sha you push.** **Advisory**: `scripts/guard-dispatch.js` (its `guard-push-rules` core) hands over `rule:ci-status-lag` on the first push.
- **A red suite in the shared tree may be a neighbour's half-written file.** **Advisory**: `scripts/guard-suite-concurrency.js` hands over `rule:suite-tree-dirty` on the first suite.

### Machine limits

- **Run one `tsc` at a time, machine-wide, on its ~2.75 GB rung (#3163).** **Enforced**: `npm run typecheck` waits for the slot through `scripts/queue-run.js --tsc`, and `scripts/guard-suite-concurrency.js` denies a bare `tsc`, `npx tsc` or `npm exec tsc` beside a running one or under the rung, naming the `queue-run.js --tsc` form, with no escape. A `tsc` launched from inside a script never reaches the guard, but is counted off `ps` once running.
- **Never run two builds or two dev servers concurrently.** **Enforced** (#1733, #1759): `scripts/guard-suite-concurrency.js` denies a second `next build` or `next dev`, printing how to stop the first (`rule:build-concurrency`).
- **Run one whole suite at a time, machine-wide — a SECOND is DENIED (#2680).** `free -m` must read **~2.9 GB** for it (5 workers), and **~4.0 GB** where a second runs anyway; a launch under its rung is refused and sent to the queue (#2305). **Extrapolated below ~7.7 GB** — `docs/environment.md`. **Enforced** (#155, #2305): `scripts/guard-suite-concurrency.js` denies a launch under its rung and a second whole suite, each naming the `--queue` form, with its escape; a run resolving below 121 test files, or a touched run at any count, rests on a lower rung of its own and is never refused at the count (#2558, #2931, #2935); a `--queue` launch and a build under a rung are warned.
- **Prefer targeted runs to the full suite unless asked. Run a suite in the foreground, `timeout: 600000`: an overrun backgrounds and notifies. Wrap `--full=<cause>`/`--queue` in `bg-run.sh run <name>`, same call, so a kill reads KILLED.** **Enforced**: `scripts/guard-dispatch.js` (its `guard-suite-background` core) refuses a detached suite, or an unbounded one wrapped in a shell `timeout`; `scripts/guard-dispatch.js` gives the `bg-run.sh` recipe; `scripts/guard-dispatch.js` (its `guard-agent-poll` core) caps the looks.
- **In an adopter, prefer a targeted run to the whole suite unless asked.** **Advisory** (#2237): `scripts/guard-suite-concurrency.js` hands over `rule:targeted-runs` once a session, with `suites` on, on a launch of the host's declared `commands.test` with nothing after it; a command running `run-vitest.js`, which selects from the diff, is no whole suite. Any further word reads as narrowing, so a flag such as `--silent` goes untold; a headroom warning or refusal on the same launch swallows it; a host declaring no `commands.test` is never told; and a declared command naming none of the runner words the hook's `if` patterns name (npm, node, next, python, pytest, npx, yarn, pnpm, bun, make, cargo, `go test`) never reaches it (#2303).
- **Run `free -h` before and after any build or full test run, and report the available figure.** **Advisory** (#2024): `scripts/guard-suite-concurrency.js` prints the MemAvailable reading and hands over `rule:memory-figure` on the first build or whole-suite launch a session makes, `npm run test:py` included. A launch its headroom warn or refusal stops gets that alone.
- **Count Claude processes by `argv[0]`, never `comm`** — a backgrounded session's `comm` is its version number, so a `comm` matcher finds no session at all. The `argv[0]` spellings, and counting sessions not processes: `docs/environment.md` §5. **Advisory** (#2027, mantahostels#481): `scripts/guard-dispatch.js` (its `guard-self-match` core) hands over `rule:claude-process-count` once a session, on a `pgrep` without `-f` or `-v` whose pattern selects `claude`, a `ps -C claude`, a `comm`-only column, a plain `ps` with no format option, or a `/proc/*/comm` read, the last three in a command naming `claude`. A count through a script, one naming no `claude`, and the shapes the guard's LIMITS lists — `pidof`, `killall`, `/proc/*/stat` or `/proc/*/status` — are never seen.
- **Never run recursive `find`/`grep`/watch across `node_modules`, `.next`, `.git` or build output; `find /` is refused.** **Advisory** (#2060): `scripts/guard-dispatch.js` (its `guard-recursive-dot-read` core) hands over `rule:heavy-tree-search` once a session, on a recursive `grep` or `rg`, a `find`, or either under `watch`, whose root's last component is `node_modules`, `.next` or `.git`, or `dist`, `build`, `out` or `coverage` where git ignores it; and on a `find` from the repo root with no `-prune` or `-maxdepth`, or a recursive `grep` from it. A search inside such a tree, a path-spelled command word, and any other watcher are never seen. `find /` is refused by `scripts/guard-root-find.js` (#1006).
