# Triage Labels

<!-- rule:triage-role-labels:begin -->
The vendored skills speak in terms of five canonical triage **roles**. **This repo has no state labels** (mantahostels#235), so a role maps to an *action*, not to a label string.

| Role in mattpocock/skills | What to do in this repo |
| --- | --- |
| `needs-triage` | Apply `takes:triage`. |
| `needs-info` | Apply `takes:human`, and ask the question in a comment. There is no reporter distinct from the maintainer here — waiting on one collapses to work done outside Claude Code. |
| `ready-for-agent` | **Apply no label for this role.** Pick the single `takes:` value naming the command that opens the issue — `takes:implement`, `takes:wayfinder`, `takes:to-spec` or `takes:to-tickets` — from the §`takes:` table below. |
| `ready-for-human` | Apply `takes:human`. |
| `wontfix` | Apply no label. Close with `gh issue close <n> --reason "not planned"` plus a comment saying why. The `guard-issue-close` core waives its `**Outstanding:**` requirement for exactly that reason. |

**Create none of `needs-info`, `ready-for-human`, `ready-for-agent` or `wontfix`**: a vendored skill applying one fails on an unknown label.
<!-- rule:triage-role-labels:end -->

The repo's other labels are roadmap categories (`Tech & Stack`, `Data & Analytics`, …), not triage states.

## Kind labels — an axis the vendored skills lack

<!-- rule:kind-label-vocabulary:begin -->
The roles above are **states**. `kind:` says what an issue *is*. `/to-spec` and `/to-tickets` reach for the same single role for a spec and for its own tickets, so without `kind:` the two are indistinguishable.

| Label | Meaning | Applied by |
| ----- | ------- | ---------- |
| `kind:spec` | A spec/PRD. A parent document, not a unit of work. | `/to-spec` |
| `kind:ticket` | A unit of implementable work, broken out of a spec. | `/to-tickets` |
| `kind:brief` | A hand-off ticket a many-destination map files per deliverable, awaiting its spec. Takes no `wayfinder:<type>` (#578). | `/wayfinder` |

An issue may carry a category, a `takes:`, a `kind:` and a `waiting:`; none is an alias for another. Not every issue needs a `kind:` — a roadmap card's issue or a `wayfinder:*` ticket takes none.
<!-- rule:kind-label-vocabulary:end -->

## `takes:` — which command opens the issue

**Read the issue's `takes:` label and type its value.** Every open issue carries exactly one, so a missing `takes:` is a defect to fix, never a state to interpret. `npm run check:labels` reports one missing, duplicated, contradicted by the issue's own `kind:`/`wayfinder:`/`manual-finding` label, or gone stale; `scripts/pick-next.js` shows the value in its TAKES column. Both only ever report (mantahostels#227).

**A creation carrying no `takes:` label is denied outright** — the `guard-issue-create-label` core, a `PreToolUse` Bash hook (mantahostels#453, mantahostels#470, mantahostels#511, mantahostels#519). All three spellings are refused: `gh issue create`; the same creation as `gh api --method POST …/issues` — including the methodless form, since gh sends a POST wherever a call carries fields; and a `gh api graphql` `createIssue` mutation carrying no `labelIds`. It also denies a value outside the seven below: a label GitHub does not know aborts the whole `gh issue create` and still exits 0, so a typo files nothing while reading as success. The escape is a value, never an omission — `takes:triage` where the disposition is undecided.

<!-- rule:create-command-shape:begin -->
**Keep the create line whole, and pass the body by `--body-file -`, fed from a quoted heredoc: `cat <<'BODY' | gh issue create … --body-file -`.** The quoted delimiter stops bash executing backticks in it, and it is the one body shape the guard reads whole: a `"$(cat …)"` body, or a heredoc under a `\`-continued create line, hides the body: blank-body passes it, `takes:human` refuses it (#668). A continuation or a quote in the title does not hide the `takes:` label itself (#490).
<!-- rule:create-command-shape:end -->

**The GraphQL route is the weakest of the three.** GraphQL takes label **node ids** (`LA_kwDO…`), not names, so a mutation that carries `labelIds` gives the guard no way to tell whether any of them is a `takes:` value: it **warns** there rather than denying, and a warning is a prompt to check the label, not a claim that one is missing. A query the guard cannot read at all — from a file, from stdin, from a variable or a command substitution — passes in silence. It does not warn there: a warning would fire almost entirely on the read-only GraphQL queries this repo runs daily, and the `guard-issue-body` core already warns on those same commands, so the opacity reaches the session anyway. A hook also sees Bash calls only, so an issue filed by a script or from the web UI still reaches the tracker bare (mantahostels#464); `check-issue-labels.js` remains the control for all of these. On the Bash routes **every** `takes:` word on the command is validated, not just the first, a create naming a label GitHub does not know aborting while still exiting 0.

<!-- rule:takes-value-vocabulary:begin -->
| Label | Meaning | Command |
| ----- | ------- | ------- |
| `takes:wayfinder` | An open question whose resolution is a decision. | `/wayfinder <n>` |
| `takes:to-spec` | A chunk large enough to need a spec before tickets. | `/to-spec <n>` |
| `takes:to-tickets` | A spec ready to break into tickets. | `/to-tickets <n>` |
| `takes:implement` | A specified unit of work. | `/implement <n>` |
| `takes:triage` | Disposition not yet decided. | `/triage <n>` |
| `takes:human` | Done outside Claude Code entirely. | — |
| `takes:children` | A container — open a child instead. | — |
<!-- rule:takes-value-vocabulary:end -->

**Why `takes:triage` and `takes:children` are separate values** (mantahostels#226): one absent label for both "type `/triage`" and "a container: open nothing here" would leave the reader deciding which applies, and the discriminator — open-child count — is invisible in the GitHub UI.

**Copies to update when the value set moves**, none of them prose, are listed in `scripts/lib/takes-label.js`'s header.

<!-- rule:takes-label-nuances:begin -->
**`takes:human` is picked from the next action, never the subject.** Name the concrete act performed outside Claude Code, and it is one of the founder's own (#1077 Q1 (A), amended by Q2 (A)): pay, buy or subscribe; sign or accept terms; delete; install an app; accept an invite; grant access; OAuth Authorize; a CAPTCHA guarding an act he is taking; card entry; a one-time code; phone verification; signing a site in for the first time; an act Claude Code's automatic permission check refused (never the same act by another path), per `rule:founder-handover`; a phone call, an in-person act, or an act in a desktop or phone app; sending anything a person outside reads. If you cannot name one the label is wrong, however legal- or compliance-flavoured the subject reads: an agent reading repo files and writing a ruling takes `/wayfinder`, and one applying a prescribed edit takes `/implement`. **A founder decision or confirmation takes `takes:wayfinder`** — the founder makes it inside Claude Code, in a `/wayfinder` grilling session, so nothing happens outside it (mantahostels#3439). **There is no "no command opens this" shape**: a scripted tracker whose queue has emptied closes, or moves to the command that owns what is left, and never sits under `takes:human` (mantahostels#3352). **An act whose product is a file in this repository is never an outside act**, whatever tool a document names as the owner's — an SVG is text, and an agent writes it; the founder's taste on an agent-drawn asset is a `/wayfinder` review (mantahostels#3439, mantahostels#3503). **A `manual-finding` is never that shape either** — `manual-sync` in full mode is the command that opens it, so a stale operating-manual stamp takes `takes:implement`, and `check-issue-labels.js` flags the contrary as CONTRADICTED (mantahostels#2810, mantahostels#3146). **A permanently-open issue is not that shape either** — every issue must be closeable (mantahostels#678).

**Being barred is not being impossible, and that is the mistake this label actually attracts** (mantahostels#2775, the ticket that ruled it). A skill's own scope barring *this* pass from an edit, a repo rule barring an agent from an act, a command wanting a password — none of them puts the work outside Claude Code, and the last least of all: the founder types `! <cmd>` and it runs *in* the session. Each of those goes back to `/implement` or to `/wayfinder`. **A `403` is the fourth shape, and it names one permission, never the act** (mantahostels#3358). Before calling an act outside, enumerate what the token *does* hold and look for a route through it.

**So a `takes:human` body NAMES ITS OUTSIDE ACT, on its own line: `**Outside Claude Code:** <the act, in plain words>`.** **Enforced** (mantahostels#2775): the `guard-issue-create-label` core denies a `gh issue create` — flag form or REST — that applies `takes:human` and carries no such line, **and a `gh issue edit <n> --add-label takes:human` on an issue whose body has none** (mantahostels#3555), fetching the body through `gh` and failing open, recorded, where it cannot — but refusing one that rewrites the body in the same call with a `--body` it cannot read or any `--body-file` (#669), since relabelling alone always has its body fetched. **The same guard denies either where the Outside line names a repo file as the act's product** — a backticked path under `docs/`, `app/`, `scripts/`, `components/`, `lib/` or `public/`, a `.svg`/`.png`/`.md`/`.js`/`.ts` filename, or Inkscape, Figma, Photoshop or a spreadsheet — the lexical test `check-issue-labels.js` repeats as REPO-FILE-ACT (mantahostels#3555). The line check cannot tell whether the act named is real. It reads a heredoc piped into `--body-file -` — the `cat <<'BODY' | gh issue create …` form every create uses — where it is the command's only `gh issue create` (mantahostels#3439); a body it cannot read (a `$VAR`, a `$(…)`, a file not on disk, an unquoted heredoc whose body would expand, `--body-file -` fed any other way) is refused (#668). **Two routes escape it entirely**: the GraphQL form, where labels are opaque node ids; and a create or relabel by a script or the web UI, which no `PreToolUse` hook sees. **Both are caught after the fact:** `scripts/check-issue-labels.js` reports NO-OUTSIDE-ACT on any open `takes:human` body whose line is absent or names nothing, and REPO-FILE-ACT on one whose line names a repo file. **A third limb refuses an Outside line that names a PROHIBITION rather than an act** (#140) — `no agent may`, `an agent is not permitted to`, `agents are barred`, `no session may`. **Every alternative names an agent or a session as the barred subject**: a prohibition about the *world* is usually part of a real errand — *"once submitted it may not be edited"*, *"phone the bank and ask why the account is barred"* — and a wider draft denied all of those. **Enforced**: the same `guard-issue-create-label` core denies it on create and relabel, and `check-issue-labels.js` reports BARRED-NOT-IMPOSSIBLE after the fact. Before relabelling, **test the bar rather than restating it** — `test -w <path>` for a file you believe unwritable, and read the rule itself for one you believe forbids it; a real bar is `takes:wayfinder`, an unreal one `takes:implement`. **Unenforced** (mantahostels#3358; mantahostels#804 for why a stale `takes:human` goes unreviewed): the same `check-issue-labels.js` WARNs HUMAN-UNREVIEWED on any open `takes:human` whose `updated_at` is 14 or more days old, telling the reader of `node scripts/status-report.js` to re-test the act in-session and comment with what was tried. Any touch resets that clock — a relabel, a sweep's body edit — so the WARN asks for a look and never proves one happened. A WARN and never a FAIL, because a real errand — a payment, a form, a reply from an OTA desk — legitimately outlives 14 days.

**Anything a person outside reads, the founder sends** (#1077 Q2 (A)) — an email, a LinkedIn message or connection note, a contact or support-desk form, a partner or affiliate application, a government registration, a public profile edit; a push to `main` publishing the website is not one. An agent drafts and iterates it with him; once he approves the final draft it may open a pre-filled Gmail compose window from the address the draft names, and it never presses Send, never pre-fills a website form, and no Chrome child sends (#1089 Q3 (A); the procedure is the `browser-ladder` skill's). **A website job no act on the list covers reaches the founder only after three methods failed** (#1077 Q3 (A)): at least three genuinely different free methods, each actually run, under a `Tried:` line, one per line with what it showed. **Enforced** (#1095): a fourth Outside-line limb passes a `takes:human` body only where its Outside line holds a word from the founder-act vocabulary, on the Outside line alone, or where a `Tried:` line, bold or plain, is followed directly by three or more list items, a sub-item counting as its method's detail rather than a method. `scripts/file-issue.js` refuses it and `check-issue-labels.js` reports NOT-A-FOUNDER-ACT after the fact; the `guard-issue-create-label` core denies it on create and relabel (#1097). **Accepted limit** (#1077 Q5 (A)): it sees three methods listed, never whether they were different or really run, and it passes a list word used in a non-act sense (*"look up which payment methods the site lists"*).

**A founder-facing item is filed the moment it exists, and a `takes:human` body follows one template ending `**Close when:** <what finishes it>`** — `rule:founder-deliverable`. **Enforced** (#983): the same guard and `file-issue.js` refuse a `takes:human` body without that line, and `check-issue-labels.js` reports NO-CLOSE-WHEN after the fact.

**A multi-step outside act gets an in-chat walk, not a re-explanation.** Where the Outside line names a walk a human must click through — a first sign-in to a third-party dashboard, credentials to capture, a one-off cutover — the walk takes the founder through the issue's body step by step, as a founder hand-over (`rule:founder-handover`) with any credential handed over as its secret line, and is never a second copy. **Unenforced** (#479): nothing detects a multi-step act walked without the hand-over, and an errand that is a *wait* on someone else earns no walk at all.

`takes:` is **disposition** — what to do with the issue next. `kind:` is **provenance** — what the issue is and where it came from: a `kind:spec` takes `/to-tickets` before its tickets exist and nothing afterwards, and a `kind:ticket` can take `/wayfinder` when it turns out to hide a decision.

**`takes:children` marks a container** — an open issue whose every remaining action sits on its open sub-issues.

**A `wayfinder:map` is never a container** while any open child carries a `wayfinder:<type>`: `/wayfinder <n>` works the map itself, so a map takes `takes:wayfinder`. **The exception is the exhausted many-destination map** — no open child carrying a `wayfinder:<type>`, each a spec or a `kind:brief` — which takes `takes:children` (#578).

A spec whose tickets are all *closed* is not a container either — nothing open carries its residual, so someone must decide whether it is discharged. That is `takes:triage`.

`scripts/check-issue-labels.js` writes no `takes:` value at all, and reports STALE-CONTAINER (mantahostels#227), and UNMARKED-CONTAINER on a spec whose tickets are still open — and a report at one session start may already be fixed by the next. Backstops: `scripts/place-new-issue.sh` asks at creation — **once per issue, not once per prompt**, since a batch shares one parent but not one disposition (mantahostels#314, the second issue of a batch, which a per-prompt ask left unlabelled; the fix had no ticket of its own) — and `scripts/check-issue-labels.js` reports on `npm run status` and daily from the session-start launcher.

**A spec's `takes:` moves the moment its tickets exist** — `takes:to-tickets` → `takes:children`, since the work now sits on the tickets. `/to-tickets` won't do it: its instructions end *"Do NOT close or modify any parent issue."* The sweep above makes the move, within one session start; move it by hand if you want it now. Left unmoved, the label invites a second `/to-tickets` run that duplicates tickets already created (mantahostels#1663).

## `card:<card-id>`

**Marks a closed issue as a parked re-file trigger for one roadmap card** — the question or task it raised waits on that card being taken, and is not written onto the card as prose (`docs/agents/issue-tracker.md` §Gating an issue, `rule:roadmap-gating`; ruled at mantahostels#3291, applied at mantahostels#3320). It says nothing about disposition or provenance, so it sits alongside `takes:`/`kind:` on a closed issue, never in place of one, and is applied only at close — never to an open issue. An issue relevant to more than one card carries more than one `card:<card-id>` label.

**Producer: whoever closes the issue onto a card** — `retire-to-roadmap`'s loop, a gated-issue close per the table above, or a hand close a session judges belongs to a card. **Consumer: the session taking that card**, via `gh issue list --state closed --label card:<id>`. Nothing checks that a card-relevant close actually applied the label; a close that forgets it loses the question silently, the same residual risk mantahostels#3291 named for the label route generally.

## `urgent`

<!-- rule:urgent-label:begin -->
**Anyone may apply the `urgent` label, agent sessions included** — it carries what issue structure cannot see, and holds until the issue closes or someone removes it. It covers its descendants and blockers at any depth (#3250), and an open `bug` ranks urgent unlabelled (#2664), so neither needs labelling. Selection reads and displays it, never writes it (mantahostels#101, mantahostels#111).
<!-- rule:urgent-label:end -->

## `waiting:external`

<!-- rule:waiting-external-vocabulary:begin -->
**`waiting:external` marks an issue whose action has been taken and now sits with someone outside the project** — an affiliate application submitted, an email sent to a party who has not replied. It says nothing about disposition or provenance, so an issue carries it *alongside* its `takes:` and `kind:` values, never instead of one: mantahostels#85 (no working channel to an outside partner) would be `takes:human` **and** `waiting:external` at once.

**The value set is closed at one value.** No `waiting:internal`, no `waiting:founder`, no severity suffix. mantahostels#101 (what defines urgency) ruled out a graded scale, since a graded scale rots.

**Producer: whoever hands the work off, at the moment it is sent** — the founder, or a session that sent the thing itself or has the founder's word that it was sent (#869). No script guesses the label: mantahostels#136 (nothing asks a mid-session issue for its labels) bars a script from guessing a routing value, and mantahostels#101 bars `pick-next.js` from writing at all. The one script that writes it, `scripts/park-blocked.sh <issue> waiting:external "<why>"`, applies the value its calling session names. It comes off by hand when the reply lands.

**Consumer: `scripts/pick-next.js`.** It reads how long the wait has run from the GitHub timeline's `labeled` event — never a date written into the body, which nothing updates when the wait resets — shows the elapsed days in a WAIT column, and **raises the issue's rank once the wait reaches 7 days**, longest wait first. A waiting issue always stays in the shortlist, and one under 7 days ranks exactly as it would with no label.

**Marking an issue "waiting" so the shortlist sinks it makes a stall quieter the longer it runs** — the failure mantahostels#85 already suffered — its request sat "pending" for over five weeks before anyone noticed. Ruled at mantahostels#243 (should a `waiting:external` label exist for work already handed off), built at mantahostels#259 (create `waiting:external` and give it a reader).

**7 days is the earliest point the evidence puts an action at** — chase again, from mantahostels#956's wait-threshold research. The threshold sits at the *first* action the research names rather than its later ones — switch channel at 21 days, treat the counterparty as non-responsive at 45 — because escalating is a prompt to look, not the action itself, and rank goes on climbing with age past 7 anyway.

<!-- rule:waiting-external-vocabulary:end -->

**A threshold rather than a curve** because the candidate population was three when it was set (census on mantahostels#243). The date comes from the issue timeline, never a hand-written body line, which rots and needs a parser. The label ships with its reader (mantahostels#235). This is **not** a breach of `pick-next.js`'s display-only rule for `takes:`: the label removes nothing from the shortlist, and what the sort reads is elapsed time, which a stale label cannot fake. ⚠ The **14 days** in `scripts/check-stale-claims.js` is a different figure and stays — how long a session sits on an issue is a different question from how long an outside party stays silent.

## `parked`

**`parked` marks an issue that waits on the founder** — a session hit a house decision, posted the round on the issue and ended `needs input:` (#2000, under the away-mode spec #1995), or the refill loop stopped a blocked session on it (#2699). It sits alongside `takes:` and `kind:`, never in place of one, and is outside the `waiting:` namespace, whose value set stays closed at one value.

**No session applies or removes it by hand.** `scripts/park-on-round.js`, a `Stop` hook, applies it when a background job ends `needs input:` with its round posted on an issue the session claims — the condition `guard-inventory.js` already checks (#1066). The refill loop (`scripts/refill-loop.js`) also applies it when it stops a blocked launch it will not resume: a question, a permission prompt or an API error past retrying (#2699, `scripts/lib/block-act.js`). It comes off when any session claims the issue (`claim-issue.js`) or, on a `Stop`-hook park only, when the founder types in that session (`scripts/unpark-on-prompt.js`, a `UserPromptSubmit` hook).

**Consumers: `scripts/pick-next.js` and the refill loop.** `pick-next.js` keeps a parked issue choosable (#2355, #2703) and lists it under a `PARKED` block with its age from the timeline's `labeled` event. The refill loop never launches it, in either mode (`scripts/lib/refill-decide.js`).

**Do not teach the skills this by editing their SKILL.md.** `.claude/skills/to-spec`, `to-tickets`, `implement` and `triage` are symlinks into `.agents/skills/`, and an edit there is reverted by the next vendor pull — which `skills-lock.json`'s `computedHash` does nothing to stop: it is per skill folder, names no file, and the installer rewrites it at every pull (mantahostels#1826, mantahostels#3522). An edit made anyway must be declared — `node scripts/check-vendored-skills.js --declare <path> --issue <n> --why "<line>"` — or the commit is refused. Route project conventions through these `docs/agents/*` files and `CLAUDE.md` instead: a declared edit still has to be re-applied by hand after every pull.
