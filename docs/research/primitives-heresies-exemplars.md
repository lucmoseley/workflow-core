# Research: primitives and heresies — declared lists and their enforcement (#2198)

Each finding gives a source URL.

## Terms

- **Primitive**: a building block of the codebase. The agent must use it for one concern (for example, one way to do data access). Source: Jo Van Eyck, youtube.com/watch?v=iPq_aCk3EsE (about 46:00-49:30); Kent C. Dodds, https://x.com/kentcdodds/status/2102843196296548461.
- **Heresy**: a bad pattern that an agent puts in the codebase. Other agents copy it and it spreads. Van Eyck attributes the term to Steve Yegge (Gas Town).
- **Sweep**: a recurring pass. It checks that the primitives stay clean and that each new feature uses them.

## Baseline (already read; not redone)

- Van Eyck, https://github.com/jovaneyck/software-factory-demo: `app/architecture.md` §Architecture primitives lists repositories for data access, DDD aggregates, domain services, large-scale unit tests with in-memory adapters, and thin adapters. `app/frontend/src/ui/README.md` tells pages to compose from a UI primitives kit. Raw Tailwind palette colours fail lint. A live `/design-system` page shows the kit.

## Findings

### F1. Steve Yegge, Gas Town — the source of "heresy"

- **What it is.** Yegge's multi-agent orchestrator. The term comes from his post "Gas Town Emergency User Manual". Source: https://steve-yegge.medium.com/gas-town-emergency-user-manual-cf0e4556d74b.
- **His definition.** Heresies are "compelling but wrong beliefs about the architecture that spread invisibly". "Agents are very approximate workers and they like to guess at stuff." A wrong guess that gets through review "becomes enshrined", and other agents then copy it. His example: "idle polecats" make it back into "the code base, comments, and docs all the time". Note: the unit of a heresy is a wrong *belief about the design*, not only a bad code pattern. It spreads through prose (comments, docs) as well as through code.
- **His remedy (two parts).**
  1. "Capture your guiding principles in the agent priming (onboarding)." Then you correct an agent by pointing at the principle it violates.
  2. Recurring review sweeps that file bugs, then fix sweeps that close them, again and again until reviews find only nitpicks. These sweeps are agent-run.
- **Form of the list in the code.** Each heresy has a capitalised name and a section in the role priming file. Example: `internal/templates/polecat-CLAUDE.md`, section "THE IDLE POLECAT HERESY": one MUST line, then a "Do NOT" list. Other named ones: "Batch-Closure Heresy" in `docs/design/polecat-lifecycle-patrol.md` and in Beads `PRIMING.md`. Source: https://github.com/gastownhall/gastown, https://github.com/gastownhall/beads/blob/main/scripts/release.sh.
- **Enforcement.** (a) A test: `internal/templates/templates_test.go` fails if the generated CLAUDE.md does not contain the string "IDLE POLECAT HERESY". So the warning itself cannot silently drop out of the priming. (b) `templates.go` uses the heresy heading as a marker (`PolecatLifecycleMarker`) to detect if the lifecycle text is present, and appends it if not. (c) A patrol agent (the Witness, `internal/witness/handlers.go`) checks for the bad state at run time.
- **Evidence it works.** Weak. Yegge says he must eradicate heresies "often multiple times". Also, the Gas Town record shows the doctrine itself changed: a later design (`docs/design/persistent-polecat-pool.md`) made idle polecats a healthy state ("Idle polecat heresy fix (skip healthy idle)"). So a named heresy list must be maintained; a stale entry becomes a heresy of its own.
- **What transfers.** Give each heresy a short name and one section in the always-loaded priming. Add a test that the priming still contains each named section. Run agent sweeps in pairs: a review sweep that files issues, then a fix sweep. Search prose (docs, comments) as well as code, because heresies spread in prose.

### F2. Stripe Minions — scoped rule files plus deterministic lint nodes

- **What it is.** Stripe's unattended coding agents. Over 1,300 merged PRs per week contain no human-written code; humans review them. Sources: https://stripe.dev/blog/minions-stripes-one-shot-end-to-end-coding-agents (Part 1), https://stripe.dev/blog/minions-stripes-one-shot-end-to-end-coding-agents-part-2 (Part 2).
- **Form of the list.** Rule files (Cursor format, synced to a Claude Code format). Stripe uses "unconditional global rules very judiciously", because otherwise the context window fills with rules. Instead rules are "scoped to specific subdirectories or file patterns, automatically attached as the agent traverses the filesystem". One rule set serves minions, Cursor and Claude Code, so there is no duplicate. Part 2 gives the reason: an agent "might encounter trouble following best practices or using the proper libraries, even with good linters". That is, rules carry the primitives ("the proper libraries"); lint alone does not.
- **Enforcement.** "Blueprints": a state machine of agent nodes and deterministic nodes. Nodes such as "Run configured linters" and "Push changes" do not call an LLM. A local executable selects and runs lints on each git push in under five seconds; a daemon precomputes lint heuristics. Then CI runs selected tests from over three million; many failures autofix. At most two CI rounds, then the branch goes to a human.
- **Evidence.** Scale only (1,300+ PRs/week). Stripe gives no measure of pattern drift.
- **What transfers.** Scope the primitive rules to the directory where they apply, so the agent sees them when it opens a file there. Make the lint step a deterministic node that the agent cannot skip. Keep one rule source for all agents.

### F3. Kent C. Dodds — primitives map, PR risk by primitive, cleanup cron agents

- **What it is.** Dodds' own statement (2026-09-23): "all you need is two things: 1. Good and discoverable primitives 2. A short conversation of how to use those primitives to do what you need done". Source: https://x.com/kentcdodds/status/2102843196296548461. His podcast "Better with Kent" has an episode "Your Coding Agent Needs Better Primitives" (four moves: create, combine, delete, expand primitives) and an episode on "a primitives catalog". Source: https://podcasts.apple.com/us/podcast/id1896798447 (episode descriptions only; no transcript read).
- **Form of the list (Kody).** A machine-readable taxonomy, `docs/contributing/architecture/primitives.yaml` in https://github.com/kody-hq/kody (870 lines, 76 entries: groups, primitives, invariants). Each primitive has `id`, `group`, `name`, a one-line `summary`, `code:` ownership roots (directories), and `docs:` links. The file header says: "This is NOT a living feature changelog". Update it "only when adding, removing, or materially reshaping a primitive". Invariants are a second list (example: "per-org-isolation: The org scopes every read/write, DO id, and vector path"). A smaller product, https://github.com/kentcdodds/kody-exchange, uses a Markdown table: `docs/contributing/architecture/primitives.md`, headed "Stable nouns. Not a changelog.", plus an Invariants list.
- **How an agent discovers it.** A short `AGENTS.md` index links "Primitives and invariants" to that file (kody-exchange `AGENTS.md`). Kody's `AGENTS.md` links a principles index with a "When to open it" column (`docs/principles/index.md`), one principle per page.
- **Enforcement.** Source: https://github.com/kentcdodds/kcd-skills, skill `visual-recap`.
  1. `check-primitives-map.mjs` validates the map: unique ids; every `code`/`docs` path exists on disk; summary is one line and at most 120 characters ("put detail in docs"). Run as `npm run primitives:check`.
  2. `classify-primitives.mjs` maps each changed path in a diff to a primitive by longest-prefix match. The PR then gets a risk label: `composes` (low: wires existing primitives), `extends` (medium: changes a primitive's contract; needs a manual preview test), `adds` (high: new primitive; must update `primitives.yaml` in the same PR). The PR description gets a rendered "system recap" block that names the touched primitives and invariants.
  3. Principles become checks: Kody principle "Examples over prose" (`docs/principles/examples-over-prose.md`) says "Show one example that matches the current code", and a `docs:check` member rejects guidance that sends agents to a forbidden path. That is a lint over *prose*, which is where Yegge says heresies spread.
  4. Sweeps. `kcd-skills` skill `autopilot` (rung 7): "Reviewers check each PR against the project's principles ... and each principle a machine can check becomes a lint rule or test." Rung 12: scheduled cleanup agents open PRs — weekly legacy reaper, daily test pruning, daily docs freshness, daily friction sweep, errors → issues. Only low/medium-risk PRs with green CI auto-merge (`skills/autopilot/references/templates.md` §Cleanup automations). Rung 2: "Write down the 'no': decisions agents would otherwise re-propose" (ADRs with "Revisit if").
- **Evidence.** Practitioner use in his own repos only; no published measure.
- **What transfers (strongest fit for a supervisor who does not read code).** The supervisor reviews *which primitive a change touches and at which risk level*, not the diff. A script, not an agent, decides that label from file paths. A validated map keeps the list short and keeps its paths true. Cleanup sweeps run on a schedule as agents and go through the same merge gate.

### F4. Evidence that agents copy and spread local patterns

- **GitClear, "AI Copilot Code Quality" 2025.** 211 million changed lines, 2020-2024. Lines classified as moved (refactoring, reuse) fell "from 25% of changed lines in 2021, to less than 10% in 2024, while lines classified as 'copy/pasted' (cloned) rose from 8.3% to 12.3%". Headline: "4x more code cloning, 'copy/paste' exceeds 'moved' code for first time in history". Source: https://www.gitclear.com/ai_assistant_code_quality_2025_research. Limit: correlation with AI adoption, vendor data, not replicated. It shows duplication, which is the opposite of one shared primitive; it does not show copying of a bad pattern as such.
- **Dinh et al., NeurIPS 2023, "Large Language Models of Code Fail at Completing Code with Potential Bugs".** One potential bug in the context drops the pass rate of CodeGen-2B-mono on buggy-HumanEval by more than 50%. Mitigations close only part of the gap. Source: https://arxiv.org/abs/2306.03438. This is the closest controlled evidence that a defect in local context propagates into generated code.
- **Gloaguen et al., 2026, "Evaluating AGENTS.md" (arXiv 2602.11988; ICLR 2026).** Context files "do not generally improve task success rates" and raise inference cost by over 20%. But "instructions in the context files are well followed by coding agents", repository overviews "are not helpful", and context files "are useful for specifying non-standard coding practices". Source: https://arxiv.org/abs/2602.11988. Consequence for primitives: a list of *this repo's own* ways (the non-standard part) is the useful content; a general tour of the repo is not.
- **No study found** that measures directly whether an agent copies an anti-pattern that sits in neighbouring files of the same repository. Searches run: GitClear; "LLM copies code smells from repository context"; AI-generated smells (https://arxiv.org/pdf/2605.02741 reports agents add a distinct "machine signature" of smells rather than only copying human ones). This is a gap.

### F5. OpenAI, "Harness engineering" — golden principles plus garbage-collection agents

- **What it is.** An OpenAI team built a product of about a million lines with "0 lines of manually-written code" over five months. "Humans steer. Agents execute." Source: https://openai.com/index/harness-engineering/.
- **The heresy problem, in their words.** "Codex replicates patterns that already exist in the repository—even uneven or suboptimal ones. Over time, this inevitably leads to drift." At first "Our team used to spend every Friday (20% of the week) cleaning up 'AI slop.' Unsurprisingly, that didn't scale."
- **Form of the list.**
  1. **Golden principles**: "opinionated, mechanical rules that keep the codebase legible and consistent for future agent runs", encoded in the repo. Examples: "we prefer shared utility packages over hand-rolled helpers to keep invariants centralized" (a primitive rule); "we don't probe data 'YOLO-style'—we validate boundaries or rely on typed SDKs".
  2. **A fixed layer model per domain**: "Types → Config → Repo → Service → Runtime → UI"; cross-cutting concerns enter only through "Providers". "Anything else is disallowed."
  3. **AGENTS.md as table of contents** (about 100 lines). The knowledge lives in `docs/` with design docs, "core beliefs", an architecture map, and "a quality document [that] grades each product domain and architectural layer, tracking gaps over time". They tried "one big AGENTS.md" and it failed: "Too much guidance becomes non-guidance ... Agents end up pattern-matching locally"; and a single blob "doesn't lend itself to mechanical checks ... so drift is inevitable".
- **Enforcement.**
  - Custom linters and structural tests for the layer rule and for "taste invariants" (structured logging, naming of schemas and types, file size limits). "Because the lints are custom, we write the error messages to inject remediation instructions into agent context." So a lint failure also teaches the primitive.
  - Linters and CI jobs check that the knowledge base is current, cross-linked and well structured.
  - Sweeps: "a set of background Codex tasks that scan for deviations, update quality grades, and open targeted refactoring pull requests. Most of these can be reviewed in under a minute and automerged." They call it "garbage collection". A "doc-gardening" agent opens fix-up PRs for stale docs.
  - Promotion path: "Review comments, refactoring pull requests, and user-facing bugs are captured as documentation updates or encoded directly into tooling. When documentation falls short, we promote the rule into code."
- **Evidence.** One team, self-reported: the manual Friday cleanup (20% of time) was replaced by the recurring agent process; it "worked well up through internal launch".
- **What transfers.** This is the closest published match to a supervisor who does not read code. (a) Lint messages written as agent remediation instructions. (b) Agent-run deviation scans on a cadence, opening small PRs. (c) A per-area quality grade document that the sweep updates, so the supervisor reads grades, not code. (d) A promotion ladder: review comment → doc → lint.

- **Addendum (Pragmatic Engineer, "OpenAI's agentic software factory").** Free part only (paywalled after it). OpenAI "has moved all its documentation inside of the source code". Review uses several agents "each with a 'domain specialist' configuration". "Code changes are classified by risk": high risk gets more AI reviews or a human; areas can opt in to an agent that "will auto-approve low risk PRs". Source: https://newsletter.pragmaticengineer.com/p/openai-software-factory.

### F6. Fitness functions and architecture tests — the mechanical form of "primitives only"

- **Definition.** Ford, Parsons, Kua (Sadalage), *Building Evolutionary Architectures*, ch. 2: an architectural fitness function "provides an objective integrity assessment of some architectural characteristic(s)". Atomic ones test one aspect (example: no circular dependencies). Source: https://oreilly.com/library/view/building-evolutionary-architectures/9781491986356/ch02.html (definition confirmed through search snippets; full chapter is behind a paywall, not read).
- **ArchUnit (Java).** Rules are unit tests (`classes().should()...`). The feature most relevant to heresies is **`FreezingArchRule`**: "recording all existing violations to a ViolationStore. Consecutive runs will then only report new violations and ignore known violations. If violations are fixed, FreezingArchRule will automatically reduce the known stored violations to prevent any regression." The store is plain text files in version control, "to continuously track the progress". Source: https://www.archunit.org/userguide/html/000_Index.html §8.6.
- **dependency-cruiser (JS/TS).** Each forbidden rule is JSON with `name`, `comment` (the human reason), `severity`, `from`, `to`. Example: "no-inter-ubc: Don't allow relations between business components". `--ignore-known` reads a baseline file `.dependency-cruiser-known-violations.json`, so only new violations fail. Sources: https://github.com/sverweij/dependency-cruiser/blob/main/doc/rules-reference.md, https://github.com/sverweij/dependency-cruiser/blob/main/doc/cli.md.
- **eslint-plugin-boundaries.** Classifies files into element types (layers) and enforces which types may import which ("boundaries/dependencies"). Source: https://github.com/javierbrea/eslint-plugin-boundaries.
- **ESLint `no-restricted-imports` / `no-restricted-syntax`.** Each restricted path takes a `message`, for example "Please use import-bar instead." The message names the primitive to use. Source: https://github.com/eslint/eslint/blob/main/docs/src/rules/no-restricted-imports.md.
- **Evidence.** These are mature tools with wide use; no controlled study of their effect on agent drift was found. The OpenAI team (F5) reports custom linters and structural tests as the prerequisite that "allows speed without decay or architectural drift".
- **What transfers.** (a) Each heresy, once found, becomes a forbidden rule with a `comment`/`message` that names the primitive to use instead. (b) The **ratchet** (freeze or baseline file): legacy violations are listed in a committed file; new ones fail; the count can only go down. This stops spread at once without a big-bang cleanup, and the baseline count is a number a non-coding supervisor can watch. (c) The rule file is itself the machine-readable heresy list.

### F7. Golden paths / paved roads (Spotify, Netflix) — primitives as a supported default, not a rule

- **What it is.** Spotify: the Golden Path is "the 'opinionated and supported' path to 'build something'" (backend service, website, data pipeline). Before it, finding how to do something meant asking a colleague: "rumour-driven development", which "simply wasn't scalable". Source: https://engineering.atspotify.com/2020/08/how-we-use-golden-paths-to-solve-fragmentation-in-our-software-ecosystem. Netflix calls the same idea the "Paved Road" (https://www.redhat.com/en/blog/designing-golden-paths, secondary).
- **Form.** One step-by-step tutorial per discipline, written as docs-like-code (TechDocs). The "blessed" tools show in the Explore section of Backstage. Software Templates generate a new project skeleton from the path. Source: https://backstage.spotify.com/learn/onboarding-software-to-backstage/11-spotify-templates.
- **Enforcement.** None, by design. Engineers may "leave the Golden Path and do your own thing, but then you will not have the same support." The incentive is support, not a gate.
- **Evidence.** Weak: "by most accounts" the tutorials "had great success" and are Spotify's "most read and most used technical documentation". No measure of fragmentation.
- **What transfers.** The template is the strongest seed of primitives: a new feature starts from a generator that already uses the primitives (Van Eyck's "seed the new app with exemplars"). But the opt-out model does not transfer to agents: an agent has no reason to value "support". For agents, the path must be backed by a check (F5, F6). "Rumour-driven development" is the human form of a heresy: knowledge that travels by copy, not from a source.

### F8. Design-system enforcement — token-only lint with one doc page per rule

- **GitHub Primer.** `@primer/stylelint-config` rule `primer/colors` "enforces the use of Primer color system variables for `color` and `background-color`"; sibling rules cover spacing, typography, borders, box-shadow. Source: https://github.com/primer/stylelint-config/blob/main/plugins/README.md. `eslint-plugin-primer-react` has `no-deprecated-*` rules (components, props, entrypoints, Octicons) and `use-deprecated-from-deprecated`: they move code off old primitives. Source: https://github.com/primer/eslint-plugin-primer-react/tree/main/src/rules. Primer's token spec tells authors to never use raw values (hex, px) and to use semantic tokens such as `bg.default`. Source: https://unpkg.com/@primer/primitives@11.10.0/DESIGN_TOKENS_SPEC.md.
- **Shopify Polaris.** `stylelint-polaris` is a "Collection of Stylelint configs and rules that promote Polaris Design System adoption and coverage". Rules are grouped by category (color, border, layout, motion, media-queries, conventions, legacy). Each rule has its own doc page, and the shared preamble says "Use [the Polaris resource] instead of custom styles". Sources: https://github.com/Shopify/polaris/tree/main/stylelint-polaris, https://github.com/Shopify/polaris/tree/main/polaris.shopify.com/content/tools/stylelint-polaris/rules, https://polaris.shopify.com/tools/stylelint-polaris.
- **Evidence.** Wide production use at GitHub and Shopify. No public measure found.
- **What transfers.** (a) A *category* of disallowed raw values per primitive (not a list of single bad strings) catches new variants of the same heresy. (b) A `legacy` category plus `no-deprecated-*` rules give a named path off an old primitive. (c) One doc page per rule, linked from the lint message, so the agent that hits the error reads the right primitive. (d) A live gallery page (`/design-system`) is a discoverable exemplar that a non-coding supervisor can also look at.

### F9. Agent instruction files that point at exemplars (AGENTS.md, Cursor rules, Claude Code rules)

- **Cursor rules (vendor docs).** Rules are `.mdc` files in `.cursor/rules` with `description`, `globs`, `alwaysApply`. Guidance: "Provide concrete examples or referenced files"; "Reference files instead of copying their contents. This keeps rules short and prevents them from becoming stale as code changes. Agent reads a referenced file when it needs it, so tell it what to look for there"; avoid "Duplicating what's already in your codebase: Point to canonical examples instead of copying code"; avoid "Copying entire style guides: Use a linter instead". A mention such as `@migration-template.sql` "tells Agent where to look". Source: https://cursor.com/docs/context/rules.
- **AGENTS.md (open format).** "Agents automatically read the nearest file in the directory tree, so the closest one takes precedence". "At time of writing the main OpenAI repo has 88 AGENTS.md files." Source: https://agents.md/.
- **Claude Code (vendor docs).** Subdirectory `CLAUDE.md` files "load on demand" when Claude reads or edits a file there. `.claude/rules/*.md` with `paths:` frontmatter load only for matching files. Target "under 200 lines per CLAUDE.md file. Longer files consume more context and reduce adherence." "If two instructions contradict each other, Claude may pick one arbitrarily." Source: https://code.claude.com/docs/en/memory.
- **What transfers.** Put each primitive's rule next to the code it governs (path-scoped), with a pointer to one canonical exemplar file and the thing to look for in it. Do not copy code into the rule; the exemplar stays true because it is real code that tests run. A pointer can go stale (the exemplar is renamed or itself drifts), so the pointer needs a check — Dodds' map check (F3) verifies that every path exists.

### F10. Uber uReview — an LLM reviewer for the primitives that lint cannot see

- **What it is.** Uber's GenAI code reviewer. It analyses "over 90% of the weekly ~65,000 diffs". "Engineers who interact with the tool mark 75% of its comments as useful, and we see over 65% of its posted comments addressed." Source: https://www.uber.com/blog/ureview/.
- **Form of the list.** "The Best Practices Assistant enforces Uber-specific coding conventions by referencing a shared registry of style rules." Public example of the registry kind: the Uber Go style guide, https://github.com/uber-go/guide/blob/master/style.md.
- **Enforcement split (the key point).** "For simple or syntactic patterns, linters are accurate, reliable, and cheap—we should continue using them. However, some properties are hard to check with linters." Example: the style guide says to use the `time` library for time operations, but "one needs some semantic code understanding to know that a certain integer variable represents time, and LLMs perform far better in these cases. So, best practices that aren't checkable by linters are often a great fit for LLMs."
- **Evidence and its limits.** Measured: usefulness rate and address rate above. "Readability nits ... and stylistic issues consistently received poor ratings. In contrast, correctness bugs, missing error handling, and coding best-practice violations—especially when paired with examples or links to internal docs—scored well." A second-pass grader prompt scores each comment, and a category classifier suppresses low-value categories. Limit: "uReview today only has access to the code ... it can't correctly assess ... the system design."
- **What transfers.** A two-tier check: lint for syntactic heresies; an LLM review criterion for semantic ones ("this integer is a time"), each criterion tied to one registry entry and linked to an exemplar or doc. Measure each criterion's address rate and drop the ones that produce noise.

### F11. Epic Stack (Dodds' starter) — decision records and one glob-scoped anti-pattern rule

- **Form.** `docs/decisions/` holds 49 numbered decision records plus a template (`000-template.md` ... e.g. `001-typescript-only.md`, `003-sqlite.md`). The README: "Decisions in here are never final", but they show "why certain decisions were made". `.cursor/rules/avoid-use-effect.mdc` is one rule, scoped by `globs: *.tsx,*.jsx`, that names the anti-pattern (`useEffect`), lists the primitives to use instead ("ref callbacks, event handlers with `flushSync`, css, `useSyncExternalStore`"), and gives a "✅ Good" code example. Source: https://github.com/epicweb-dev/epic-stack (`docs/decisions/README.md`, `.cursor/rules/avoid-use-effect.mdc`).
- **What transfers.** A heresy rule in three parts: the bad pattern by name, the primitive(s) to use instead, and one good example. Decision records hold the "no" so that agents do not re-propose a rejected option.

### F12. Addendum to the baseline — Van Eyck's review criteria and #2197's factory

- `software-factory-demo/.agents/skills/pr-review/SKILL.md` declares review criteria as tagged lines: `[architecture-violation] if the outlined architecture.md is not followed, such as including business logic in controller endpoints or routes.` Other tags: `[completeness-check]`, `[consistency-type-file]`, `[naming-types]`. The reviewer reports only violations, and ends with "Checked: <categories>". Each tag has a worked example that links the file. `app/CLAUDE.md` tells the agent: "read `frontend/src/ui/README.md` before any frontend work". The reviewer runs **once** (single round), static only (`.agents/FACTORY.md`). Source: https://github.com/jovaneyck/software-factory-demo (local clone, read 2026-10-19). Note: sweeps are not automated in the repo; Van Eyck describes them as his own manual pass.
- `super-simple-software-factory` (README only, in the local clone; its mechanics belong to #2197) declares no code primitives. Its "primitive" is the orchestration phase ("three lanes, one primitive"). Its `adw_quality` lane is "lint, typecheck, build, no agents at all". So it polices heresies only through whatever lint the target repo already has.

## Ranked synthesis — the forms most worth copying

Context: a repo whose supervisor does not read code. So the list must be machine-checkable, and the sweep must be agent-run, and the supervisor must see a number or label, not a diff.

1. **Lint and architecture rules whose error message names the primitive to use (with a ratchet for old violations).** OpenAI writes custom lint messages "to inject remediation instructions into agent context" (https://openai.com/index/harness-engineering/). ESLint `no-restricted-imports` `message`, dependency-cruiser `comment`, Polaris one-doc-page-per-rule do the same (F6, F8). ArchUnit `FreezingArchRule` and dependency-cruiser `--ignore-known` freeze old violations so only new ones fail, and the count only goes down (F6). Why first: it is the only form that stops spread *at write time*, deterministically, and it teaches the agent at the moment of the error. The baseline count is a number the supervisor can track.
2. **A short, validated primitives map that classifies each change by risk.** Kody's `primitives.yaml` with `code:` roots and `docs:` links; a check that every path exists and every summary is one line; a classifier that labels each PR `composes` / `extends` / `adds` from its paths (F3; https://github.com/kentcdodds/kcd-skills, https://github.com/kody-hq/kody). OpenAI uses risk classes for review and auto-approval (https://newsletter.pragmaticengineer.com/p/openai-software-factory). Why: it makes primitives discoverable (Dodds: "good and discoverable primitives") and gives the supervisor a reviewable label — "this PR adds a primitive" — instead of a diff.
3. **Scheduled agent sweeps that open small PRs and update a quality grade.** OpenAI: "background Codex tasks that scan for deviations, update quality grades, and open targeted refactoring pull requests", which replaced a 20%-of-the-week manual cleanup (F5). Dodds: daily docs-freshness, friction sweep, weekly legacy reaper, auto-merge only low/medium risk with green CI (F3). Yegge: review sweep files bugs, fix sweep closes them, repeat until only nitpicks (F1). Why: this is the agent-run form of Van Eyck's manual sweep, and the grade document is what the supervisor reads.
4. **Named heresies in the priming, each with the principle it violates, plus a test that keeps the section present.** Yegge: "capture your guiding principles in the agent priming", then correct by pointing at the violated principle; Gas Town tests that `IDLE POLECAT HERESY` stays in the generated CLAUDE.md (F1). Epic Stack's rule shape: bad pattern, primitive instead, one good example (F11). Scope each rule to the paths it governs (Stripe, Cursor, Claude Code, F2, F9). Why: heresies are wrong *beliefs* and spread through docs and comments, which lint does not read; a named entry lets any agent cite it. Caveat: Gas Town's own idle-polecat doctrine later changed, so each entry needs an owner and a re-check.
5. **An LLM review criterion per semantic primitive that lint cannot express.** Uber uReview: linters for syntactic patterns, LLMs for semantic ones such as "this integer is a time"; comments that cite "examples or links to internal docs" score well; usefulness above 75% measured (F10). Van Eyck's tagged `[architecture-violation]` criteria are the small form (F12). Why fifth: it is probabilistic and costs tokens per PR, so it should cover only what rank 1 cannot, and each criterion should be measured and pruned.

Evidence caveat: no study isolates whether agents copy a bad pattern from neighbouring files of the same repo. The supporting data are GitClear's rise in cloned lines (8.3% → 12.3%, 2021-2024), Dinh et al.'s >50% pass-rate drop from one bug in context, and first-party practitioner reports (OpenAI: "Codex replicates patterns that already exist in the repository—even uneven or suboptimal ones"). Gloaguen et al. show that context files are followed but do not raise success on their own; so instructions should carry only the repo's non-standard ways, and checks should carry the weight (F4).
