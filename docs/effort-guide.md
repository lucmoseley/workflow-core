# Claude Model & Effort Guide

v2.31 · 29 September 2026 · **Sole authority on model and effort** (mantahostels#831, which ruled every other surface down to a pointer) — every other surface carries a pointer, never a second statement of the rule. Read it before choosing a model or an effort level for non-trivial work.

---

## The standing default

**Opus 5.5 · medium**, and it needs no per-session action: `~/.claude/settings.json` carries `"model": "claude-opus-5-5[1m]"` and `"modelSettings": {"claude-opus-5-5": {"effortLevel": "medium"}}`. The effort is set per model because Opus 5.5 ignores a top-level `effortLevel` (§Effort). The model is the full id, not the `opus[1m]` alias, so that the next alias move is an edit to this guide rather than a silent change (#353, which pinned it). Medium is the measured default (mantahostels#828, which established what Opus 5 and Fable 5 are each for); an unclassified session must get the safe model, not the cheap one (mantahostels#1088, which fixed where the Sonnet bound sits). Departures are named — a launch flag, a card code, a subagent pin — and everything unnamed runs the default.

There are four axes, and they answer different questions. **Model** and **effort** are fixed when a session launches, before it has read a word of the ticket. **Surface** (Code / Chat's Research toggle / Cowork / Design) is chosen per piece of work. **Ultrareview** is a spending decision the founder makes when a session asks.

## Burn mode — Sonnet up to Opus, Opus effort up to high, on one switch

**`scripts/burn-mode.sh on`** spends allowance on purpose: Sonnet work runs on Opus 5.5, and Opus 5.5 runs at `high` rather than `medium`. Opus is **not** moved up to Fable — Fable costs about 2.0× Opus 5.5 on this repo's token mix and scores lower on every published axis (#351, which settled the Opus 5.5 default, effort table and burn mode; #355, which reworked it). The code reviewer is untouched: its dispatch names `opus`, and its agent definition's `effort: high` outranks the per-model setting (§Code review's model). `off` restores the standing default above; `status` reports. The `burn-mode` skill wraps the script. **Off is the standing state**, and the routing below is written for it.

Three things move, through one table (`scripts/lib/burn-mode.js`), and they apply at different moments:

- **Every `Agent` dispatch, at once.** `scripts/lib/dispatch-rewrite.js` rewrites the call's `model` field `sonnet` → `opus` and says so in the session's context. `opus`, `fable`, `haiku`, a fork and a dispatch naming no model are left alone; the last inherits the session's model.
- **Every `scripts/dispatch-sessions.sh` launch, at once.** A Sonnet spelling launches as `claude-opus-5-5[1m]`, with no advisor; an Opus spelling launches as written. The advisor is not remapped — nothing it would attach to survives the remap. A spelling the table does not know launches as written, and the launcher says so per member.
- **Opus 5.5's effort, at the next session start.** The script writes `modelSettings["claude-opus-5-5"].effortLevel: "high"` in every plan's `settings.json` — `~/.claude`, `~/.claude2` and `~/.claude3` are one machine — recording what each held so `off` restores it rather than assuming the standing default; a plan that had no key has it removed again. It never touches `model`. A plan whose `settings.json` is a symlink to another's is one file, recorded and written once (#187, which found the three-paths-one-file walk restoring the burn value over the real prior). Where the record is gone — the marker lost between the two calls, or a plan added since `on` — `off` still reverts any plan reading `high` to `medium` and leaves a plan on anything else alone, and it **exits 1 naming any plan still at `high` when it finishes** (#126). Claude Code reads that key only at startup, so a running session keeps its effort; **a new session's subagents inherit it too**, which is intended — all but one whose agent definition sets `effort:` itself, the code reviewer (§Effort). The warm-spare hazard in §Which model to launch each session on applies unchanged. `scripts/check-user-settings-drift.js` reports the effort difference against the settings snapshot (`userSettingsSnapshotPath` in `.claude/workflow-core.json`, else `docs/claude-user-settings.md`) while burn mode is on — expected, and gone after `off`.

**What it does not reach:** a session already running, a `claude --model …` or `--effort …` typed by hand or launched from the agents view, `CLAUDE_CODE_EFFORT_LEVEL`, which outranks settings, and a spare pre-booted before the switch — each keeps what it was given.

**The state is a marker, `~/.claude/.burn-mode` — one per machine, and the same scope as the `settings.json` half it gates, so an `off` run in any checkout ends burn mode everywhere (#127).**

## Model ids and prices

| Alias | Full id | Price /Mtok in–out | Use |
|---|---|---|---|
| `opus` | `claude-opus-5-5` | $4 / $20; cache read $0.20 | The default. The alias has resolved to Opus 5.5 since CLI 2.1.280. |
| `sonnet` | `claude-sonnet-5-5` | $2 / $10; cache read $0.20 | `/pick-next`, the one session kind named below. $2/$10 is **permanent** — the 1 September 2026 reversion to $3/$15 was cancelled on 10 August 2026 (mantahostels#1124, which priced the metered spillover routes). |
| `fable` | `claude-fable-5-1` | $10 / $50 | Nothing standing — see §Code review's model. |
| `haiku` | `claude-haiku-4-5-20251001` | $1 / $5 | Nothing standing. |
| `opusplan` | resolves to `sonnet` outside plan mode | as `sonnet` | Interactive terminal sessions only — it is inert in a background one, and `scripts/dispatch-sessions.sh` treats it as a Sonnet spelling. See §Claude Code specifics. |

A `[1m]` suffix on any alias selects the 1M-context variant. `sonnet` resolves to Sonnet 5.5 here, server-side, at launch and at an `Agent` dispatch alike — probed 29 Sep 2026 on CLI 2.1.284; it was Sonnet 5 through 28 Sep (mantahostels#1112). Sonnet 5.5 refuses a Sonnet 5, Opus 4.8 or Opus 4.7 advisor; `--advisor opus` reaches Opus 5.5, which it accepts. The binary's own fallback is `claude-sonnet-4-6`, at different pricing, so re-check after a catalogue change.

Sonnet is half Opus 5.5's price on input, output and cache writes but the same on a cache read, and cache reads are most of this repo's cost — so on this repo's token mix **Sonnet is about 0.73× Opus 5.5**, and routing a session down pays only while fewer than about **27%** of routed sessions need a full Opus redo (#366, re-priced at #1183). Derivation: 15,804 Opus 5.5 requests in workflow-core and fantasy-books, 24–26 Sep 2026, cost 46.6% cache read, 37.5% cache write, 15.9% output and 0.0% fresh input at Opus 5.5 prices, each cache write at its own TTL's price — main sessions write 1-hour cache ($8/M), subagents 5-minute ($5/M); Sonnet pays the same on the first and half on the rest, 0.466 + (0.375 + 0.159) ÷ 2 ≈ 0.73. #366's 0.77 priced every write at the 5-minute rate. Routing `/implement` down is reopened only at ≤0.60×, which needs cache read to fall to about a fifth of cost. Sonnet's tokenizer still spends ~1.0–1.35× more tokens per prompt than its predecessor, so the effective gap is narrower still.

## Effort

`low` / `medium` / `high` / `xhigh` / `max`, all five reaching Opus 5.5, Sonnet 5.5 and Fable 5 as well as Opus 5 — but **`max` is not accepted in a settings file**, so it can only arrive on the launch flag or the environment variable. Effort moves **all** tokens in a response — text, tool calls and thinking — so a cut buys fewer tool calls as well as shorter reasoning, and never a reliable length cap.

**Effort binds per launched session, and per dispatch through an agent definition.** At launch the lever is `claude --effort <level>` (or `CLAUDE_CODE_EFFORT_LEVEL`, which takes precedence over settings). At a dispatch it is a `.claude/agents/<type>.md` definition's `effort:` frontmatter, which reaches a subagent the `Agent` tool spawns even when the call also names `model` — probed on CLI 2.1.282 (#350) and re-verified here on 2.1.283 (#363); the code reviewer is its one standing use. Three routes do not work and must not be reached for: a skill's `effort:` frontmatter has no runtime effect (claude-code issue #69267), `claude -p --agent` ignores a definition's (claude-code #82259), and **`/effort` mutates *global* `settings.json`** (claude-code #66402) — on a machine running ~9 concurrent sessions that moves every neighbour mid-run.

⚠ **Opus 5.5 ignores a top-level `effortLevel` in user settings, so its effort is set under `modelSettings["claude-opus-5-5"]`.** Without a per-model level, `/effort`, `--effort` or `CLAUDE_CODE_EFFORT_LEVEL`, it starts at its own default, which is `medium` (code.claude.com/docs/en/model-config.md; [docs/research/opus-5-5-harness-mechanics.md](https://github.com/lucmoseley/workflow-core-tracker/blob/0a69e0d4be03/docs/research/opus-5-5-harness-mechanics.md) §4). The top-level key still applies to Opus 5, Fable 5.1 and earlier models. **The first-run effort hold is gone for Opus 4.7, Opus 4.8 and Fable 5** since CLI 2.1.280; no source says whether Fable 5.1 ever carried it (the 28 Aug 2026 incident is on mantahostels#678). If sessions ever report an effort the settings do not name, check for a missing per-model key before the settings' top-level value.

**Effort is the only thinking control, and there is no per-task one.** Opus 5.5, Opus 5, Sonnet 5.5 and Fable 5 use adaptive thinking rather than the `thinking.type: "enabled"` parameter, so `MAX_THINKING_TOKENS` is ignored. Not worth chasing anyway: thinking is **14.6% of spend, ±2.8pp** (mantahostels#1084, the thinking-share measurement) and **45.5% of turns emit none at all**. The `/config` disable is not an escape — like `/effort` it writes *global* settings and moves every neighbour, it is unavailable on Fable 5, and on Opus 5 it returns a 400 at `xhigh` or `max`.

**No low-effort routing rule.** mantahostels#1084 asked whether checkable work should run at `low` and be re-run at `high` on failure, and answered **no**: the trigger never fires, because the measured failures passed their own in-session gate (mantahostels#1108, the twelve-session measurement behind it). The signature to watch for is **under-disclosure** — an `**Outstanding:**` line omitting the defect — not incompetence. Whether `low` should be adopted *flat*, with no trigger, turns on mantahostels#1214, the missing control arm, and is not decided.

## Which model to launch each session on

**Plain Opus — the standing Opus 5.5 · medium above, launched with no model flag — is the live default for every session kind** — nothing reaches Sonnet automatically, `opusplan` being inert here — so this is an inclusion list of the kinds that move *down*, not an exception list. **The bound is blast radius, not difficulty:** Sonnet where a mistake would be **visible and cheap to reverse**, however hard the work is — a hard ticket whose errors surface immediately is a better Sonnet candidate than an easy one whose errors hide. The operative test is **whether any check reads the substance of what the session writes**, and almost nothing in this repo does, so a kind moves down on a *human* approval step or a structural gate, never on a content gate. Apply that test to any kind not in the table (mantahostels#1093, which decided the list).

| Launch as | Model | The check that catches a Sonnet error |
|---|---|---|
| `/implement` | **plain Opus** | Not routed down since #354: Sonnet costs ~0.73× Opus 5.5 here (§Model ids and prices) |
| `/pick-next` | Sonnet | `guard-selection-sum.js` at Stop — the repo's only content-shaped gate. A bad selection is visible in the dispatch message and costs one re-run |
| `/to-tickets` | **plain Opus** | Not routed down since #1920: the founder check that justified Sonnet does not happen while the refill loop launches it |
| `/triage` | **plain Opus** | Not routed down since #1920: the founder check that justified Sonnet does not happen while the refill loop launches it |
| `/card-close` | The host session's model (standalone: **plain Opus**, #360) | Blocks same-session on `check-roadmap-pair.js`, `check-roadmap-valid.js`, `check-digest-version.js` and the `guard-issue-close` core; stops and asks when a card id doesn't resolve |
| `roadmap-edit` | The host session's model (standalone: **plain Opus**) | `validate.js` in-loop, plus the roadmap and digest gates at commit; an edit to phase, `needs:` or card ordering lands as a validator WARNING, which passes |
| `/wayfinder` | **plain Opus** | None. Tracker-only, and the three issue guards check form alone |
| `/to-spec` | **plain Opus** | None. A wrong acceptance criterion propagates into every ticket written from it |
| `/code-review` | **plain Opus** | None — a *missed* finding is by definition uncaught. Already automatic via the subagent pin below |
| `manual-sync` | **plain Opus** | None. Freshness is a timestamp check; nothing tests whether the synthesis is true |
| `concision-pass` | **plain Opus** | None for the failure that matters — nothing verifies that a deleted line was redundant, and no cut has yet been shown to have removed a load-bearing line either way (mantahostels#2649, mantahostels#2674) |
| `research` | **plain Opus** | None. Nothing validates a citation |
| ad-hoc / untyped | **plain Opus** | Mechanical gates only, and none of a typed skill's discipline |

**`scripts/launch.sh` binds a model to a command name, from `scripts/lib/launch-models.sh`** — the one copy of this table that code reads, which `scripts/lib/launch-models.test.ts` holds this table to (#361). A Sonnet-arm kind is launched `--model sonnet --advisor opus` via `scripts/dispatch-sessions.sh`; everything else launches on plain Opus. Carve-outs escalate to Opus and **never** de-escalate, so failing to classify is always safe.

⚠ **The no-flag path has no defence against `/model` rewriting the default.** An interactive `/model` in any session writes `~/.claude/settings.json`'s `model` key machine-wide — *"saved as your default for new sessions"* — so one session deliberately launched off-default re-points every later no-flag session, `scripts/dispatch-sessions.sh`'s among them. Launching *with* `--model` persists nothing and is not the vector (mantahostels#678, which measured it).

⚠ **And correcting the default does not reach a warm spare.** The daemon pre-boots spare processes (`claude bg-spare`) and hands one to a no-flag job on claim, so the session runs on whatever `settings.json` said at *spare boot* rather than at dispatch. After fixing a model default, kill or claim the warm spares before trusting it. A claimed spare is told from an idle one by `readlink /proc/<pid>/cwd` — an idle one sits in the daemon spare directory — never by its argv, which still reads `bg-spare` for the life of the process (mantahostels#678). **The agents view's launch line is the same trap**: it creates the next session about 3 s after each submit, claiming a spare then, so whatever is typed there next runs on the settings that spare booted on. After switching, launch one throwaway session from the agents view (`/usage` serves) so the next is created fresh (#568).

**Accepted residual: this table binds at launch, so a skill invoked *inside* another session runs at that session's model** — `/card-close` and `roadmap-edit` run on their host session's model, usually plain Opus, which errs the safe way.

## Which model each subagent dispatch runs on

**A dispatch that names a model names `sonnet` unless it is one of the two carve-outs below** (mantahostels#1417, which routed fan-out down; mantahostels#1410 and `mantahostels:docs/research/subagent-model-split.md` hold the measurement; #513, which retired the guard that enforced it). A dispatch naming none inherits the parent's model — Opus in an Opus session — which forgoes the routing saving but is not a fault.

**Two carve-outs off Sonnet — both failures are invisible after the fact:**

- **Code review — `subagent_type: "code-reviewer"` (`"workflow-core:code-reviewer"` in an adopter), `model: "opus"`, at high effort.** A *missed* finding is by definition uncaught, and Opus 5.5 high recalled the most on #349's bake-off (#350, which ruled it). §Code review's model has the figures and the lockstep edits any further change needs.
- **Legal and regulatory research — `model: "opus"`** — OTA terms, UU PDP, the database right. Nothing validates a citation, and a fabricated one reads exactly like a real one.

**Everything else is Sonnet**: concision passes, verification and audit, doc-map and propagation mechanics, sweeps/greps/file reads, measurement and cost analysis — **and the unclassified remainder**, which the founder took the tier with in. That remainder has **no mechanical check** — it was bucketed by a keyword heuristic, so judgement-heavy work is certainly hiding in it. Carving it out would cut the saving from about 3.9pp to 2.6pp.

**The concision pass's own fresh reader is a *measured* Sonnet pin, not just that remainder's default** (mantahostels#2643, approved by the founder). Fable 5.1 was the option refused: it has **zero** production `.claude/skills/concision-pass/SKILL.md` §3 dispatches, so the record holds no evidence about it at all. **The literal pin lives at three sites** — §3 itself, `scripts/inject-tracker-docs.sh`'s `closing_steps` and `scripts/concision-backstop.sh`'s code-signal nag — **and `scripts/inject-tracker-docs.test.ts` asserts all three agree and read `sonnet`**, counting each file's bare `model:` literals so that a fourth pin added in a new sentence is caught too.

⚠ **The ~3.9-percentage-point saving is conditional and must never be restated as a fact.** mantahostels#1410 measured 5.20pp of all spend, 3.48pp without the unclassified remainder, at Opus 5 prices; #354 rescaled them to about 3.9pp and 2.6pp at Opus 5.5 prices on the subagent cost mix — 42.2% cache write, 34.7% cache read, 23.0% output, Opus 5 era ([docs/research/burn-measurement-method-correction.md](https://github.com/lucmoseley/workflow-core-tracker/blob/0a69e0d4be03/docs/research/burn-measurement-method-correction.md)) — where Opus 5.5 is 0.660× Opus 5 and Sonnet about 0.61× Opus 5.5: the 8.67% of all spend routed saves 8.67 × (0.660 − 0.40) ÷ 0.576 ≈ 3.9pp, 0.576 being Opus 5.5 ÷ Opus 5 on the Opus 5-era all-spend mix (0.561 × 0.4 + 0.439 × 0.8) of all spend at Opus 5.5 prices. Rescaled, not re-measured. It holds only if the weekly allowance is metered in cost-equivalent units, which `mantahostels:docs/research/weekly-meter-model-weighting.md` puts at **42% (25–60%)** — Anthropic publishes no unit and no multiplier for the subscription window. A founder `/usage` plan-bar reading settles it and has not been taken. The routing rule is worth keeping either way.

**`model:` binds** — 398/398 real dispatches matched the model requested (95%, 90–98%), so claude-code #82259, which ignores a definition's *effort* under `claude -p --agent`, does not reach this. Two routes it does not cover: **`subagent_type: "fork"` ignores a `model` override entirely and always inherits**, so a fork of an Opus session is an Opus dispatch with no route down; and a **vendored** skill that dispatches — `research` is the live one — carries no pin, a local edit there being lost on re-vendor with no injector covering it, so the session naming the model at the call is the only route.

**Every subagent dispatch here runs on the 1M-context variant, never the 200K default** — measured (mantahostels#1866) over 806 `claude-sonnet-5` subagent transcripts: 13 (1.6%) peaked past 167,000 uncompacted tokens, 3 (0.4%) past 200,000, one holding 291,172 tokens of `cache_read_input_tokens` in a single turn, impossible inside an actual 200K window. **The `Agent` tool's `model` field takes only the bare four aliases** (`opus`/`sonnet`/`haiku`/`fable`) — no `[1m]` spelling is accepted at a dispatch (mantahostels#1866). The 1M window is the harness's own subagent default; it is not something a session selects.

## Card codes and dispatch codes — two vocabularies

**Card codes** are the roadmap's `m` field, and they mark only a card's departure from the default:

- `"max"` — a genuinely one-way call, where a mistake cannot be walked back.
- `"—"` — **no Claude session works this card at all**, the exact equivalent of `takes:human` on that card's own issue (the unparented one titled `<card-id> — <title>`). A `takes:human` *child* under a card with real build work is a different thing and is correct.
- No `m` at all — the Opus 5.5 · medium default. **A decision, reference or admin card that Claude does work carries no `m`; it does not carry `—`.**
- Leg-scoped: `m:[["design","max"]]`, in which a leg with no entry runs the default.

**Dispatch codes** are the harness's own `opus` / `sonnet` / `haiku` / `fable`, passed at an `Agent` call. A call naming none inherits the parent's model, which is fine; where you name one, §Which model each subagent dispatch runs on above says which.

**No tracker label encodes model or effort, and none will** (mantahostels#1173, which considered mirroring the card codes as labels and refused). Model and effort are fixed at launch, before any issue body or label has been read, so a label could only ever inform the human choosing what to launch — which is what an issue body saying so in prose already does. `docs/agents/triage-labels.md` may point here; it must never restate the rule.

## Code review's model

**Code review runs on Opus 5.5 at high, through the `code-reviewer` agent type** (#350, which ruled it). Both axes spawn from a single message carrying two `Agent` calls, `subagent_type: "code-reviewer"`, `model: "opus"` on both. `.claude/agents/code-reviewer.md` sets `model: opus` and `effort: high`; naming `opus` at the call as well is redundant with it and changes nothing. An adopter has only the plugin's copy, which a plugin offers namespaced as `workflow-core:code-reviewer`; `scripts/lib/review-agent-type.sh` hands each dispatch route whichever spelling the host has (#741). Verified in a fresh session (#363); the evidence is #349's bake-off, in which Opus 5.5 high recalled the most for about half Fable's cost.

**A change touching a path its adopter declares sensitive escalates the tier** (spec #1612). **Escalated** adds a third run, focused on the touched areas' declared focus; **mission-critical** — one altering an access rule or money calculation itself — adds a fourth, an attacker. Every run is Opus 5.5 high through the same `code-reviewer` type; no Fable and no second vendor in any tier (#1556). The two briefs, `docs/agents/rules/review-focused-run.txt` and `review-attacker-run.txt`, which `scripts/guard-dispatch.js` (its `inject-review-tier` core) prints, name no model, so a model change still takes only the two edits below.

**A model change here is two lockstep edits**, plus the tests that pin each: `.claude/agents/code-reviewer.md` and `docs/agents/rules/review-dispatch-shape.txt`, which `scripts/guard-dispatch.js` (its `guard-review-rules` core), `scripts/inject-tracker-docs.sh` and `scripts/concision-backstop.sh`'s code-signal nag all print (#1697). `scripts/inject-tracker-docs.test.ts` asserts neither script spells a reviewer pin of its own; nothing ties the definition to the fragment, so it can still drift apart green (mantahostels#1009, the gap this leaves open). That nag gates on `CODE_THRESHOLD=20` changed lines — churn, added **plus** deleted — **a first guess, never measured**.

**Fable has no standing use.** It costs about **2.0× Opus 5.5** on this repo's token mix — its cache read $0.25/M against $0.20/M, its cache writes and output 2.5× (#356) — and it recalled less than Opus 5.5 on review. Two things still bind anything that dispatches it: **the sub-cap** — Fable draws the weekly all-models counter *and* its own weekly sub-cap at ~50% of it, so a workload mostly on Fable exhausts the sub-cap with half the all-models window unspent — and **the alias**: the `Agent` tool takes the bare `fable` only, which resolves to 5.1 from CLI 2.1.257 but to the dearer Fable 5 on an older binary, and a server-side catalogue entry outranks either, so re-check after a catalogue change (mantahostels#1112).

**Where a model pin for a vendored skill goes:** the injector, not the skill file. `.claude/skills/code-review/SKILL.md` is a symlink into the vendored `.agents/skills/` tree, where a local edit is lost on re-vendor. One instance stands behind that pattern, so it is a candidate, not a settled home for every future pin.

## What the allowance is actually spent on — measured

**The allowance is spent re-reading context, not writing output** ([docs/research/allowance-burn-measurement.md](https://github.com/lucmoseley/workflow-core-tracker/blob/0a69e0d4be03/docs/research/allowance-burn-measurement.md), mantahostels#830, with mantahostels#1121's method correction applied). **Price a change by how much standing context it puts in front of how many turns, never by how much a model outputs**: the median turn re-reads **109k** tokens, of which **28.3k** is fixed preamble — base prompt, tool schemas and the always-loaded pool — so a KB added there is re-read ~**79** times a session (mantahostels#1081, which decomposed the per-turn re-read). Subagent fan-out is a cost-*reduction* lever: never tell a session to fan out less. Spend is spread rather than concentrated, so there is no runaway set to fix — **session count and standing context are the only two levers the data exposes**.

**Three 20x Max subscriptions partition rather than pool.** Each carries its own counters, and each boots only once the ones ahead of it are exhausted — **never model them as one pool of triple size**; the second and third are failovers. The plan meters **three** windows per seat and **none is Opus-only**: a 5-hour session window, a **weekly all-models** window, and a **weekly Fable** window at ~50% of it. Opus draws on the all-models window alone, **so that is what binds**. The founder's "both plans empty in ~5 days" figure (mantahostels#829) was measured over two seats in the week of 3 Aug 2026 — [docs/research/time-past-the-ceiling.md](https://github.com/lucmoseley/workflow-core-tracker/blob/0a69e0d4be03/docs/research/time-past-the-ceiling.md) (mantahostels#1125) found blockage fell to zero from 19 Aug and the second seat never hit a limit at all, so it is not a standing runway — and the third seat has no measurement of its own yet. The ceiling in force carries a **+50% promotional uplift** running to **13 September 2026**, when it **steps down to +25% rather than lapsing** — 1.50x base to 1.25x base, a **16.7% cut in headroom** (founder-supplied 1 Sep 2026; the 31 August date it carried before was extended, and `/usage` still displays the superseded `through Aug 31` wording). Budget against today's ceiling, not the step-down. Usage credits are **off**, so nothing bills the card without an explicit opt-in.

⚠ **Two stale claims to recognise on sight.** That an **Opus-only weekly counter** exists on this plan — Anthropic's support article says so, but this account's separately-metered model is **Fable 5** — and, with it, the reading that **Fable spares the scarce counter**. And Anthropic's usage panel, whose attributions are **independent characteristics, not a breakdown**: they overlap and never sum to 100, so none of them answers what dropping the subagent fan-out would save. Every account-level figure here is read off **one account, this machine only**, and a plan or promo change invalidates them silently; every dollar figure is a list-ratio weighting of four token classes, never a bill.

## The fourth axis — what earns an ultrareview

`/code-review ultra` runs a fleet of reviewer agents in a remote sandbox for 5–10 minutes. A session never starts one unasked: when its change meets the test below, it asks you, and on your yes runs `claude ultrareview <base-sha>` from a throwaway worktree at its commit (#1572).

**It does not spend what binds.** Ultra bills usage credits, not the weekly all-models window. **9 lifetime free runs** — 3 per account, three accounts, one-time, non-refreshing, no published expiry — and usage credits are off here, so run 10 needs a deliberate opt-in at $5–25. An aborted or failed run burns one and returns nothing.

**So ration on what ultra buys over the local review, not on how many are left.** The baseline is two Opus 5.5 high axes on this machine. Ultra adds two things and no others: every finding independently reproduced and verified, and a fleet whose combined context exceeds one reviewer's.

**The test — all three:** the diff touches a path the adopter declares sensitive in its `.claude/workflow-core.json`; **and** it is large or cross-cutting enough that one reviewer's context cannot hold it; **and** it touches a path its adopter has declared live — the first and third together being a **live sensitive path**. The session applies it after the local review tiers have returned and their fixes are made, before the shared-tree commit. **Escape clause, yours at the terminal alone:** or the weekly counter is exhausted and a review cannot wait, ultra being the only review that still runs then.

These are **firing conditions at the moment of work, never properties of a card.** Neither a card field nor a tracker label marks them: either would flag a card whose code does not yet exist.

**Mechanics.** Branch mode reviews HEAD against a merge base; this repo commits direct to `main`, so there is none, and the documented fallback — review every tracked file — exceeds ultra's 500-file / 8,000-line ceiling and is refused. So the session commits the change on a local branch in a throwaway worktree, never on shared `main`, and asks you — in a background job by ending on `needs input:`. On your yes it runs `claude ultrareview <base-sha>`, backgrounded, through Bash from a detached throwaway worktree at that commit, `<base-sha>` being the commit the change sits on; the worktree keeps neighbours' uncommitted files out of the upload. That command shows no launch dialog: it starts at once, spending a free run, or billing usage credits where the server would otherwise ask, then prints the findings (CLI 2.1.299's own code, read at #1623). It records `**Ultrareview:** ran <date>, <n> findings, <disposition>` or `**Ultrareview:** declined: <reason>` on the ticket in hand, and lands the change by #290's route. **Fallback**, where the command cannot start from Bash, an auto-mode refusal included: you start `claude` in that worktree and type `/code-review ultra <base-sha>`. Its launch dialog shows scope, remaining free runs and estimated cost **before** the session starts, so read it — an unavailable ultra silently runs an ordinary local review instead, and the dialog is the only way to tell.

**What voids this.** The rationing rests on two premises — 9 lifetime non-refreshing runs, and usage credits off. If either changes, **the rationing goes and only the test survives**, ultra becoming the default review on a declared live sensitive path. The fallback's launch dialog shows the remaining-run count, the headless command showing none; correct this section when it disagrees.

## Choosing the surface — Chat vs Code vs Cowork vs Design

- **Code** — everything that touches the repo: build, tests, migrations, git, CI, and roadmap edits via `roadmap-edit`. Terminal-and-git-native, in the real WSL2 environment. Review diffs via the VS Code extension; keep the terminal for quick ops.
- **Chat** — **one role: hosting the Research toggle.** Strategy, judgement, turn-by-turn contestation, discovery analysis and living-document maintenance (including this guide) all moved to `/grilling` in Code (mantahostels#167, the surface ruling that left Chat this one role). Both skills that ever had a Chat copy — `roadmap-edit` and `interview-analysis` — are repo-canonical only, with no fallback export.
  - **Which research surface — route by source-knowledge.** Chat's **Research toggle** when the source landscape is unknown and needs discovering; **`/research`** when the source is named and needs reading accurately (its findings are posted on the issue); **`last30days`** when the question is what people are saying now.
  - **A Research run crosses back as citations, never a document.** A Code session re-reads the cited sources and writes the file itself — Chat-authored content is reliable on intent and unreliable on fact.
  - **Nothing is pushed the other way.** No synced project knowledge, no uploaded roadmap; context is pasted per run.
- **Cowork** — narrow. Bounded, file-heavy deliverables *outside* the codebase: owner-facing docs assembled from the guides, bulk transcript synthesis (rough trigger: batches >5), photo-asset organisation. Below that, Code with `interview-analysis` is cheaper and lands the findings in the repo. **It can't own the build**: a sandboxed VM with no native git against the host repo and restricted outbound network, so it can edit files but can't commit, fire Husky, self-verify CI or run the dev-server loop. **Scheduled Cowork tasks only run while the machine is awake and Desktop is open** — any unattended recurring job belongs on a GitHub Actions cron.
- **Design** — narrow, and *before* Code, not instead of it. Two charters: (1) **pre-build UI exploration and prototype user-testing** where design risk is real — 2–3 layout directions, the winner turned into a shareable clickable prototype to put in front of backpackers or an anchor hostel with nothing deployed, then handed off to Code (`search-core`, `review-ux`). (2) **Print/visual collateral drafts** — desk cards, stickers, one-pagers — exported to PDF or Canva, then routed to Marisha before anything final (`partner-onboarding`, `in-hostel-mkt`). Not for standard low-design-risk UI, not for copy, not for anything already `done`. **Its metering is the open question** — the help centre says it counts against the plan, at least one write-up says otherwise; verify against Settings → Usage before leaning on it. **One-time setup:** point its design-system import at the repo and `public/brand/` once and every prototype comes out on-brand, with the caveat that the brand device there is still provisional.

Chat, Code and Cowork all draw the same weekly window, so choosing between them is a fit decision, not a saving — except that Cowork's plan-execute-verify loop burns more per task than a Chat turn.

- ⚠ **`/model opusplan` is inert in a background session, and silently.** In 2.1.239's resolver the Opus phase is gated on **`permissionMode === "plan"` and nothing else**, and outside plan mode `opusplan` resolves **byte-identically to plain `sonnet`** (mantahostels#1101; `mantahostels:docs/research/opusplan-plan-mode-gate.md`).   - **Forcing plan mode makes it worse**: with no human to approve the plan and `ExitPlanMode` denied in `~/.claude/settings.json`, the session never leaves — Opus all session with edits blocked.

  - **A subagent inherits the gate, not the model**: `model: inherit` spawned in plan mode gets Opus, spawned outside it gets Sonnet.
  - Each plan-mode toggle is a model switch and starts a fresh cache — ~$0.16 at the measured median context, so noise unless a session toggles repeatedly (mantahostels#1092, which measured the switch).
- **The advisor tool puts the strong model at the decision, not at the phase.** A Sonnet session consults an Opus advisor "before committing to an approach, when stuck on a recurring error, or before declaring a task complete". Toggling it **keeps the prompt cache**, unlike a model switch. Its own read of the conversation is **never cached**, and **no setting caps how often it fires**. Experimental.
  - **Re-priced against real traffic** (mantahostels#1185, `scripts/measure-advisor/scan_advisor.py`, 23–25 Aug window): median **$1.28 a call** at median **52k** context. As a share of the same window's `/implement` spend: **5.7%** observed (45 calls, $60.86 of $1,072.80), **10.8%** at the upper bound where every configured session that fired zero rounds is assumed to have actually fired the median 2 rounds ($115.38 of $1,072.80).
  - **Roughly a quarter of configured sessions never fire it at all, and that population cannot be resolved retrospectively** — 23 of 45 sessions with the advisor configured logged zero rounds in the same sweep. No transcript field distinguishes "ran and had nothing to escalate" from mantahostels#1102's silent-off risk (a disabled feature flag, `DISABLE_TELEMETRY` included).
  - **The per-launch `--advisor` flag is this repo's only route** (mantahostels#1102, which changed how `/implement` launches). It is real but absent from `claude --help`. The alternatives are worse: `advisorModel` in settings attaches an advisor to **every** session including plain-Opus ones and their subagents, and `/advisor` answers *"isn't available in this environment"* in a headless session.
  - **The gate is `CLAUDE_CODE_DISABLE_ADVISOR_TOOL` unset, first-party auth, and the `tengu_sage_compass2` feature flag** — so `DISABLE_TELEMETRY` takes the advisor with it, and `CLAUDE_CODE_ENABLE_EXPERIMENTAL_ADVISOR_TOOL=1` forces it past the flag. It is on here.
  - **Off, it reports nothing at all** — the session runs bare Sonnet with no escalation path. `scripts/dispatch-sessions.sh` reads the flag and warns, but a launched session reports its own advisor nowhere, so a hand-typed launch gets no check.
- **Tests are the actual check**, not effort level: write the failing Vitest test first and let the session self-correct against it. Cheaper and more reliable than re-prompting a stronger model.
- **Context hygiene** — reference files by bare path, never `@` (which injects the whole file plus its CLAUDE.md tree); a new session per unrelated task; keep the always-loaded pool lean and drop unused MCP servers.
