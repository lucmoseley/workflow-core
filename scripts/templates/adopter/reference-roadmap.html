How to read this. Phases are sequence, not calendar — each gates the next. Every card has a kind (its nature) and a state (where it stands). Kind: Action = a task with a Done-when · Decision = a choice to make or record · Reference = a standing rule or fact you apply, never "finished" · Watch-out = a risk or hard constraint to heed. State: Active = in play now · Open = unresolved, needs a call · Parked = deferred to a future trigger · Done = nothing left for you. A card's Needs line names its nearest prerequisites only (green ✓ = satisfied, coral = still blocking) — tap one to jump to it. The On record block captures what's been decided, discovered, or shipped. Filter remaining work with State → Active.

To change a card's state, edit state:"active" in its ITEMS entry ("active" / "open" / "parked" / "done"), then re-open the file. To record an outcome, add or extend its log:"…". To flag a dependency, add needs:["card-id"] using the target's id — the page warns in the browser console if an id is missing or points to a later phase. Granular execution — sub-tasks, assignees, day-to-day — stays in GitHub Issues; this doc tracks kind, state, dependencies and outcomes, not the hour-to-hour. There is deliberately no "in-progress" state: solo, it just becomes a drawer of half-started work, and the active slice already lives in Issues.

The "at a glance" cockpit (Now · Next · Progress) is computed entirely from ITEMS plus one constant, CURRENT_PHASE, at the top of the script. When you finish a phase, bump that one line (0→1…) and the cockpit re-points itself — nothing else to maintain. Now lists the current phase's active work (flagging anything blocked by an unmet prerequisite); Next surfaces the following phase's watch-outs early; Progress shows the state mix and total blocked count. Each card is a launchpad: tap to drop into the matching filtered view below.

The Claude strip at the foot of a card marks only where that card departs from the standing default — most cards carry no strip at all:

An unmarked card runs the default. Max marks a genuinely one-way call — a mistake that can't be walked back. Not a Claude task marks work no Claude session does at all, equivalent to that card's own issue carrying takes:human.
