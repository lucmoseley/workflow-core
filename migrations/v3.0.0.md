# v3.0.0

## What changed

Breaking, action required: `landing` is always on (#5276, spec #5273). It is
no longer a module and cannot be switched off: every session works in its own
worktree and lands through its queue ref, and only the queue lander moves
`main`.

At every session start, a main checkout that is not cut over is cut over by
the session itself, provided no session's working directory is the main
checkout. Otherwise the session-start check fails naming each session that
stands there. The cutover lands any commits the main checkout's `main` holds
that `origin/main` lacks through a queue ref.

The refill loop serves no repo pinned below v3.0.0 whose config lacks
`"landing"`. It names such a repo in its log as not served, and serves it
again once its pin moves to v3.0.0 or later.

Rule ids lose their `-landing` suffix (#5295): `push-cadence`, `ci-status-lag`,
`branch-publish`, `review-ultra-axis` and `unasked-rerun`;
`main-rewind-landing` is now `main-remote-rewind` and
`branch-shared-tree-landing` is `branch-shared-tree-cutover`. The session-start
check `check-landing-switch-on.js` is now `check-main-checkout-cutover.js`,
status id `main-checkout-cutover`.

The core glossary and the doc-map method now ship as core-owned files,
`.claude/workflow-core.glossary.md` and `.claude/workflow-core.doc-map.md`,
rewritten on every upgrade (#5296, spec #5294).

`npm run status` reports the verdict proof's state.

The practice notes ship in the plugin. A session uses the repo's own
`docs/practice/<craft>.md` while it is current, else the plugin's copy.

A `ci` key in `.claude/workflow-core.json` has the upgrade write
`.github/workflows/workflow-core-ci.yml` (#5347): one job on each push to
`main` running the declared `check`, `lint` and `typecheck` commands, the
whole test suite as the lander runs it (`full_test`, else `test`, and the
plugin's pytest runner where Python is routed), the plugin's checks on the
repo's documents and workflows, and Semgrep. Removing the key removes the
workflow.

The code standards base gains §G13: a hot-path program costs no more per call
than its work needs (#5335). A session is handed it the first time it writes
a program a per-tool-call hook entry, a per-commit git hook, the status line
or a dispatcher registry runs, or a hook registration itself.
`.claude/workflow-core.json` takes an optional `polled`, the repo-relative
programs the repo runs every few seconds, default `[]`.

`suites` is no longer a module (#5383). Each rule it switched now follows
its own subject: the `targeted-runs` advice is handed where `commands.test`
has a fresh verdict proof; the suite-queue wait report runs where
`commands.test` is declared; the suite-size drift check runs in
workflow-core alone; and where `.github/workflows/workflow-core-ci.yml` is
committed, the daily repo checks file a red run of it on `main` as one
`ci-red` issue, the upgrade creating that label. With no `commands.test`
declared, the test gate answers no gate.

The browser-profile guard, the practice guard and its craft list
(`docs/practice-crafts.md`) ship as plugin hooks (#5383). The browser guard
derives the Chrome profile from the session's own signed-in account. The
session rules gain four working rules: Leading practice with the practice
gate, removal means gone, no reports to Anthropic and no paid research or
data APIs. Their Machine section is figure-free; a new session-start line
gives the machine's architecture, cores, memory and swap, read live.
