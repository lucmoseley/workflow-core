# v3.0.0

## What changed

Breaking, action required: `landing` is always on (#5276, spec #5273). It is
no longer a module and cannot be switched off: every session works in its own
worktree and lands through its queue ref, and only the queue lander moves
`main`.

At every session start, a main checkout that is not cut over is cut over by
the session itself, provided no session's working directory is the main
checkout. Otherwise the session-start check fails naming each session that
stands there. The cutover lands any commits the main checkout's `main` holds
that `origin/main` lacks through a queue ref.

The refill loop serves no repo pinned below v3.0.0 whose config lacks
`"landing"`. It names such a repo in its log as not served, and serves it
again once its pin moves to v3.0.0 or later.

Rule ids lose their `-landing` suffix (#5295): `push-cadence`, `ci-status-lag`,
`branch-publish`, `review-ultra-axis` and `unasked-rerun`;
`main-rewind-landing` is now `main-remote-rewind` and
`branch-shared-tree-landing` is `branch-shared-tree-cutover`. The session-start
check `check-landing-switch-on.js` is now `check-main-checkout-cutover.js`,
status id `main-checkout-cutover`.

## Manual steps

- [act] Remove `"landing"` from `modules` in `.claude/workflow-core.json`,
      which now warns that it names an unknown module:
      `node -e "const fs=require('node:fs'),f='.claude/workflow-core.json',c=JSON.parse(fs.readFileSync(f,'utf8'));if((c.modules??[]).includes('landing')){c.modules=c.modules.filter((m)=>m!=='landing');fs.writeFileSync(f,JSON.stringify(c,null,'\t')+'\n')}"`.
      `grep -c '"landing"' .claude/workflow-core.json` then prints 0. Run your
      formatter over the file and commit it.

- [act] Delete `push_check` from `commands` in `.claude/workflow-core.json`,
      which now warns that it names an unknown key, and any npm script that
      runs the plugin's `push-check.js`, which no longer ships:
      `node -e "const fs=require('node:fs'),f='.claude/workflow-core.json',c=JSON.parse(fs.readFileSync(f,'utf8'));if(c.commands&&'push_check' in c.commands){delete c.commands.push_check;fs.writeFileSync(f,JSON.stringify(c,null,'\t')+'\n')}"`.
      `grep -c push_check .claude/workflow-core.json` then prints 0, and
      `grep -c push-check package.json` prints 0 once the script is gone.
      Run your formatter over both files and commit them.

- [act] Rename any reference to the old rule ids or check name. List them with
      `git grep -nE 'push-cadence-landing|ci-status-lag-landing|branch-publish-landing|review-ultra-axis-landing|unasked-rerun-landing|main-rewind-landing|branch-shared-tree-landing|landing-switch-on'`,
      and rename each to its new name above. A fragment of your own at
      `docs/agents/rules/<old id>.txt` no longer overrides the plugin's rule
      until you `git mv` it to `<new id>.txt`. The `git grep` then prints
      nothing. Commit the renames.

- [notice] A bare `npm run test:changed` no longer prints whether its run
      is admissible:
      the queue lander's full run gates what reaches `main`.

- [notice] Where the main checkout was never cut over, the next session to
      start with no session standing there cuts it over. Its report names any
      edit left in the main checkout for you to move into a session worktree
      or discard.
