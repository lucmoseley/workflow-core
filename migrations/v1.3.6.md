# v1.3.6

## What changed

`upgrade` now writes the `.gitignore` block ignoring `.claude/tmp/` and
`/private/` that v1.3.5's `init-adopter.js` wrote only for a new repo (workflow-core#773).
The block's markers are now `# workflow-core:begin` and
`# workflow-core:end`; a block `init-adopter.js` wrote under v1.3.5's markers
is rewritten in place, not copied, as is one whose file has CRLF line
endings.

In the shared tree, a command that discards or stashes uncommitted work
across the whole tree is refused, since it takes every neighbour's edits too:
`git reset --hard`/`--merge`/`--keep`, `git checkout .` or `git restore .`,
`git clean -f` with no path, a `git stash` push or save naming no path, a
forced `git checkout` or `git switch`, and a checkout, restore or stash fed
`--pathspec-from-file` or given a bare `-p`. Any form passes in a linked
worktree (workflow-core#768).

`count-guard-fires.js` now counts refusals to move `main` (workflow-core#767).

## Manual steps

- [notice] Added the two lines by hand, as v1.3.5's note asked? The block
      now carries them, so you may delete your own copies.
- [notice] Upgraded to v1.3.5 already? Its note said only a move of `main`
      backwards is refused. A `git reset` in the shared tree naming a commit
      other than `HEAD`, and a forward move of `main`, are refused too; move
      `main` forward with `git merge --ff-only`.
- [notice] Discard your own edits in the shared tree by naming them on the
      command line: `git restore --staged --worktree -- <paths>`,
      `git clean -f -- <paths>`, `git stash push -- <paths>`.
