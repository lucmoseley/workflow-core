# v1.3.18

## What changed

The core's code is public at `lucmoseley/workflow-core`, and v1.3.18 is the
first release there: its `main` starts from one squashed commit, and no
earlier tag is on it (workflow-core#1954). The core's issues and history are on the
private `lucmoseley/workflow-core-tracker`. The marketplace url is unchanged.

Base §N7 now counts an exit code a test chooses per call as chosen output, so
a fake `node`, `npm` or `python3` that passes some calls and fails others is
injected at its var, never put on `PATH` (workflow-core#2266). `guard-npm-install.sh`
reads `curl` at `WFC_CURL` and `guard-issue-close.sh` reads `timeout` at
`WFC_TIMEOUT` (workflow-core#2422). §N7 names `WFC_GIT` for `git` (workflow-core#2581). The core's
session arbiter, `commit-paths.js`, `check-instruction-surface.js` and the
libs they reach read it through `scripts/lib/git-binary.js`, and
`guard-registry-atomicity.sh` and `inject-review-tier.sh` as
`${WFC_GIT:-git}` (workflow-core#2589). The core's other scripts still find `git` on
`PATH` (workflow-core#2636).

`guard-suite-concurrency.sh` now refuses an unbounded test launch while
`MemAvailable` is under its §6 ladder rung, its first line the same launch
with `--queue` (or through `queue-run.js`), which waits until the rung is
free (workflow-core#2305). A run naming its test files, a `--queue` launch and a build are
still only warned. `WFC_SUITE_CONCURRENT=1` stands it down, and its
stand-down record carries `limb: memory`; a count-cap one carries
`limb: count`. Admission holds no memory back for suites any more, so it
admits more sessions on the same reading, and the shell-start warning's
default floor is 2200 MB.

`.husky/commit-msg`'s `Weakens:` check counts a skip added to a tracked
`.spec.` test file (workflow-core#2271).

The read-edge extractor reads every test file vitest collects, not only
`.test.ts` and `.test.tsx`, so a `.spec.`, `.test.js` or other JS test's reads
join `docs/test-read-edges.json`, and its unseen reads reach `--unseen` and
the commit-time warning, which `.husky/pre-commit` now arms on any such test
file (workflow-core#2545).

`.husky/pre-commit` refuses a commit adding a file under `docs/research/`,
printing `rule:research-in-tree`: research is posted on its issue. Editing or
deleting a note already there passes (workflow-core#2356).

`.husky/pre-commit` refuses a commit staging `skills-lock.json` unless it
also stages `.agents/vendored-upstream-pass.json` with hashes matching the
staged lock and `.claude/skills/THIRD-PARTY-NOTICES.md` (workflow-core#2394).
`WFC_UPSTREAM_RECORD_OFF=1` stands the refusal down for one commit, for a
GitHub outage.

The priced-options guard's low-top test now refuses a round whose top
option is priced 65 or less once on its first send; re-sent still at 65 or
less, it meets the research ladder (workflow-core#2519). The band-drift watch reads tops
bunching at 70. `record-delegated-decision.js` takes `--still-caught yes|no`
in place of `--still-close`, meaning close or low-top, and its comment prints
`Still caught:`, though the ledger key stays `stillClose`; the morning review lists still-caught entries and still
finds ones posted as `Still close:` (workflow-core#2594).

A new Stop hook, `refill-wake.sh`, wakes the refill loop when a session it
launched in your repo ends, so the freed slot refills without waiting out the
loop's 300 s poll (workflow-core#2313, workflow-core#2466, workflow-core#2564). It needs `jq`, and without it wakes
nothing; where the loop's pidfile is absent it exits at once. No action
needed.

`init-adopter.js` infers a `check:staged` script that is a plain
`biome check --staged` as `node "$WFC_PLUGIN_ROOT"/scripts/biome-staged.js`
with the same flags, which lints the bytes the commit carries rather than the
worktree's, so a `commit-paths.js --patch` commit is no longer refused for a
neighbour's unstaged hunks in the file it patches (workflow-core#2540).

`init-adopter.js` no longer infers a `lint-staged` script as `check_staged`,
and refuses a `check_staged` it is given or infers that runs lint-staged:
lint-staged hides each partly staged file's unstaged hunks for its run,
removing a neighbour's uncommitted edits in a shared tree (workflow-core#2583, workflow-core#2587).

Every `PreToolUse` hook the plugin ships that can refuse a call now carries
`"onFailure": "block"`, so a deny-capable guard that times out, cannot start
or exits other than 0 or 2 refuses the call instead of letting it through; a
fault the guard catches itself still allows (workflow-core#2670). This needs Claude Code
2.1.295 or later. An older CLI ignores the field and keeps failing open, its
other hooks unaffected (measured on 2.1.294). A guard registered in your own
`.claude/settings.json` gets no field.

## Manual steps

- [act] Add `"onFailure": "block"` to each `PreToolUse` hook in your own
      `.claude/settings.json` that can refuse a call — by a `deny`
      `permissionDecision` or exit 2 — and to none that only warns (base §S3,
      workflow-core#2670). List the candidates:
      `jq -r '.hooks.PreToolUse[]?.hooks[]? | select(.onFailure == null) | .command' .claude/settings.json`;
      the step is done when every command left is a hook that never refuses.
- [act] Replace `lucmoseley/workflow-core` with
      `lucmoseley/workflow-core-tracker` in your `.claude/workflow-core.json`
      `corpus`, and in any skill, doc or script of yours that reads or files
      the core's issues, or each search meets the public repo, which has
      issues off (workflow-core#1954). List them:
      `git grep -nE 'lucmoseley/workflow-core([^-]|$)' -- ':!*.lock' ':!package-lock.json'`;
      the step is done when every hit left names the code: a clone,
      `blob/` or marketplace url.

- [act] Inject at `WFC_NODE`, `WFC_NPM`, `WFC_PYTHON` or `WFC_TIMEOUT` each
      `node`, `npm`, `python3` or `timeout` your tests fake with output or
      exit codes they choose per call, and have the test set the var instead
      of prepending `PATH` (workflow-core#2266, workflow-core#2422). List the candidates:
      `git grep -nE "[\"'/](node|npm|python3|timeout)[\"']" -- '*.test.*' '*.spec.*' 'test_*.py' '*/test_*.py' '*_test.py' 'conftest.py' '*/conftest.py'`;
      the step is done when every hit left is a decoy failing every call, a
      detached launcher's stub `node`, or a fake already set at its var.
- [act] Where a test of yours fakes `git` with output or exit codes it
      chooses per call, have the program under test run `git` as
      `"${WFC_GIT:-git}"` or `process.env.WFC_GIT || "git"`, and the test
      set `WFC_GIT` to the fake instead of prepending `PATH` (base §N7,
      workflow-core#2581, workflow-core#2589). List the candidates:
      `git grep -nE "(, *[\"']git[\"']\)|/ *[\"']git[\"']|/git[\"'\`]?( *<<| *>| *;| *,| *\)| *$))" -- '*.test.*' '*.spec.*' 'test_*.py' '*/test_*.py' '*_test.py' 'conftest.py' '*/conftest.py' '*.bats'`;
      the step is done when every hit left is a decoy failing every call, a
      fake already set at `WFC_GIT`, or no fake at all.
- [notice] The gate-switch check now counts a tracked `.spec.js`,
      `.spec.jsx`, `.spec.ts` or `.spec.tsx` file, or its `c` or `m` form,
      as a suite, so a repo holding one with `suites` off has its commits
      refused until it turns `suites` on (#2271).
- [act] Where your repo has `docs/test-read-edges.json` and tracks a test
      other than a `.test.ts` or `.test.tsx` one, clear each read
      `node <plugin root>/scripts/generate-test-read-edges.js --unseen`
      now lists in one: name the path as a literal the test or a helper it
      imports spells, or add a `full-sweep-only: <why>` line to the test's
      header comment (base §X10, #2545). The step is done when the listing
      reads `0 read(s)`.
- [notice] `resolve-ticket.js` refuses a completed close with no
      `**Practice:**` line — `ran — <note>`, `covered — <note>, <Researched
      date>`, `skipped — <exempt kind>` or `none-fits — nearest <craft>` — so
      a session or script of yours that closes through it must write one;
      a not-planned close owes none (#2325).
- [act] If you vendor skills, write the upstream record before your next
      commit that changes `skills-lock.json` (#2394). Run `node "$WFC_PLUGIN_ROOT/scripts/check-vendored-skills.js" --upstream`;
      where it names an `UPSTREAM-LICENCE` or licence `UPSTREAM-GONE`, refresh
      that `THIRD-PARTY-NOTICES.md` section from upstream and run it again.
      Commit the `.agents/vendored-upstream-pass.json` it writes. The step is
      done when `git ls-files skills-lock.json` prints nothing, or
      `git ls-files .agents/vendored-upstream-pass.json` prints the record.
- [act] If your `.claude/workflow-core.json` `commands.check_staged` runs
      `biome check --staged` with no `--write`, `--fix` or `--unsafe`,
      itself or through a `package.json` script, and your `package.json`
      declares `@biomejs/biome`, set `commands.check_staged` to
      `node "$WFC_PLUGIN_ROOT"/scripts/biome-staged.js` followed by that
      call's other flags, `--staged` dropped, then `&&` any other command the
      script ran (#2540). Leave the `package.json` script as it is: only the
      hook sets `WFC_PLUGIN_ROOT`. The step is done when
      `node scripts/lib/resolve-core.js scripts/lib/workflow-core-config.js command check_staged`
      prints neither a `biome check --staged` without a write flag nor the
      name of a script running one.
- [act] If your `.claude/workflow-core.json` `commands.check_staged` runs
      `lint-staged`, itself or through a `package.json` script, set it to
      `node "$WFC_PLUGIN_ROOT"/scripts/biome-staged.js` with your Biome
      flags, or to a command of your own that lints the index's bytes rather
      than the worktree's (#2587). No lint-staged flag makes it safe in a
      shared tree: `--no-stash` still hides the unstaged hunks, and
      `--no-hide-partially-staged` commits them. The step is done when
      `node scripts/lib/resolve-core.js scripts/lib/workflow-core-config.js command check_staged`
      prints neither `lint-staged` nor the name of a script running it.
- [notice] A commit made with any `WFC_<NAME>_OFF` variable set, such as
      `WFC_CITATION_TRACKER_OFF`, is now refused until a `Weakens:` line in
      its message names the variable (#2394).
