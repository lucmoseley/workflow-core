# v1.3.8

## What changed

Green suite runs from different sessions now count together. A push, or a
`result:` report, is covered when full or admissible `npm run test` greens
cover every commit it sends between them, each still holding at the commit,
so a neighbour's commit after your run voids your green only where it changes
a file your tests read (workflow-core#811, workflow-core#814). Regenerating `docs/test-read-edges.json`
no longer voids open greens: the manifest is re-read at the commit judged
(workflow-core#799). The pre-push check names each file no green covers and the commit
that carries it; its separate warnings for partial, unknown-scope and
admissible-scope runs are gone, and it still never refuses a push.

`push-check.js`, the new `push_check` entry in `.claude/workflow-core.json`'s
`commands`, says before a push whether a run is owed: exit 0 where every
commit is covered, naming the covering runs; 1 naming each uncovered file,
its commit and the command to run; 2 where it cannot judge. With the `suites`
module off, or the tests gated at commit, it prints the skip line and exits 0
(workflow-core#814). A repo declaring no `push_check` is given the plugin's own
`push-check.js`. The push line in `.claude/workflow-core.md`,
`rule:push-cadence`, `rule:push-green-suite`, the Stop warning on unpushed
commits and the `result:` refusal now send a session to it rather than to a
re-run.

With a session id, `run-vitest.js`'s narrowed default — a bare
`npm run test` or `npm run test:changed` — runs in a detached worktree at
HEAD under `.claude/worktrees/isolated-<pid>`, carrying only the uncommitted
files this session wrote, so a neighbour's or an orphaned edit can neither
redden nor void its green (workflow-core#812). Where that worktree cannot be built the run
says so and reads the shared tree as before; no session id, or `--shared`,
reads the shared tree.

A new SessionStart checker, `check-orphaned-edits.js`, names each tracked file
with uncommitted changes that no live session owns and nobody has touched for
24 hours, and files each one once per path and content as a `takes:triage`
issue, at most two per session start. It never reverts or writes the file
(workflow-core#813).

A new guard, `guard-unasked-rerun.sh`, refuses a session's first bare
`npm run test`, `npm run test:changed` or `npm test` while vitest greens
already cover HEAD and nothing the session wrote is uncommitted, naming the
covering runs; the same command typed again runs. A run with any argument or
flag, one in another checkout, or one with no session id is never refused,
and with no green on record nothing is (workflow-core#815).

`commit-paths.js --patch <file>` commits only your own lines of a file a
neighbour has also edited, from a private index, without writing the working
tree; its exit 4 means the commit landed but its follow-up did not, so never
re-run it — do what the output says (workflow-core#801). `commit-paths.js` also waits out
a neighbour's commit that moves HEAD under it, within the same three-minute
ceiling, instead of refusing (workflow-core#819).

The doc-map gate refuses a commit that adds a `docs/doc-map.md §<name>`
reference naming no heading of the map, or a bare `§<n>` that two `### <n>.`
headings share; references already in the tree are inherited and pass
(workflow-core#805). A new repo's `docs/doc-map.md` starts with §A and §B preambles and a
`## The propagation pass` section; an existing map is not rewritten.

The session-start container sweep and the label check confirm a
`takes:children` container's open children on its own sub-issue list before
retagging it, and no longer read another repo's `#N` as a local child (workflow-core#778).
`guard-sweep-fire.sh` and `guard-branch-publish.sh` now read a `gh` command
through every wrapper the other guards see through, and let a `--help`
through wherever it sits (workflow-core#772). `launch-successor.sh` is executable, as the
session-ceiling guard's bare-path instruction needs (workflow-core#796).
`docs/agents/adopter-upgrade.md` says `git tag --contains` is always empty on
a release, and names the core checkout's `release-contains.js` instead
(workflow-core#797).

## Manual steps

- [notice] Before a push, run the command the push line in
      `.claude/workflow-core.md` names — the plugin's `push-check.js` unless
      `commands.push_check` in `.claude/workflow-core.json` names your own —
      and run the suite only for what it lists. Another session's green now
      counts towards your push.
- [notice] A session's first bare `npm run test` over a HEAD that greens
      already cover is refused once; type it again to run it.
- [notice] Session start now files a `takes:triage` issue for each tracked
      file left uncommitted for 24 hours that no live session owns, at most
      two per start. Nothing is reverted: read each diff, then commit or
      revert it.
- [act] If `npm run test` runs the plugin's `run-vitest.js`, make sure
      `.gitignore` ignores `.claude/worktrees/` and your vitest config's
      `exclude` lists `.claude/worktrees/**`: every session's narrowed run now
      builds its worktree there, and without the exclude a neighbour's
      shared-tree run collects that copy's tests too. Nothing to do where both
      are already there.
- [act] With the `governance` module on, check that `docs/doc-map.md` has a
      `## The propagation pass` heading: `.claude/workflow-core.md` sends
      sessions to it, and the doc-map checker now reports a reference to a
      missing section. Where it is missing, copy that section from the
      plugin's `scripts/templates/adopter/doc-map.md`.
