# v1.3.17

## What changed

Base §0's test kind now names vitest's `.spec.` files — `*.spec.js`,
`*.spec.jsx`, `*.spec.ts`, `*.spec.tsx` and their `c` and `m` forms (workflow-core#2109).

`resolve-ticket.js` now refuses `--gist`, exiting 2 and writing nothing;
`--decision` is its only spelling (workflow-core#2111).

`.husky/commit-msg` now refuses a commit that weakens a check until its
message names each weakening on a `Weakens:` line: a `disabled` entry added to
`.claude/workflow-core.json` or a `modules` entry dropped, a `check-*`,
`guard-*`, `check:` or test command a workflow under `.github/workflows/` runs
less often, or a skip added to a test file HEAD holds (workflow-core#2235). The refusal
names each one and the line to write.

`.husky/commit-msg` also refuses a commit whose subject, its first line
that is not a `#` comment, runs over 72 characters, counted in characters,
not bytes (workflow-core#2332, ruled at workflow-core#2168). Subjects git writes itself pass:
`Revert "…"`, `Reapply "…"`, git's `Merge …` forms, `fixup!`, `squash!` and
`amend!`. `--no-verify` is the only escape.

The priced-options guard's close-rivals refusal now also catches a round of
any shape — rivals, yes/no or combinable — whose top option is priced 60 or
less, refusing it once on its first send whatever its `Checked:` or
`Unmeasured:` line says (workflow-core#2327, ruled at workflow-core#2228). Re-sent still at 60 or
less, it meets the research ladder as a still-close one does (workflow-core#2328), and the
close-check log's `stillClose` means still caught by either test.

The doc map has five authority classes: `append-only-historical` is gone,
with the pre-commit retro-edit gate, its `WFC_ALLOW_RETRO_EDIT` escape, and
the concision landing gate that refused an unpassed append-only `.md` (workflow-core#2334,
ruled at workflow-core#2162). The class-aware scans exempt only `binary-asset` files, and `docs/archive/sync-*` reports are `free-edit`. The
concision pass's `mark-pass.js` takes only `<cuts> [--base <rev>]`; a path
after `--` is refused.

Each entry of `docs/doc-map-superseded.json` and
`docs/machinery-superseded.json` holds only its `needles` and `allowlist`: the
loaders refuse a `text`, `figure`, `live` or `settled` field (workflow-core#2338, ruled at
workflow-core#2162). `generate-superseded-needles.js` and `npm run gen:superseded` are
gone; a superseded entry's needles are written by hand.
`check-always-loaded-pass.js` reads the last entry of
`docs/always-loaded-passes.json` and nothing else, so a pass replaces that
entry.

`docs/doc-map-vacated.json`, `generate-doc-map-vacated.js` and
`npm run gen:doc-map-vacated` are gone (workflow-core#2339). The doc map's
data holds one high-water mark instead, `highWaterMark` in
`docs/doc-map-high-water.json`: the highest §B id ever removed.
`check-doc-map.js` assertion 12 refuses a new `### B<n>` at or below it, and
assertion 13 refuses a commit that removes an entry above it without raising
it, or that lowers it.

No shipped skill writes a Bound, Corrected, Superseded or Withdrawn banner
back to a file any more: a disposal edits the declaring line in place or
deletes it (workflow-core#2337, ruled at workflow-core#2162).

`landing` is a known module, for the landing queue (workflow-core#2261); it stays off,
and nothing is owed for it.

`check-stranded-research.js` and `npm run check:research` are gone: research
is posted on its issue, and any note still in `docs/research/` is deleted
once a decision has used it (workflow-core#2335, ruled at workflow-core#2162).

The roadmap validator warns on a retired `m` code (`S/H`, `O/H`, `O/M`) on
every card, done cards included, and the roadmap template renders one as a
`RETIRED m CODE` chip on every card (workflow-core#2344, ruled at workflow-core#2170).

The adopter templates carry none of the removal-residue census's strict
patterns, held there by a test (workflow-core#2345). The patterns, kinds K1 to K8, are
`scripts/lib/residue-patterns.json` at the plugin root.
