# v3.2.0

## What changed

Breaking, action required: a checker opt-out marker takes a pointer, never
prose (workflow-core#5540). Each `<name>-exempt:` marker (`arbiter-literal`,
`bare-citation`, `citation`, `claude-route`, `cli-args`, `gh-route`,
`git-identity`, `isolation`, `jsonl-read`) passes a site only when a pointer
follows it: `#N`, `owner/repo#N`, `ADR-NNNN` or an RFC. A marker followed by
prose no longer passes, so a commit that touches its file is refused. The
comment-policy gate reads a pointer marker as code.

`check-test-env-writes.js` passes no `env-write-kept:` marker (workflow-core#5566): a
test's direct `process.env` write is refused whatever sits beside it. Use
`vi.stubEnv`, or run the case in a child process given its own env.

The comment-policy gate changes in three ways:

- It judges a shipped file's header (workflow-core#5627).
- It refuses a multi-line comment that carries a URL, unless at most one of
  its prose lines carries no URL (workflow-core#5589).
- It skips files `.gitattributes` marks `linguist-vendored` or
  `linguist-generated` (workflow-core#5530).

It also judges the files the upgrade copies, `resolve-core.js`,
`resolve_core.py` and `browse.py`, against the plugin's own bytes (workflow-core#5562); an
older copy clears once the upgrade rewrites it.

`check-swallowed-errors.js` judges a `contextlib.suppress` of a broad type
and an `__exit__` that returns true as it judges an `except` (workflow-core#5561).

The queue lander's `landingTester` takes `auto`, the default (workflow-core#5524, spec
workflow-core#5511): over the newest 20 whole runs, a
median suite time over 3 minutes tests on Actions, else, or under 5 runs,
locally; an Actions ask that never starts is tested locally. The upgrade
writes `.github/workflows/workflow-core-lander.yml` and
`.github/workflows/workflow-core-named-rerun.yml` where `landingTester` is
absent or `auto`, and removes them where it pins `local`. On a private repo
those runs draw on the account's Actions minutes.

Gating changes in the shipped rule text (workflow-core#5406). A calendar-date gate stays
open however far off the date is. A before/after rate
question is sized by a two-sample exact test, and the create guard,
`file-issue.js` and `issue-body.js` refuse a `**Gate basis:**` whose own
figures do not give the window it states.

`resolve-ticket.js` refuses a build close whose `**Values:**` line holds an
untraced value, a guess or an estimate not tagged `delegated — <why>` or
`house: #N` (workflow-core#5647). A build ticket lists those values under `## Values`.

The card rules in the shipped rule text, `rule:roadmap-gating`'s card branch
and the card-title and card-close rules, apply only where the `roadmap`
module is on (workflow-core#5405).

A background job keeps working while its waits and dispatched agents run in
the background (workflow-core#5554). Nothing to do.
