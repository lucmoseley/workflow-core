# v2.0.0

## What changed

`init-adopter.js` infers a `check:staged` script that runs
`biome check --staged` as `node "$WFC_PLUGIN_ROOT"/scripts/biome-staged.js`
with the same flags, `--staged` dropped, which lints the bytes the commit
carries rather than the worktree's (#2540, #2773). A script carrying a write
flag (`--write`, `--fix`, `--unsafe`, `--apply`, `--apply-unsafe`) now maps
too, the flag dropped, and init prints that auto-fix on commit was dropped
(#2598). A script that does not map is no longer kept as
`npm run check:staged`: init refuses it, exits 2 and writes nothing, naming
the form to declare, as it does a lint-staged one (#2774). An explicit
`--command check_staged=…` that runs `biome check --staged` is refused the
same way, naming the mapped command where one exists; one that is already
`biome-staged.js` is accepted unparsed. A config init keeps is not checked
there: `.husky/pre-commit` refuses a commit whose `check_staged` runs
`biome check --staged`, itself or through the script an npm, pnpm, yarn or
bun `run` names,
before running it, naming the command to declare (#2775).

Base §G7 now holds a fake the repo owns to its production adapter by a
contract test: one case list run against both, checking shape and verdict
(#2781).

Base §0's design vocabulary adds **core** (a module doing no I/O, its I/O
through injected ports) and **shell** (the program or composition root that
wires the adapters, calls the core and writes what it returns). New base §X11
has a program with a core keep a named boundary set of end-to-end cases (each
exit path, input channel, production adapter, boundary shape and boundary
regression) and test its other branches as module cases on the core (#2206).

The core's Node scripts now read `WFC_GIT` through one seam,
`scripts/lib/git.js`, its test fixtures aside. The core's shell scripts
still find `git` on `PATH` (#2636).

The mutation hold now refuses an old `Stryker disable` comment stating no
reason whose reach the commit widens over a line it adds: a line added under
a `next-line` directive, or one inside a region left open or opened wider by
deleting its `restore`. Its disable-comment read no longer fails open on a
host Babel or Stryker config that prints on stdout, is bounded at 30 s, and
a git fault reading one file costs that file alone rather than the whole
gate (#2727).

`guard-node-heap` and `guard-headroom-read` now run as Node entries,
`scripts/guard-node-heap.js` and `scripts/guard-headroom-read.js`. The rules
they hand over read as before; on a host with no `node` both stand down
(#2784).

`guard-bg-job`, `inject-test-rules` and `guard-citation-tracker` now run in
one PreToolUse hook, `scripts/guard-dispatch.js`, as in-process Node cores:
one node start per call where three bash guards ran, every core's context
joined, the call refused where the entry itself crashes or times out
(#2786).

`guard-pull-form` and `record-divergence` now run as Node entries,
`scripts/guard-pull-form.js` and `scripts/record-divergence.js`, still on
`if: Bash(git *)`, and `guard-branch` as a core of `scripts/guard-dispatch.js`. Their refusals and rows read as before. Where a guard's
core throws, guard-branch and guard-pull-form now refuse the call rather than
allow it; record-divergence follows `cd`, `-C` and an env prefix to the repo
a pull ran in, and no longer counts a `git pull` written inside a heredoc or
a quoted message (#2797).

`guard-issue-create-label` now runs as a Node entry,
`scripts/guard-issue-create-label.js`, over an in-process core, still on
`if: Bash(gh *)`. Its refusals and warnings read as before. A relabel,
`gh issue edit <n> --add-label takes:human`, now reads `#12` and an issue URL
as the issue they name, fetches the body from the repo the URL or `--repo`
names, and runs that fetch in the directory the edit runs in; a `--repo` it
cannot read is allowed, recorded (#2796).

`guard-suite-concurrency` now runs as a Node entry,
`scripts/guard-suite-concurrency.js`, over an in-process core, still on the
same twelve `if` narrowings. Its refusals, warnings and rule hand-overs read
as before. `scripts/run-vitest.js --queue` reads the gate in process rather
than spawning the guard on each poll (#2795).

`guard-npm-install`, `guard-unasked-rerun` and `guard-vitest-wrapper` now
run as Node entries, `scripts/guard-npm-install.js`,
`scripts/guard-unasked-rerun.js` and `scripts/guard-vitest-wrapper.js`, each
over an in-process core, still on the same `if` narrowings, and
`guard-check-sh` as a core of `scripts/guard-dispatch.js`. Their refusals, warnings and rule hand-overs read as before.
Where a core throws, guard-npm-install and guard-unasked-rerun now refuse the
call rather than allow it; a bare `npm` with no arguments, which crashed
guard-npm-install and so was refused, is now allowed. `lib/npm-options.sh` is
gone, its last sourcer with it (#2800).

`guard-rm-unchecked`, `guard-root-find`, `guard-ugrep-pattern` and
`guard-hook-escape` now run as Node entries, each `scripts/<name>.js` over an
in-process core, still on the same `if` narrowings, and `guard-cpu-load` as a
core of `scripts/guard-dispatch.js`. Their refusals and warnings read as before. guard-rm-unchecked
now reads a quoted value an `export` or `declare` gives (`export T='/q'`),
which crashed its bash form and let the whole command through, so such a
command can now be refused once; a crash or timeout of its entry now refuses
the call (#2801).

The capped launch's projection of a running session's remaining spend no
longer jumps to the gap between the cost table's two top quantiles once the
session is past the second-highest: it charges the tail's measured mean
remainder, `tailRemainderUsd`, which the table now carries. Each bar now
counts only the spend projected to land before its own reset, read off the
table's new `landedByHours`. `upgrade` rebuilds a table that lacks either,
by `node "$WFC_PLUGIN_ROOT"/scripts/measure-session-cost.js --write`, as it
builds a missing one (#2925).

`guard-stale-script`, `guard-job-dir-scratch`, `guard-root-scratch` and
`guard-scratch-overwrite` now run as in-process cores of
`scripts/guard-dispatch.js`. Their refusals and warnings read as before; the
four bash hook entries and `scripts/warn-stale-script.js` are gone (#2789).

`guard-claimed-bash-write` and `guard-file-claim` now run as in-process
cores of `scripts/guard-dispatch.js`. Their refusals, warnings and handed-over
rules read as before; the two bash hook entries,
`scripts/warn-claimed-bash-write.js` and `scripts/lib/guard-parse.sh`'s
`gp_rule_path_rows` are gone (#2788).

`guard-last30days`, `guard-review-rules`, `inject-review-tier`,
`guard-tracker-rules` and `guard-branch-publish` now run as in-process cores
of `scripts/guard-dispatch.js`, whose matcher gains `Skill`, and
`inject-founder-wording` runs there on a Skill call and as
`scripts/inject-founder-wording.js` on `UserPromptSubmit`. Their refusals,
warnings and rule hand-overs read as before. The six bash hook entries are
gone, and with them `lib/gh-body.sh`, `lib/push-dests.sh`,
`lib/main-rewind.sh` and `lib/guard-job-dir.sh` (#2792).

`guard-self-match`, `guard-wait-loop`, `guard-suite-background` and
`guard-sweep-fire` now run as in-process cores of `scripts/guard-dispatch.js`.
Their refusals, warnings and handed-over rules read as before, save that
`guard-self-match` now also warns on a grep pattern ending in a newline and
judges a `pkill` behind `time`. The four bash hook entries,
`scripts/lib/paste-self-match.sh`, `scripts/lib/pgrep-args.sh`,
`scripts/lib/suite-bounded.sh` and `scripts/lib/sweep-budget.js`'s command
line are gone (#2790).

`guard-recursive-dot-read`, `guard-echo-call`, `guard-dispatch-rewrite` and
`guard-blind-dispatch` now run as in-process cores of
`scripts/guard-dispatch.js`. `guard-wide-read` runs there too on `Read`, and
on its Bash `if` narrowing as a Node entry over the same core,
`scripts/guard-wide-read.js`; `guard-agent-poll` runs there on `Read`,
`ListAgents` and Bash. Their refusals, warnings and rule hand-overs
read as before, and the six bash hook entries are gone, with
`lib/echo-chain.sh` and `lib/guard-parse.sh`'s `gp_parent_wait_text` and
`gp_subagent_wait_text`.
Where they differ: `rule:dispatch-tier` and `rule:dispatch-search-tracker`
may be said once more in a session that saw them before the upgrade, their
latch having moved from `warn.<id>` to `<id>`; a missing `dispatch-*` rule
fragment now refuses every Agent call; where the agent-poll, echo-call,
dispatch-rewrite or blind-dispatch core throws, the call is refused; a
non-string `agent_id` reads as the parent's call (#2791).

`guard-agent-poll`, `guard-anthropic-report`, `guard-branch`,
`guard-check-sh`, `guard-commit-form` and `guard-cpu-load` now run on Bash
inside `scripts/guard-dispatch.js` rather than as hooks of their own, each
core on the commands its old `if` narrowings admitted, so a Bash call starts
no process for them. Their refusals, warnings and rule hand-overs read as
before. Where they differ: a core's throw is refused in the dispatcher's
words, naming the core; a command reached past leading blanks, a compound
command's keyword or `NAME=value` assignments is judged wherever its
harness `if` narrowing may not have started the guard (#3224). Every fail-closed core of
the dispatcher, `guard-branch-publish` included, now allows, logged, where
the repo itself does not resolve, as the per-guard entries already did
(mantahostels#147).

Where the `landing` module is on, a bare `npm run test` runs only the
session's touched tests: each test file its own work edited, and each test
that directly imports or reads a file it changed, one hop. It never
escalates to the whole suite. Where the read-graph manifest will not render
it runs the edited tests, the tests directly importing a changed file and
each changed file's same-stem sibling tests, and says so. A selection with no test in it runs nothing and exits 0; the
lander runs the full suite. The run ledger records such a run as kind
`touched`. With `landing` off the bare run is unchanged (#2930).

Where the `landing` module is on, a push owes no certificate: the
lander runs the full suite before `main` moves. `.husky/pre-push` and
`push:check` print one skip line saying so and exit 0, and the push-rules
guard hands no `push-green-suite` rule. `push-cadence-landing` now reads: run the
tests you touched, by name or with the bare test command, then push to
`landing`. `push-green-suite-landing` is gone. With `landing` off every
push check is unchanged (#2929).

Wherever `push:check` skips — the `landing` module on, `suites` off, or the
tests gated at commit — the `result:` refusal no longer blocks a job whose
commits no certificate attests, and the unpushed-commits `Stop` warning says to push,
to `landing` where that module is on, rather than run `push:check` first.
Where `push:check` judges attestation, both are unchanged (#2933). In those same
three cases a `--changed`, `--adopt` or `--retest` run's banner reads
`NO PUSH GATE — <why push:check skips>` in place of its admissibility line,
and a `--queue` run that selects nothing ends on that reason (#2961).

Where the `landing` module is on, a bare `npm run test:py` runs only the
session's touched Python tests, through the same selection as the bare
`npm run test`: each `test_*.py` its own work edited, each test that directly
imports a changed module, and each test naming a changed path under its own
directory, the way a test reaches a script it runs as a subprocess or loads by
file path. Where the read-graph manifest will not render it keeps those and
adds `test_<stem>.py` beside a changed `<stem>.py`. A selection with no test
in it runs nothing and exits 0; a selection it cannot read refuses the run, exit 1, naming `npm run test:py -- scripts`. A
typed argument, or `landing` off, leaves `test:py` unchanged. The run ledger
records a touched pytest run, an empty one included, as kind `touched` with
its `resolvedFiles` (#2934, #2958). A pytest config that exists but cannot
be read, such as a `pytest.ini` that is a directory, now refuses the bare run
rather than reading as absent, and the `pyproject.toml` read runs the python
`WFC_PYTHON` names (#2962).

Under `landing`, a bare run launched with a session id — `test:py`, or
`npm run test` in its overlay — selects only from the paths that session's
own work carries, and refuses
where that set cannot be read (#2958). With no session id, as in a terminal
or CI, and in a vitest run on the shared tree (`--shared`, or an overlay that
would not build), it selects from the tree's diff against the default base
plus every untracked file, and reads import edges from that tree. Both bare runs keep only files their runner
collects: vitest's own `vitest list`, and pytest's `testpaths`,
`python_files` and `norecursedirs` from whichever config pytest discovers.
The banner lists dropped files under `NOT COLLECTED` (#2952).

Where the `landing` module is on, the unasked-rerun refusal's rule now says,
before a push, to run the tests you touched; the lander runs the full suite.
With `landing` off it still names `push:check` (#2936).

Admission now weighs every test run by the test files it resolves to in
its own repo, counted once at launch and carried in its launch record, where
the queue, the gate and the `ps` weighers all read it; the files its argv
names no longer weigh it. A run takes the machine-wide whole-suite slot only
at 121 resolved files or more; any smaller run, a whole suite of yours
under 121 files included, runs beside the slot on the memory rung for its
file count. The run ledger records each run's `resolvedFiles` and
`wholeSlot` (#2931).

A touched run — named test files however many, `--retest`, or the bare
`npm run test` under `landing` — never takes or waits for the whole-suite
slot, and waits only on the memory rung for its file count. It forks one
vitest worker per file below the whole-suite count. Queue-exit records name
such a bare run's kind `touched` (#2935).

`record-tool-echo`, `post-write`, `refresh-claims`, `scan-injection` and
`guard-image-budget` now run as in-process cores of one PostToolUse hook,
`scripts/guard-dispatch.js`, matched on `Bash|Read|Write|Edit|NotebookEdit|WebFetch|WebSearch`
with a 15 s timeout. What each says reads as before; the five hook entries,
`scripts/record-write.sh`, `scripts/format-on-write.js` and
`scripts/scan-on-write.js` are gone, and `scripts/scan-injection.js` is only
its `--file` measurement path (#2787).

While another process's whole suite is running, a vitest run outside the
whole-suite slot raises its nice by 10, to at most 19, before it forks its workers, which
inherit it; the lander's own bisect runs never yield, and pytest runs are
not reniced (#2955).

`start-lander.js` starts the lander under `systemd-run --user --scope` where
the user's systemd manager makes one, so its suite takes CPU as one cgroup
sibling of the sessions' cgroup rather than process by process; elsewhere it
starts as before, and its log says so. A vitest run yields its CPU only to a
whole suite in its own cgroup. Without `Linger=yes`, the user manager, and
the lander's scope with it, stops when the user's last login ends (#2956).

`init-adopter.js` and `upgrade.js` now install a `.husky/post-merge` hook
beside `.husky/post-commit`. Both run `keep-hook-shims.js`, which in the
main checkout keeps an exit-0 shim at each `scripts/` hook script that
`.claude/settings.json` or the core's self-plugin hooks file named for a live
session, after the checkout deleted it, and removes the shim once no live
session started on that line (#2879).

The bash guard parser is gone: `scripts/lib/guard-parse.sh`,
`scripts/lib/suite-launch.sh` and `scripts/lib/guard-gh-api.sh` are deleted,
with `gp_allow`, `gp_begin`, `gp_subject` and `gp_warn`, and `guard-log.sh`'s
`gl_open` and `gl_exit`, off the helper surface. `guard-log.sh` keeps
`gl_log`. These are exports v1.3.18 promised, so this release is a major
one (#2802).

`.claude/workflow-core.json` takes an optional `fullTestShards`, a positive
integer: the landing module's local tester splits `full_test` into that many
`--shard=k/n` runs, each in a suite slot of its own and under its own suite
ceiling, so a whole suite too long for one ceiling still reaches a verdict
(#2996). The batch is red where any shard is. Declare it only where
`full_test` takes vitest's `--shard`; absent, the run stays whole.

Base §G5's house identifier limb now names readers `readX`: a JS or TS
function whose job is returning what it read from a file, a directory or a
command's output, raw or parsed. Another verb leading the name (`renderX`,
`loadX`) passes, as does a wrapper named for the command it runs (`git`,
`gh`) (#2750).

## Manual steps

- [act] If your `.claude/workflow-core.json` `commands.check_staged` runs
      `biome check --staged`, itself or through a `package.json` script, set
      `commands.check_staged` to
      `node "$WFC_PLUGIN_ROOT"/scripts/biome-staged.js` followed by that
      call's other flags, with `--staged` and any write flag (`--write`,
      `--fix`, `--unsafe`, `--apply`, `--apply-unsafe`) dropped (#2731).
      Dropping a write flag loses auto-fix on commit: `biome-staged.js` lints
      a thrown-away extract of the index, and Biome's `--write` would rewrite
      the worktree file, a neighbour's hunks included (#2583, #2598). Where
      the script also runs other commands, through `&&`, `;`, `|`, a redirect
      or a second command, declare them in a gate of their own, never
      `&&`-joined onto `biome-staged.js`; where you followed v1.3.18's step and
      `check_staged` is now `biome-staged.js … && <other>`, move `<other>`
      the same way. Leave the `package.json` script as it is: only the hook
      sets `WFC_PLUGIN_ROOT`, and run by hand it still fixes. The step is done when
      `node scripts/lib/resolve-core.js scripts/lib/workflow-core-config.js command check_staged`
      prints neither a `biome check --staged` nor the name of a script
      running one. A call in one of these shapes is refused; declare instead:
  - a value after a space (`--reporter json`): its `=` form,
    `--reporter=json`;
  - `--config-path`, `--vcs-root`, `--reporter-file`, `--log-file` or
    `--stdin-file-path`, whatever the value: a `biome-staged.js` command
    whose flags you own;
  - a positional path, `.` included: the command with no path;
  - Biome run through anything but `biome`, `@biomejs/biome`, `npx biome`
    or `npx @biomejs/biome` (`npm exec`, `pnpm`, `yarn`, `bunx`, a
    `node_modules/.bin/` path, a version pin such as
    `npx @biomejs/biome@1.9.4`): a bare `biome check --staged …` script, or
    a `biome-staged.js` command;
  - `@biomejs/biome` declared in neither `dependencies` nor
    `devDependencies`: add it to `devDependencies`;
  - `--changed`, `--since`, `--watch`, `--help`, `-h` or `--`: the command
    without it;
  - a switch given a value (`--write=true`), or a value flag given an empty
    one (`--reporter=`): the bare switch, or the flag with its value;
  - a flag not on `biome-staged.js`'s allowlist, which the refusal names,
    every short flag but `-h` among them (`-v`): a `biome-staged.js` command
    whose flags you own.
