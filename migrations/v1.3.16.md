# v1.3.16

## What changed

Your session rules gain `## Building for the long term` (workflow-core#1739): where a
durable fix and a quick one both finish the task, take the durable one even
when it costs more now.

`.claude/workflow-core.json` takes an optional `worktreeLinks`: an array of
repo-relative paths, the gitignored files your suite reads — a `.env`, a venv,
a generated artefact (workflow-core#1767). A commit-gated suite now runs in a throwaway
worktree holding only tracked files, both in `commit-paths.js`'s pre-lock run
(workflow-core#1760) and in the pre-commit hook (workflow-core#1766), so no other session's unsaved file
can refuse your commit, and a suite needing one of these goes red there. Each
declared path your checkout has is linked in; one it lacks is skipped.

The `.gitignore` block now ignores `.claude/worktrees/`, where those
throwaway worktrees are made, so one no longer shows in `git status` while
your suite runs, for a sweeping `git add` to stage (workflow-core#1774).

A guard of yours that calls `gp_begin` now leaves a guard-log record when it
exits non-zero before a verdict, so an abort on an unset variable under `-u`
reaches `check-guard-errors.js` rather than stderr alone (workflow-core#1818).

Your session rules now name the on-demand status report,
`node <plugin root>/scripts/status-report.js`, which needs no `package.json`
(workflow-core#1825). It runs the repo-health checkers that no longer fire at session
start.

The standards base gains §G9 (workflow-core#1821): state a module keeps between calls
has one writer, or writers whose names say what each does to it. It binds
programs, libraries and hook modules, as a judgement rule.

The standards base's lighter tier is gone (workflow-core#1824). Presentational code — a
component, a layout, a static data table — now takes the library's full
rule set. Five rules newly bind it: §N2's header, §T5's `readonly`, §T6's
no `satisfies`, §T7's injected dependencies and no I/O, and §T8's
missing-entry check. §0's default map now sends all of `app/**` to library.
workflow-core#1824 gives what the listings below found in mantahostels.

Your `AGENTS.md`'s supervision priors still say to skip tests, docs and
review on presentational scaffolding, a skip with no ground but effort; a
manual step rewrites that line to match (workflow-core#1873).

§T7 now lets the two kinds of module at a web app's edge do I/O (workflow-core#1903): a
production adapter, which fills a port against a real supplier and holds
only the transport, and a composition root, a module the framework invokes
as an entry point — a server-rendered page or layout, a `route.ts` handler,
a `"use server"` function or module, `proxy.ts` (`middleware.ts` before
Next 16), `instrumentation.ts`. Each one's header says which it is and
names the suppliers it touches, in place of the no-I/O statement.
§0's default map now sends `proxy`, `middleware` and `instrumentation`,
as `.ts` or `.js`, at the root or under `src/`, to library (workflow-core#1923), so §T
and §N2 reach them.
It also sends `src/app/**` and `src/lib/**` there (workflow-core#1961): a `src/`-layout
app's pages, layouts, route handlers and modules, which bound §G alone.
It sends a Next.js Pages Router app's `pages/**` and `src/pages/**` there
too (workflow-core#2061), and §T7 names that router's composition roots: a page's
`getServerSideProps`, `getStaticProps` and `getStaticPaths`, and a
`pages/api/*` handler.

The pre-commit Python gate now refuses an `except` your commit adds that
neither raises nor exits and cites no ticket, narrow catches included
(base §N5, workflow-core#1830). It judges the staged program-routed `.py` paths and
needs `python3`. A citation is `#N`, or `<repo>#N` for a repo in your
`corpus`. `.claude/workflow-core.json` takes an optional `pythonRoutes`,
an object of pathspec globs to `program`, `test`, `library` or `none`,
the first match winning, as your code-standards local file's route rows
do. A `.py` no row matches is a program only where it opens with a
shebang and sits under no `test/`, as base §0's default map has it. The
code-standards checker warns where `pythonRoutes` and the table disagree,
and the table wins (workflow-core#1863).

Each `.husky/*` hook is now a shim naming no plugin path (workflow-core#1839). At every
run it finds the core through your `scripts/lib/resolve-core.js`, which
upgrade now writes, and runs that core's own hook, so a pruned plugin version
or a fresh clone no longer stops a commit and a bump changes no hook. Where no
core resolves, a commit is refused; a push and a post-commit go on, saying
their checks did not run. This walk rewrites every hook that names a plugin
path into its shim.

The pre-commit shell gates, shellcheck and shfmt, now take every shell file
you commit, not only `scripts/**/*.sh` and the husky hooks (workflow-core#1828). A shell
file is a husky hook or its `.local` companion, a `.sh` or `.bash` file
anywhere, or a file with no extension whose shebang names `sh`, `bash`, `dash`
or `ksh`. A path your `.gitattributes` marks `linguist-vendored` or
`linguist-generated` is left out: that is now how a route row sending shell to
"none" takes effect. `node <plugin root>/scripts/lib/formatters.js shell-files
--tracked` lists the set, one path a line, and is on the helper surface.

An `archScan.threshold` override no longer moves the architecture-scan
counter's learned threshold, so removing it resumes what your scans' yields
set (workflow-core#1348). `--next-threshold` prints `{threshold, nextThreshold}` as one
JSON line on stdout. Growth leaves out test support: `test/`, `tests/`,
`fixtures/`, `testkit/`, `testkits/`, `stubs/` and `fakes/` directories,
testkit, harness, fixture, stub and fake modules, and `.test.mjs`, `.test.cjs`
and `.test.jsx` files (workflow-core#1743). A new `--partners <saved dry run>` prints each
hot file's change-coupling partners over that run's window, for the
architecture-scan skill's explore step (workflow-core#1743).

Base §0's test kind now names every path the standards checker and the
architecture-scan counter already treat as test code: `.test.jsx`, the
`c`- and `m`-prefixed test extensions, pytest's test files, `tests/`,
`fixtures/`, `testkit/`, `testkits/`, `stubs/` and `fakes/` directories, and
§G6's support modules (workflow-core#1888). §X and §N2 now bind those files, and a shell
script among them routes as test, losing §S.

The standards base gains two test rules (workflow-core#1885). §X8, a judgement rule:
a test case a change adds or rewrites costs no more to run than its
fitness needs — an expensive fixture built once per file, a state seeded
rather than replayed, one pass over a shared input, and a speed change
proved by a named mutation. §X9, a hard rule: a test asserts time through
an injected clock or a count, never through wall time measured around the
call, and a case that must cross the real clock says why at the site. §0
gains pytest's tell: a `pytest.ini`, a `[tool.pytest.ini_options]` table
in `pyproject.toml`, or a `conftest.py`.

§X10, a judgement rule binding every test: a test names each tracked file
it reads where the test selector can see it, or its header carries a
`full-sweep-only:` line saying why (workflow-core#1886). §0 gains the read-edge
manifest's tell, `docs/test-read-edges.json`. The `--unseen` listing of
`generate-test-read-edges.js` now follows a name walking a literal array or
a listing — a `for … of`, an array callback or an `it.each` table — and a
helper parameter its callers pass one.

`retro-count` no longer refuses on a warning about another key that quotes
`"retro"`, such as an unknown module named `retro`; every fault on `retro`
itself still refuses (workflow-core#1744).

Your `.claude/settings.json`'s `"outputStyle": "core-voice"`, written at
adoption, named no style, so no session of yours has loaded the core's voice
(workflow-core#1944). The harness names a plugin's style `<plugin>:<name>`, here
`workflow-core:Core voice`, and this bump rewrites `core-voice` to it. A style
you chose yourself is left alone. Expect about 1.6–2.0k more tokens at each
session start. `node <plugin root>/scripts/status-report.js --only
output-style` now warns where the setting names no style.

Every suite run through the core's vitest wrapper now ends with the
run-cost report (workflow-core#1883): one `RUN COST:` line per test file new or changed
since the merge-base with `origin/main` and over 10 s of its own wall time,
import and setup included, marked new or pre-existing, then one summary line
with the load and available memory. It never changes the suite's exit code,
and prints nothing under `CI`. A run through the core's pytest wrapper,
`run-pytest.js`, ends with the same report, timed in worker-seconds: each
file's setup, call and teardown summed across xdist workers (workflow-core#1884).

A session's first `Write`, `Edit` or `NotebookEdit` to a test file now
hands it base §X8, §X9 and §X10, once a session (workflow-core#1887).

The standards base now records, in §0, the floor every repo's review checks
a finding against: what the plugin's own `.husky/pre-commit` refuses in
every repo (workflow-core#1826). Your local file's §W lists only what your repo adds.

A new `mutation` module, off by default, holds a commit on a declared
sensitive path while a planted bug on a line it adds or changes survives
every test (workflow-core#1871). With it on, a commit whose staged paths match a
`sensitivePaths` glob runs StrykerJS 10 with the vitest runner over exactly
those lines, in a throwaway worktree, and is refused while any mutant there
survives or has no covering test (workflow-core#1906). The two ways past are a test that
kills it, or a `// Stryker disable next-line <mutator>: <reason>` comment;
one stating no reason is refused (workflow-core#1909). No score is gated. Your own
Stryker config is used where you have one (workflow-core#1907). Without either Stryker
package or vitest, every commit on a declared path is refused with the
install line; a declared path Stryker cannot mutate is named and skipped
(workflow-core#1911). A cold run costs minutes, a warm one seconds;
`node <plugin root>/scripts/mutation-hold-gate.js --seed` pays the cold run
once, with no commit (workflow-core#1912).

Your tracker gains a `parked` label, synced like the others (workflow-core#2000). A
background session that ends `needs input:` with its question round posted
on an issue it claims labels that issue `parked`; the shortlist then skips it
and lists it under `PARKED` with its age. The label comes off when the
founder types in that session, or when any session claims the issue.

Every prompt you type now writes its time to `~/.claude/.founder-presence`,
one file per machine (workflow-core#2004). A background job's launch prompt, a
`claude -p` run, a subagent and a prompt the harness writes (a subagent's
report, a task notification) write nothing; a prompt typed in a repo that
does not run this plugin writes nothing either. Nothing reads it yet; the
away-mode refill loop will, to keep a slot free while you are present.

Your session rules file is smaller (workflow-core#2035). A rule a guard prints at the
moment it bites leaves the file, and that guard prints the whole rule
then: claiming, labels, closing, branches, publishing, pathspec commits,
`--no-verify`, file claims, wait loops and the rest. Switching a module
on, the on-demand repo checks and the plugin provenance block move to
`.claude/workflow-core.reference.md`, a new core-owned file that is never
imported. Your `AGENTS.md` template loses the verify-a-package line,
which `guard-npm-install.sh` prints; your own copy is not touched.

Sixteen plugin skills leave the start listing (workflow-core#2036, workflow-core#2030, workflow-core#2050):
`architecture-scan`, `capture-drain`, `card-close`, `code-review`,
`codebase-design`, `concision-pass`, `diagnosing-bugs`, `domain-modeling`,
`grilling`, `pick-next`, `prototype`, `research`, `retro-sweep`,

session start and reports when a Claude Code update lists such a skill

`card-close` is now a skill rather than a command, and the plugin declares no

file, a `CLAUDE.md` or an `AGENTS.md` is told to load `writing-for-agents`

Where your output style resolves to Core voice, the tracker commands paste

Start reports no session acts on now print only in

repo-checks replays, the plugin-reconcile deferral, the throttling-collector

`.claude/workflow-core.json` gains `admissionGate` (workflow-core#2033). Set to `true`,
