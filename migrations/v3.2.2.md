# v3.2.2

## What changed

The upgrade rewrites `scripts/lib/resolve_core.py` from the plugin where an
adopter already holds a copy, as it does `resolve-core.js` (#5718). An older
copy's comment-gate breaches clear with this bump's walk.

The comment-policy gate changes in four ways:

- It accepts the `workflow-core#N` pointer the release writes into shipped
  files (#5694).
- It passes a Stryker disable that states its reason after the colon, as a
  K3 suppression, and refuses one with no reason (#5720). A disable with
  more than one space after the comment opener, or a JSDoc-starred one,
  which Stryker ignores, is refused (#5748). A comment opening `Stryker restore` passes only where it is the
  directive Stryker's own pattern matches; anything else is judged as prose
  (#5495).
- An adopter may list one-word markers in a `commentMarkers` key in
  `.claude/workflow-core.json`; a comment line opening on one reads as code,
  for the adopter's own checker to judge (#5709). A suppression stays judged
  as one, and a malformed key prints a WARN.
- `fails_loudly` passes a Python handler that prints and returns a
  `(result, code)` tuple holding a non-zero constant (#5749).

`check-precommit-exit.js` reads each `||` on a pre-commit line on its own, so
it catches a checker's `exit 1` behind `; fi`, `; done`, `}`, `)`, a case arm,
an `else` or `elif`, a one-line `|| { ...; exit 1; }` group, or a redirect or
`&` after the closer, among other one-line forms (#5684, #5686).

An adopter may declare a `ciSetup` key in `.claude/workflow-core.json`: a list
of single-line shell commands the lander workflows and the CI job run after
the install (#5700). On an adopter, an Actions red that names no failing test
file, on the whole run or on one shard (#5700), and every Actions-side run that
gives no verdict (#5511), hands the ask to the local tester with a lander log
line.

The lander signs a failure alike across temp-dir names, so main's red rerun
elsewhere is no longer charged to a queue ref, and says when main fails the
same files (#5727). A stale-base batch takes every waiting ref before it
holds (#5681). `blobTree` fetches each blob from git once, so a read-edge
render at pre-commit runs in seconds (#5745).

A session's touched, named and `test:changed` runs read a snapshot of its
tree taken at launch, so it may keep writing while the run goes; a rerun of a
run still in flight, and a commit through the declared commit-time test gate
meanwhile, are refused (#5716). A subagent holds its turn on a run
moved past 30 s with `in-flight-runs.js wait` (#5724).

The refill loop's gate sweep queues a by-hand triage for a `Gated on:` gate
with no `check:` segment on first sight and every 14 days after
(lucmoseley/mantahostels#3869).
