# v1.1.18

## What changed

A new hook, `inject-recurrence-checks.sh`, hands a session four checks to run
when a fault the founder believed fixed comes back: on a prompt that describes
one, and when a session loads the `diagnosing-bugs` skill. One check is a
search for the earlier fix across the trackers named by `corpus` in
`.claude/workflow-core.json`. Listing the hook under that file's `disabled`
switches both routes off.

Undeclared, `corpus` is your own tracker plus workflow-core's. A fix that
landed on a sibling tracker is then never searched, and nothing says so.
