# v3.2.4

## What changed

Breaking for a session's own test run: `guard-test-timeout` refuses a
foreground touched, named or `test:changed` run whose Bash `timeout` is over
30000, or unset, and names the same command at 30000 (workflow-core#5800). Such a run
reads a launch snapshot, so past 30 s it moves to the background and
notifies. The refusal binds only where the test script's body runs
`run-vitest.js`; a repo with no such script, a `--full`, `--queue`,
`--shared` or `--isolated` run, a `run_in_background` call, a command that
also launches a suite the snapshot does not cover, and a `WFC_TEST_TIMEOUT=1`
prefix pass.

The comment-policy gate changes in three ways:

- JavaScript held in a Python string, on the right of a `NAME_JS =`
  assignment or passed to a Playwright page call such as `evaluate` or
  `add_init_script`, is judged by the JS comment rules at its Python line
  (workflow-core#5793).
- A `requirements*.txt` at any depth in the tracked tree is a K2 manifest,
  so a comment naming a dependency it lists has a source (workflow-core#5792).
- A K2 source note whose URL sits behind a `#N` pointer written as a
  reference link, `[#N]: url`, is refused, as the inline form is (workflow-core#5494).

The gate sweep reads closed issues labelled `watch:closed` beside the open
ones, so a watch on a rare or outside event can close and still have its
`Gated on:` check run; on met, the judge reopens it and strips the label
(workflow-core#5801). The upgrade creates the label.

`scripts/remove-orphaned-worktree.js <dir>` removes a linked worktree only
where nothing in it is unlanded, closing its orphaned-edit filings, and an
orphaned-edit filing whose worktree holds nothing unlanded names it (workflow-core#5806,
workflow-core#5807). Levelling the main checkout discards an edit `origin/main` already
holds byte for byte and carries on, and `check-orphaned-edits.js` files no
issue for one (workflow-core#5808).

A pytest or `node --test` part-suite queued through `queue-run.js` is
charged no more than its repo's highest measured whole-run peak, where the
peak tripwire is armed (workflow-core#5802), and counts live on the tripwire while it
runs (workflow-core#5812).

Burn mode moves only code-review and legal-research dispatches; launches,
loop resumes and the session model are the same on and off, and switching
needs no restart (workflow-core#5809, workflow-core#5810). The morning review reports a crash-zeroed
ledger record only where it could fall in its window (workflow-core#5795).

## Manual steps

- [notice] The test-timeout refusal needs no config. To stand it down in a
      repo, list `guard-test-timeout` under `disabled` in
      `.claude/workflow-core.json`.
- [notice] The comment-policy gate refuses only a breach the commit adds;
      an existing comment the wider reading now charges does not block. To
      list them first, run
      `node "$WFC_PLUGIN_ROOT"/scripts/check-comment-policy.js --all`.
- [notice] The upgrade's label sync creates `watch:closed` in the tracker;
      a sync that prints FAILED for it owes
      `gh label create watch:closed --color D4C5F9 --description "A closed issue whose Gated on: check the gate sweep still runs; a met reading reopens it." -R <tracker>`.
