# v1.3.9

## What changed

The vendored Matt Pocock skills now match `mattpocock/skills` v1.3.1, with
every local edit this plugin declares re-applied (workflow-core#906). Two of upstream's
changes reach an adopter directly. The domain glossary is now `GLOSSARY.md`
at the repo root, not `CONTEXT.md`: `domain-modeling`, `triage`,
`improve-codebase-architecture`, `diagnosing-bugs`, `tdd` and the rest now
read and write that name, and the session-rules line in
`.claude/workflow-core.md` says so (workflow-core#882). And `resolving-merge-conflicts` is
gone, as upstream dropped it (workflow-core#879).

`grilling` keeps upstream's new round template but without the `---` line
between questions, which the priced-options guard refuses. `ask-matt` no
longer routes to `/implement-spec`, `/pr` or `/retro`, which this plugin does
not ship (workflow-core#879). `grilling` also stops warning that a fact-finding dispatch
with no `Artefact:` line is refused: one is supplied (workflow-core#928).

A Stop guard, `guard-automode-refusal.js`, sends a turn back once per refused
call when it ends after an auto-mode classifier refusal, printing the refusal
paragraph `rule:founder-handover` now carries (workflow-core#851, workflow-core#860). A Stop guard,
`guard-paste-self-match.js`, refuses a turn handing the founder a `!` paste
whose `pkill -f` pattern matches the paste itself, and so the founder's own
shell (workflow-core#921). A PreToolUse Bash guard, `guard-hook-escape.sh`, refuses an
agent's command setting `WFC_ALLOW_BRANCH` or
`WFC_ALLOW_GATE_INPUT_DELETE`; the pre-commit refusals and rule texts now name each
escape as the founder's to set from their own terminal (workflow-core#916). A new
SessionStart check, `check-kernel-stall.js`, prints the recovery when the
kernel log shows an RCU CPU stall this boot, and `dispatch-sessions.sh`
refuses with exit 5 on one; both stay silent where the log cannot be read
(workflow-core#867).

A CPU load ceiling: at load1 of 6 per core or more, `run-vitest.js` holds a
new run for up to 5 minutes and then refuses, and session admission,
`dispatch-sessions.sh` and `pick-next` hold every slot, the always-admit-one
slot and `--force-memory` included. `WFC_LOAD_CEILING` sets the ceiling, `0`
turns it off, and an unreadable load fails open (workflow-core#830, workflow-core#834).

`resolve-ticket.js` refuses a resolution comment that names a commit sha
without a `**Door:**` line saying whether the change is two-way or one-way;
`docs/agents/issue-tracker.md` holds the one-way list (workflow-core#895). A `/triage`
session opening a spec whose tickets have all closed is told to review them
together: the new `spec-commits.js <n>` lists every commit citing the spec or
its tickets and one `git show` over them, findings are filed under the open
spec, and `--since <sha>` re-reviews only the commits after the last pass
(workflow-core#892, workflow-core#897). `/implement` is told to read its parent spec and its closed
blockers' resolutions before starting (workflow-core#893).

An issue write adding a gate
line is refused where the gate basis leaves one of its windows unexplained,
and prints `rule:roadmap-gating` (workflow-core#823). A dry run of `issue-body.js replace`
now writes nothing (workflow-core#821). A session may apply `waiting:external` itself when
it sent the thing or has the founder's word it was sent (workflow-core#869). The tracker
guide fetches a ticket with `--json comments`, not `--comments` (workflow-core#899).

The session-ceiling guard's 100-turn and 200,000-token bands no longer refuse
a turn ending `waiting:` or `needs input:`; the 300,000 ceiling still refuses
any turn (workflow-core#919). A background job needing only one founder act may hand it
over directly — the literal command and a send-back line — instead of a
lettered round, and the priced-options guard and `core-voice` say so (workflow-core#926).
The Standards review axis, on all three routes, is told when the repo has no
`docs/code-standards.md` and reviews against the smell baseline (workflow-core#886).
`docs/agents/guard-authoring.md` records that a Stop hook's
`additionalContext` re-opens the turn as a block does (workflow-core#829).

Seven skill descriptions are reworded to "<what it is>. Use when <trigger>.",
and steps that ran `concision-pass` in prose now call the Skill tool (workflow-core#884,
workflow-core#889); `burn-mode` and `design-mode` descriptions are quoted, so strict YAML
readers stop dropping them (workflow-core#885).

`issue-body.js`, `reap-finished-sessions.js`, `check-host-root.js`,
`checker-new-faults.js` and `report-new-shared-faults.js` answer `--help` with
their usage and refuse an unknown flag with exit 2 before doing anything, and
every checker built on `lib/check.js` answers `--help` (workflow-core#920).
The pre-commit host-root check judges only what the commit stages, so a
neighbour's untracked script no longer refuses your commit (workflow-core#917), and the
guard-test isolation check also reads non-test `scripts/` `.ts` helpers, run
on any staged `scripts/` `.ts` or `.sh` (workflow-core#837). A narrowed test run's worktree
skips a shared artefact the checkout lacks instead of failing on it (workflow-core#822).
The post-Bash claim refresh and lock listing are faster (workflow-core#833, workflow-core#841, workflow-core#852).

## Manual steps

- [act] If `CONTEXT.md` exists at the repo root and `GLOSSARY.md` does not,
      `git mv CONTEXT.md GLOSSARY.md` and fix every reference to the old
      name. Until then the skills find no glossary and start a new one.
- [act] If `.claude/settings.json` lists `resolving-merge-conflicts` in its
      skill overrides, delete that line: the skill no longer exists.
- [notice] Test runs and session launches now hold while load1 is at or
      above 6 per core. On a machine where that is normal working load, set
      `WFC_LOAD_CEILING` to a higher figure, or `0` to turn the ceiling off.
- [notice] A ticket close through `resolve-ticket.js` whose comment names a
      commit now needs a `**Door:**` line, two-way or one-way.
