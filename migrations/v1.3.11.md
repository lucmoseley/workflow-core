# v1.3.11

## What changed

The `takes:human` issue-create guard and the label check now name the
founder-deliverable template at the plugin root, so the command they print
runs in your repo (#1248).

The inventory and close guards now judge exactly as the shared
`**Outstanding:**` parser does (#1247):

- `waits on you: Nothing`, in any letter case, is accepted as the empty
  inventory.
- A `**Outstanding:**` line inside a fenced block in a close's `--comment`
  no longer counts: the close guard reads the issue's newest comment instead.
- `resolve-ticket.js` owes a `**Door:**` line only for a sha holding both a
  digit and a letter, so an all-letter hex word such as `defaced` no longer
  needs one.
- A tracker configured with capital letters now matches when the inventory
  guard checks that this session claims the issue holding its question round.

A comment GitHub returns as null no longer stops the inventory guard checking
where a `needs input:` round was posted; it is skipped (#1249).

Where the parser itself fails to load or crashes, the close guard lets the
close through and records it, rather than refusing every `gh issue close`
with an empty message (#1255).

The code-standards base your reviews read has changed:

- A program in any language but Node is no longer held to §N3's four program
  families or §N4's `runCheck`, and the three §N4 sub-rules a reviewer cites
  directly bind only a program reporting in `check.js`'s five-outcome
  alphabet (#1250).
- §G5's house naming binds JS and TS files, and shell file names, only. Shell's
  own identifiers and every other language follow the scheme your local file
  states, else the language's own convention: snake_case for Python (#1252).
- §G5 asks a family prefix only of a Node program that joins a family, not of
  one whose header says why it joins none (#947).
- A local rule sits in your local file's Local rules section only, and
  contradicts nothing in the base (#947).

      close any issue that asks you to rename a snake_case Python file or
