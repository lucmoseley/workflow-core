# v2.0.1

## What changed

`guard-headroom-read`, `guard-hook-escape`, `guard-issue-body`,
`guard-issue-close`, `guard-issue-create-label` and `guard-issue-phase-scope`
now run on Bash inside `scripts/guard-dispatch.js` rather than as hooks of
their own, each core on the commands its old `if` narrowings admitted
(#3225). Their refusals, warnings and
rule hand-overs read as before. Where they differ: a core's throw is refused
in the dispatcher's words, naming the core; a command reached past leading
blanks, a compound command's keyword or `NAME=value` assignments is judged
wherever its harness `if` narrowing may not have started the guard; and a
core's `gh` reads stop where the dispatcher's 30 s budget ends
(`scripts/lib/hook-deadline.js`).

`guard-registry-atomicity`, `guard-pull-form`, `guard-push-rules`,
`guard-node-heap`, `guard-rm-unchecked` and `guard-npm-install` now run on
Bash inside `scripts/guard-dispatch.js` the same way (#3226). A crash or hang
of `guard-push-rules` or `guard-node-heap`, which their own hooks let
through, now refuses the call. The dispatcher's `PreToolUse` timeout is now
60 s, the `guard-npm-install` hook's own, and that core's 30 s registry
budget runs from the dispatcher's start.

`guard-root-find`, `guard-suite-concurrency`, `guard-ugrep-pattern`,
`guard-unasked-rerun` and `guard-vitest-wrapper` join them the same way, and
`guard-wide-read`'s Bash limbs move into the core that already ran its `Read`
limb (#3227). A throw in `guard-suite-concurrency`, `guard-ugrep-pattern` or
`guard-vitest-wrapper` is still allowed, logged; one in `guard-root-find` or
`guard-unasked-rerun` is refused in the dispatcher's words.

`scripts/write-secret.js` now writes `~/.config/workflow-core/secrets.env`
(`$XDG_CONFIG_HOME/workflow-core/` where that is set), owner-only, instead of
the host root's `.env`. `guard-jev-advisory` reads `AI_GATEWAY_API_KEY` from
there when the environment lacks it, and an api overflow seat's launch reads
its `key=` variable from there (#3202). A script writing a relative
`.env` from the repo root can no longer destroy a stored secret. The run
refuses where that file would lie in a git working tree.

The code standards base gains a Primitives section, kept real by
`scripts/check-primitives.js` (#3451).

The base gains four rules, judged by `/code-review`'s Standards axis
(#3470): §G10, a Stop hook's block through `blockStop`; §G11, a rule the
rule-text store holds printed through `rule_text` or `readRuleText`; §N10,
an arbiter record through `readRecord` and `writeRecord`; §S6, a pre-commit
gate staging blobs through `staged_gate`.

Your pre-commit now runs `scripts/check-test-spawn.js` on a commit staging a
test, refusing any spawn of `node` on the program under test in your tests,
rather than running it through `scripts/lib/run-in-process.js`, with no
`spawn-kept: <why>` comment (#3458).

Your pre-commit now runs `scripts/check-jsonl-reads.js` on a commit staging
a `scripts/` program, refusing any hand split-and-parse of JSONL in your
`scripts/` rather than `readJsonl`, `parseJsonl` or `parseJsonlRow` from
`scripts/lib/jsonl.js`, with no `jsonl-read-exempt: <why>` comment (#3452,
#3453).

Your pre-commit now runs `scripts/check-clock-copies.js` on a commit staging
a `scripts/` program, refusing any read of `WFC_NOW` in your `scripts/`
outside `now()` in `scripts/lib/check.js`, with no `clock-kept: <why>`
comment (#3457).

Your pre-commit now runs `scripts/check-precommit-exit.js` on a commit staging
`.husky/pre-commit` or `.husky/pre-commit.local`, refusing a line that runs a
checker (`node`, `bash` or `sh` on a script, or a script run directly) and
ends `|| exit 1`, or opens a `|| {` block that exits 1, which turns the
checker's BROKEN into a finding; an outside command such as gitleaks or
`sh -c "$declared_command"` is left alone (#3456).

Your pre-commit now runs `scripts/check-report-programs.js` on a commit
staging a `scripts/report-*` program, refusing any `report-*` in your
`scripts/` that writes through `console` or `process.stdout.write` /
`process.stderr.write` rather than `writeFd` from `scripts/lib/write-fd.js`,
or that builds its own `gh issue create` rather than filing through
`createIssue` in `scripts/lib/tracking-issue.js` (#3454).

`run-pytest.js` takes a lone `--full`, which runs the whole Python suite.
Under `landing` a bare run selects only the session's touched tests, so in a
clean checkout it runs nothing and exits 0 (#3508).

A monthly heresy sweep is switched on in every repo (#3464, spec #3365).
`scripts/report-heresy-sweep-due.js`, run daily at session start, files one
`takes:implement` issue, *Heresy sweep due*, in your own tracker 30 days
after the last one closed, or at once where none was ever filed, and
refreshes the open one rather than filing again. The new `heresy-sweep`
skill works it. A failure is one line in the guard-error log, never a failed
session start. `node "$WFC_PLUGIN_ROOT"/scripts/report-heresy-sweep-due.js
--dry-run` prints the last sweep, the next due date and why, and files
nothing.

Your pre-commit now runs `scripts/check-gh-route.js` on a commit staging
`scripts/`, `.claude/skills/`, `.husky/` or `hooks/`, refusing any `gh` call
off its one route: `WFC_ARBITER_GH`, a Node program spawning `gh` or reading
`WFC_GH` itself rather than through `scripts/lib/gh.js`, a shell script
running a bare `gh` rather than `"${WFC_GH:-gh}"`, or a test putting a `gh`
stub on `PATH` rather than at `WFC_GH` (#3455). It refuses a second `claude`
route on the same shapes: a `WFC_<name>_CLAUDE` or `WFC_<name>_CLAUDE_BIN`
var, a Node program spawning `claude` or reading `WFC_CLAUDE_BIN` itself
rather than through `scripts/lib/claude-bin.js`, a bare shell `claude` rather
than `"${WFC_CLAUDE_BIN:-claude}"`, or a test's `claude` stub on `PATH`
rather than at `WFC_CLAUDE_BIN` (#3559). The arbiter's debt lookup now reads
`WFC_GH`.

Your pre-commit's and init's check of `commands.check_staged` now reads more
of what a command runs, and refuses less of what it cannot read (#3545,
#3851). It follows `yarn <script>`, `pnpm <script>` and `bun <script>`; npm's
`test`, `start`, `stop` and `restart`; each `pre<name>` and `post<name>`; and a
run in a directory written out through `cd`, `--prefix`, `-C`, `--dir` or
`--cwd`. A command it cannot read is refused only
where your repo shows Biome evidence: `@biomejs/biome` declared in
`package.json`, a script there mentioning `biome`, or `biome` in the command.
The words that make such a command suspect are now `npm`, `pnpm`, `yarn`,
`bun`, `bunx` and `npx`, not `run`, so `uv run ruff check $(…)` and
`./scripts/run-lint.sh $(…)` pass.
