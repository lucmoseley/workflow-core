# v2.2.0

## What changed

Since v2.1.0, an overflow seat line in `~/.claude/refill-seats` names its plan
seat's config dir, and its sessions run as that dir's background jobs, billed to
the line's `key=` (#3701). A line on a dir of its own, such as an `-api` dir, is
refused, and the refusal refuses the whole seat file, so the refill loop acts on
none of its seats (#4394).

The helper surface now lists `scripts/biome-staged.js` as a command: each
argument you give it reaches `biome check` ahead of the staged paths (#4616).

Your `docs/clobber-reviewed.json` now takes a CLOBBERED finding's identity too
(#4636): a body rewrite you have judged deliberate, keyed `"#N\t<edit time>"`
to the reason as a reviewed SUSPECT is, then reports as `CLOBBERED-REVIEWED`,
a WARN the daily repo-checks run leaves off its standing issue. A CLOBBERED
with no entry still fails. The check's `--json` output lists reviewed
CLOBBEREDs under `clobberedReviewed`, and its reviewed SUSPECTs move from
`reviewed` to `suspectReviewed`.

The vendored Matt Pocock skills move from upstream v1.3.1 to v1.3.2; nothing is
owed from you (#4633). `implement` states the ticket's title before starting and
asks on an ambiguous reference. `code-review`, `research`, `grilling`,
`wayfinder`, `improve-codebase-architecture` and `codebase-design` start their
sub-agents with a fresh context window, and `code-review` searches the repo for
every coding-standards file. `wayfinder` resolves a ticket by its
`wayfinder:<type>` label and, by a local edit, posts a research ticket's
findings on the ticket.
`diagnosing-bugs` checks that a forced red landed; `tdd` notes what each
proposed seam catches and misses. `to-tickets` makes each ticket a sub-issue of
the issue it came from and drops its "Blocked by" section where blockers are
native edges. `setup-matt-pocock-skills` wires a missing git remote, creates
the labels a tracker lacks and files issues only into your own repo.
It also offers to rename a legacy `CONTEXT.md` or `CONTEXT-MAP.md` to its
`GLOSSARY` name, and its GitHub and GitLab tracker templates gain the sub-issue
and blocker commands. `teach`
resolves workspace paths from the directory it was run in.

The type-check slot charges each `tsc` by its compiler: a TypeScript 7.0 run
waits for its own ~2.6 GB rung, a 5.x or 6.0 run for ~3.15 GB. It counts 7.0's
launcher and the native compiler it starts as one runner, and the bare-`tsc`
guard holds a `tsc6` launch as it holds a `tsc` one (#4892).

## Manual steps

- [act] If your `~/.claude/refill-seats` holds an overflow line (one whose
      second word is `api`) whose first word is not also a plan seat line of
      its own, rewrite that first word to the config dir of the plan seat whose
      API credits the key bills to, keeping the rest of the line. Until then
      `node "$WFC_PLUGIN_ROOT"/scripts/refill-loop.js status` prints, for each
      such line,
      `seat file refuses: <home>/.claude/refill-seats:<n>: <its first word> has no plan seat line, and an overflow seat launches under its plan seat's config dir: <the line>`.
      The step is done when it prints no `seat file refuses:` line.
  - Before: `~/.claude` on one line, then
    `~/.claude-api api key=ANTHROPIC_API_KEY_OVERFLOW grant=50 cycle-day=1`;
  - after: `~/.claude` on one line, then
    `~/.claude api key=ANTHROPIC_API_KEY_OVERFLOW grant=50 cycle-day=1`.

- [notice] The run-cost report judges an existing test file's growth
      against the newest green `scheduled-checks.yml` run's per-file timings,
      read from that run's `vitest-report-*` artefacts in your `codeRepo` and
      cached under your git common dir, checked at most every 6 hours and
      read for a day after its last passed check. A committed
      `docs/data/ci-shard-timings.csv` of your own is no longer read, and the
      workflow read is `scheduled-checks.yml` whatever yours is named. Where
      your repo has no such run, every pre-existing file reads unjudged. The
      lander's `fullTestShards` runs pack by the same file (#4579).

- [notice] The pre-commit ESLint gate now also arms on a staged `scripts/`
      `.js`, `.mjs`, `.cjs` or `.ts` file, and passes ESLint
      `--no-warn-ignored` (#4642). With an ESLint config whose blocks are all
      scoped to other directories, nothing changes: a `.js` there gets no
      rules and a `.ts` is skipped. A config block with no `files` key, such
      as a preset spread bare, now runs on those staged scripts too.
