# v2.0.2

## What changed

Your pre-commit's and init's check of `commands.check_staged` now follows npm's
workspace selectors (#4041): `-w` or `--workspace` by member name, directory or
parent directory, and `-ws` or `--workspaces` to each member of `package.json`'s
`workspaces`. It does not read `pnpm --filter web cs` or `yarn workspace web cs`, nor
`node --run cs`, nor a selector set by `npm_config_workspace` or `.npmrc`, so each
passes though its script runs Biome. Each of the four has one form to use:
`node "$WFC_PLUGIN_ROOT"/scripts/biome-staged.js` plus flags you own, and the rest
in a gate of its own. Reading a selector needs Node 22.5; on an older one a
`check_staged` holding a selector is refused as one that cannot be checked, so
upgrade Node or, where the command never runs Biome, put it in a shell file
(`sh ./your-gate.sh`).

The code standards base's §N6 now has a program read whole stdin through
`readFdAll` from `scripts/lib/read-fd.js` and decode the `Buffer`, since a bare
`readFileSync(0)` throws `EAGAIN` on a non-blocking pipe (#4017).

The check refuses no script holding only the `biome-staged.js` command, its root
spelt `"$WFC_PLUGIN_ROOT"` or `"${WFC_PLUGIN_ROOT:-.}"` (#4042). It does not read
`npm_config_call='biome check --staged' npx`, which passes though it runs Biome:
declare `node "$WFC_PLUGIN_ROOT"/scripts/biome-staged.js` plus flags you own. It
still refuses text naming the command (`echo "run biome check --staged by hand"
&& eslint .`), so word the text otherwise, and expansions fitting Biome's slots
(`eslint $A $B $C`, `python -m ruff $OPTS check $FILES`), so write the words out;
either may instead go in that shell file.

Where no split route opens the refill panel, `scripts/refill-panel-open.js --if-enabled`
now says why on stderr and holds it and the printed command on screen for 5 seconds
before your agents alias starts the view, which otherwise covers them at once (#4066).
Keys typed in those seconds reach the view. Stdout is still the command alone, and a
by-hand run without `--if-enabled` prints it and returns at once.

## Manual steps

- [act] List your programs' bare whole-stdin reads with
      `git grep -nE 'readFileSync\(0' -- scripts ':!*.test.*'`, run from your repo
      root. Base §N6 now has each read through `readFdAll` from the plugin's
      `scripts/lib/read-fd.js` and decode the `Buffer`, or say in a comment why not
      (#4017).
- [act] On a Node older than 22.5, whether or not your repo shows Biome evidence,
      your next commit refuses a `commands.check_staged` holding an npm workspace
      selector. Upgrade Node; or, where the command never runs Biome, move it to a
      shell file (`sh ./your-gate.sh`); or declare
      `node "$WFC_PLUGIN_ROOT"/scripts/biome-staged.js` plus flags you own (#4041).
- [act] If your repo shows Biome evidence (`@biomejs/biome` declared in
      `package.json`, a script there mentioning `biome`, or `biome` in the command),
      your next commit refuses a
      `commands.check_staged` in any of these shapes. Set it now where one fits, in `.claude/workflow-core.json`.
      `<flags>` below is
      `node "$WFC_PLUGIN_ROOT"/scripts/biome-staged.js` plus flags you own. The
      step is done when
      `node "$WFC_PLUGIN_ROOT"/scripts/lib/infer-commands.js check-staged "$(node "$WFC_PLUGIN_ROOT"/scripts/lib/workflow-core-config.js command check_staged)"`,
      run from your repo root, exits 0 (#4041).
  - `biome check --staged` run through a workspace selector (`npm run cs -w web`,
    `npm run cs --workspaces`): `<flags>`;
  - an npm workspace selector no member of `package.json`'s `workspaces` answers
    (`npm run cs -w nosuch`): the selector naming a member, or `<flags>`;
  - a flag's quoted value naming the command (`npx --call='biome check --staged'`,
    `npm exec -c='biome check --staged'`): `<flags>`; where it is only text
    (`eslint --rule='biome check --staged'`), the text worded otherwise, or that
    shell file (`sh ./your-gate.sh`).
